## 3. Поведение и ограничения

Проверяется сохранение существующего определения, отказ при отличии календарного `StartBoundary` или `Enabled`, создание только после типизированного отсутствия без экспортированных байтов, отсутствие принудительного Import и повторного Create. Ошибка после создания и отказ восстановления сохраняются. Receipt создания либо совпадение XML не разрешают удалить текущее поколение задачи. Явное удаление остаётся отдельным контрактом. Подставные setup-сценарии используют те же правила.

Реальная нормализация календарного определения Windows ещё требует своей отдельной проверки. Публичный `EnsureLivenessTask` с фиксированным установленным именем, полные стандартный и тегированный наборы, установка/обновление/отмена/восстановление в разрешённой среде и полная приёмка A здесь не подтверждены. Текущие build/vet и контроллерные результаты составного Source52 имеют собственную область и не заменяются этой проверкой.

## 4. Сохранённая история

Source6d сохраняет свой исходный FAIL/CLOSED на очистке тестовой фикстуры. Source52 сохраняет отдельный FAIL/CLOSED `ParoleQueuedStop` и последующую диагностическую область. Старые V1 и удержанные FAIL/UNKNOWN не переоцениваются. Успех этих двух самостоятельных команд не является повторным исполнением или закрытием старых владельцев.
