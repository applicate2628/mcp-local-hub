## 1. Причина и граница правки

В составном Source `b426508361858ff2d63a5b994633d4cc367f55bf` проверка `TestWeeklyRefreshLockOrderInventory` остановилась на предварительном перечне тестовых подменщиков: в выбранных исходниках с тегом `test_state_path_env` оказалось девять вызовов `installKnownFolderStub`, тогда как проверка ожидала восемь. Дополнительный вызов принадлежит `TestStateDirObserved_SelectedBuildSource` из #637. До него вызывается `statePathsHelper(t)`, а параллельное исполнение не включено.

Числовой лимит не увеличен. Перечень теперь связывает каждый вызов с точным именем файла и тестовой функции. Правка принадлежит существующему #660; единственный изменённый Go-файл — `internal/api/weekly_refresh_atomic_test.go`. Составная копия содержит также самостоятельную политику консоли из #665; эта политика не перенесена в #660.

Производственный анализ происхождения ошибок, включая динамический переход `errnoIs → Unwrap`, и его пределы не изменены. После предварительного перечня исполняется весь прежний производственный барьер графа вызовов и порядка блокировок.

## 2. Контракт

Три основных вызывающих теста перечислены явно. Пять тестов выбора каталога через переменные окружения добавляются только при выбранном теге `test_state_path_env`. Вызов наблюдателя #637 допускается только при присутствии его выбранного Windows-файла и только под его точным именем.

Для каждой разрешённой пары «файл / функция» требуется ровно один вызов. Неизвестный вызывающий код, повторный вызов и метод с получателем вместо тестовой функции получают отказ. Исчезновение обязательного вызывающего теста также получает отказ. Сохраняются проверки сохранения и восстановления `knownFolderResolverFn`, единственной записи подменщика, предшествующего `statePathsHelper(t)` и отсутствия `t.Parallel()`.

Этот перечень представляет закрытый набор проверенных владельцев. Его не следует интерпретировать как универсальный анализ потока управления для произвольных новых тестовых помощников.

## 5. Ревью и незакрытые условия

Собственное ревью проверило исходный дефект, закрытость разрешённого набора, отказ неизвестному и повторному вызывающему коду, сохранение жизненного цикла, выбор файлов по тегам, отдельное владение изменениями #660/#665 и неизменность ограничений анализа. Открытого замечания в изменённом участке не осталось.

Полные стандартные Go-тесты и полный набор API/CLI с тегом не исполнялись: допуск полного тестового окружения остаётся отдельным условием. CLI означает интерфейс командной строки. Установка Product, изменение системных задач Scheduler, политика доступа, дерево исходного Git при тайм-ауте, исполнение на POSIX и Unix/ARM64 этой проверкой не подтверждаются. POSIX — семейство стандартных интерфейсов Unix-подобных систем; ARM64 — 64-разрядная архитектура ARM.

Это не новый выданный Source и не квалификация Product после изменения его идентичности. Внешнее ревью нового публикуемого коммита требуется отдельно; старые отзывы не переносятся на него. Ветки и запросы на включение изменений не объединялись.
