<a id="context"></a>
## 1. Контекст

Аудит выявил широкие пакеты и размытое владение, но не доказал необходимость независимых deployable services. Один локальный hub остаётся продуктовой ценностью.

<a id="decision"></a>
## 2. Решение

Сохранить один deployable product, разделив его на внутренние модули с направленными зависимостями и одним владельцем каждого инварианта.

<a id="consequences"></a>
## 3. Последствия

- Проще эксплуатация и обновление.
- Границы пакетов становятся архитектурными контрактами.
- Микросервисные сетевые failure modes не добавляются.
- Architecture tests и archcheck проверяют направления зависимостей.

<a id="alternatives"></a>
## 4. Рассмотренные альтернативы

- Сохранить текущий god-package layout — отклонено из-за роста стоимости изменений.
- Перейти к микросервисам — отклонено как несоразмерное локальному продукту.
