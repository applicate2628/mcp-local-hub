## 1. Метод

Исторические findings `R-01—R-36` не закрывались по названию commit/PR. Для каждого изменения проверялись:

- merge status;
- exact HEAD;
- affected components;
- заявленные проверки;
- изменение owner/invariant;
- необходимость regression revalidation.

Закрытая ветка без merge не считается частью продукта.

<a id="deltas"></a>
## 5. Новые delta entries

### DELTA-001 — route daemon является current contract

`mcphub route` уже supervisor-managed. Characterization должна охватывать read-only routing, state-file non-mutation, reload serialization, port ownership и shutdown.

### DELTA-002 — большой post-audit release delta

PR №604 требует повторной классификации findings и baseline на exact master.

### DELTA-003 — auto-reaper former-signature gap

PR №565 закрыт без merge. Review доказал:

- config-present процессы одновременно номинировались и исключались;
- config-absent процессы теряли источник номинации;
- текущая конфигурация не может доказать, что процесс был ранее managed.

Нужно D-017: persisted former signature + TTL + exact identity. Name-only kill запрещён.

### DELTA-004 — межъязыковой lifecycle inventory

CST/native/Python process chains не покрываются `archcheck workers`.

### DELTA-005 — oneAPI timeout/output loss

Long-running child может пережить caller timeout, но потерять stdout. Требуется durable output owner и typed settlement.

### DELTA-006 — protocol-incompatible shipped servers

Wolfram/LLDB backlog показывает, что process `Running` не доказывает protocol readiness. Install/status должны выявлять incompatibility до/при запуске.

### DELTA-007 — CST Third order

Узкий tool schema gap. Он относится к product backlog и не меняет архитектурный DAG.
