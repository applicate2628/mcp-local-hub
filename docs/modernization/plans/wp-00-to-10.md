<a id="cycle"></a>
## 1. Общий цикл

Для каждого WP:

1. обновить `master` и зафиксировать exact SHA;
2. выполнить delta-review связанных R-*;
3. написать falsifier/characterization tests;
4. разделить работу на PR по одному инварианту;
5. выполнить локальный gate;
6. пройти Codex review на exact HEAD;
7. обновить traceability и удалить закрытый baseline debt;
8. выполнить rollback rehearsal для stateful changes.

<a id="wp-00"></a>
## 2. WP-00 — базовая воспроизводимость и тестовая изоляция

**Результаты:** общий client-config sandbox, общий test state root, устранённый `internal/cli` hang, repeated/shuffle/race baseline, canonical defect index.<br>
**Выход:** одна локальная команда доказывает clean status; тесты не выходят в реальные пользовательские каталоги.

<a id="wp-01"></a>
## 3. WP-01 — единая входная безопасность и framing

**Результаты:** `LocalIngressSecurity`, Host/Origin/Content-Type policy, typed framer, raw non-JSON removal, bounded request/response, owner token migration.<br>
**Миграция:** audit-only → default strict for new installs → strict for existing installs с one-release warning.<br>
**Выход:** R-01, R-03, R-12 закрыты; R-25 реализован либо принят как P3 с expiry.

<a id="wp-02"></a>
## 4. WP-02 — correlation router и cancellation

**Результаты:** delivery state model, ext↔int ID map, cancellation translation, session cleanup, единый protocol-header owner, миграция relay/direct/hub.<br>
**Выход:** collision/cancel tests проходят; mutating call не replay-ится после ambiguous delivery.

<a id="wp-03"></a>
## 5. WP-03 — sharing policy и Serena project pool

**Результаты:** manifest sharing metadata, project-keyed pool, canonical root, reverse-routing policy, idle reap/max limits, атомарная миграция unified daemon.<br>
**Выход:** параллельные проекты не разделяют active state; rollback path сохраняется одну minor version.

<a id="wp-04"></a>
## 6. WP-04 — legacy и modern MCP

**Результаты:** решение по версии `2025-03-26`, отдельные adapters, modern discovery/headers/_meta, conformance corpus, явная negotiation.<br>
**Выход:** каждая рекламируемая версия проходит suite; silent downgrade отсутствует.

<a id="wp-05"></a>
## 7. WP-05 — capabilities, lists и caching

**Результаты:** один bounded paginator owner, deterministic list snapshot, route-map publication после согласования, resources/prompts support, явный partial state.<br>
**Выход:** capabilities отражают фактический route graph.

<a id="wp-06"></a>
## 8. WP-06 — единый audit writer

**Результаты:** общий lock/append/sync/rotation owner, typed outcomes, health, migration journals, independent emergency reporting.<br>
**Выход:** unlock/close/sync failures наблюдаемы; automatic replay не выполняется при неопределённом commit outcome.

<a id="wp-07"></a>
## 9. WP-07 — crash-safe adoption/de-adoption

**Результаты:** transaction journal, resume/rollback, reclaim-crashed, fault-injection matrix, GUI recovery flow.<br>
**Выход:** terminal state всегда committed, rolled-back либо recovery-required с конкретной командой resume.

<a id="wp-08"></a>
## 10. WP-08 — platform lifecycle

**Результаты:** IPC write deadline, process-tree abstraction, Linux systemd scope, macOS native evidence либо preview classification, POSIX orphan fixtures, doctor checks.<br>
**Выход:** все заявленные stable platforms проходят native release matrix.

<a id="wp-09"></a>
## 11. WP-09 — release и supply chain

**Результаты:** immutable pin gate, локальные verify-local/verify-release, `govulncheck`/OSV/npm audit, SBOM/licenses, OIDC trusted publishing, двухкоммитный release evidence protocol.<br>
**Выход:** tag/publish невозможны без manifest для source commit; обычный PR не запускает hosted CI.

<a id="wp-10"></a>
## 12. WP-10 — документация и управление состоянием

**Результаты:** решение [D-005](../decisions.md#d-005), canonical defect registry, generated index, versioned docs, ADR extraction, CODEOWNERS, generated capability/client/server matrices.<br>
**Выход:** один live status source; версия, docs и capabilities синхронизированы.

<a id="gate"></a>
## 13. Общий gate

Единственный нормативный минимальный gate определён в [разделе 3 Governance](../governance.md#local-gates). Этот план не дублирует команды, чтобы они не расходились. Исполнитель обязан использовать актуальную версию блока, которая:

- фиксирует exact HEAD;
- сохраняет `worktree-status`, build, vet и test evidence в `.reports/`;
- завершает работу неуспешно при грязном worktree;
- использует `set -euo pipefail`, чтобы `tee` не маскировал ошибку;
- после A2 создаёт JSON- и Markdown-отчёты `archcheck`.

Дополнительно по затронутой области выполняются tagged tests, frontend tests, package tests, race, shuffle, fuzz corpus, fault injection и native platform smoke.
