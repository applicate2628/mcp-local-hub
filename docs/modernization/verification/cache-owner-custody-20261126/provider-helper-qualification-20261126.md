## 1. Проверенный состав

Изменены только `internal/api/main_test.go` и `internal/api/adopt_provider_working_directory_windows_test.go`. Временный корень пакета, которым уже владеет `TestMain`, хранит успешно собранные образы helper отдельно для каждой архитектуры. Доступ к карте образов защищён mutex; она пополняется после успешной сборки. Время жизни общего каталога заканчивается при существующей очистке после `m.Run`.

Каждый вызов по-прежнему создаёт собственного дочернего helper и выполняет прежние ожидание и очистку. Проверки working directory, identity и named pipe не изменены. Здесь helper — небольшой тестовый дочерний процесс, рабочую директорию и идентичность которого проверяют существующие сценарии.

Проверялся частный Source `aca81a1743ccfbf3e10902769a9b071eb911919e` с **ровно двумя виртуальными заменами через Go overlay**. Физические 3508 файлов Source остались неизменны. Использованы новые каталоги module/build cache; их исходные идентификаторы сохранены до конца проверки. Старые cache или готовые helper-образы не копировались. [1]

Собран отдельный API test image: Windows AMD64, GUI subsystem, `-tags=test_state_path_env`, Go `go1.27.4`. SHA-256 образа — `646d659defb717878f7f3e9732d0d311c3716c5f01b421b5c047f98bb624d717`. Это обычный тестовый образ, не новая квалификация Product или Serena. Байты двух preimages совпадают с сохранённым публичным #665 на `03719d32a13a20f3254eccc148684efae3c3287a`; весь публичный head в этом проходе не проверялся.

Двухфайловое изменение уже опубликовано в существующем #665: [`d30326c099ced46984cee38d4455498d3209a967`](https://github.com/applicate2628/mcp-local-hub/commit/d30326c099ced46984cee38d4455498d3209a967). ## 3. Завершение и границы вывода

У всех пяти команд приняты `direct_reaped=true`, `active_zero=true`, `handles_closed=true`, пустой список native issues и исходное состояние `complete`. Присоединены **11 исходных I/O workers: десять читателей stdout/stderr и один писатель stdin** для `test2json`. Получены EOF, возвраты закрытия pipe/capture handles; ошибок и превышений capture limits нет. Захваты измерены после завершения. Parent получил exit 0 и закрыл собственные capture handles; result связан с точным plan, а command receipt — с result и parent по SHA-256. Source, входы, тестовый образ и converter после исполнения неизменны. [1]

Код трёх успешных сценариев и проверенное переиспользование подразумевают **четыре отдельных запуска helper и две успешные сборки: одну 386 и одну AMD64**. Эти числа выведены из точного исходного пути и трёх PASS; отдельный журнал рождения всех четырёх child и SHA двух helper-образов не выдавался. Фактически приняты общий native tree closure и события тестов.

Результат подтверждает работоспособность нового времени жизни helper-образов в указанных сценариях. Сопоставимого запуска «до/после» для измерения ускорения не было. Причина и исправление прежнего превышения 30-секундной подготовки API/CLI этим проходом не доказаны: literal inventory preparation здесь не повторялась. Неизменённые старые UNKNOWN остаются UNKNOWN и не дают разрешения на доступ к их ресурсам.
