# Serena: относительная проверка выделений памяти

**Проектирование и независимое чтение критерия без исполнения.** Ведущий исполнитель отдельно проверил прямые квитанции запусков и выполнил собственное ревью; фактические положительный и отрицательный контроли приведены в [RESULTS.md](RESULTS.md). Здесь сохранено обоснование критерия. Итоговый тест закреплён опубликованным коммитом `2cb467aac31259ed4fb665ed0a4f277a8f9c31a2`.

## Вывод

Тест `TestResolveByPath_DoesNotCloneUnrelatedNestedRows` проверяет отсутствие лишнего клонирования через абсолютный предел `allocs < 100`. Но измеряемый вызов включает файловую канонизацию и периодическое чтение реестра. Переданный root результат 112 выделений памяти устанавливает нарушение старого предела; сам по себе он не устанавливает клонирование 256 посторонних строк.

Подготовлено изменение только этого теста поверх исправления фикстур. Производственный код в итоговом наборе не изменяется. Отдельная мутация ниже предназначена только для отрицательного контроля.

Порядок фикстуры существенен: выбранная запись добавлена первой, затем 256 посторонних. ## 2. Новый критерий

[Новая версия теста](https://github.com/applicate2628/mcp-local-hub/blob/2cb467aac31259ed4fb665ed0a4f277a8f9c31a2/internal/api/serena_routing/resolver_test.go#L634) сохраняет выбранную запись с непустыми `ClientEntries` и `Languages`; [исходная версия](https://github.com/applicate2628/mcp-local-hub/blob/92f2d4350bfc22a5fa8099fd1b4ec199f9a19c22/internal/api/serena_routing/resolver_test.go#L633) содержит прежний абсолютный предел. Изменение критерия ограничено одной функцией.

Обе серии используют **тот же абсолютный путь выбранного файла, тот же путь реестра и ту же выбранную запись на первой позиции**:

1. Сохранить только выбранную строку. Создать новый наблюдатель, выполнить начальное чтение и проверить опубликованное число строк: 1.
2. Измерить 16 вызовов полного `ResolveByPath(file)` через `testing.AllocsPerRun`.
3. Сохранить по тому же пути выбранную строку и 256 посторонних строк с вложенными картами и срезами. Создать новый наблюдатель, выполнить начальное чтение и проверить число строк: 257.
4. Измерить такую же серию и потребовать `withUnrelated <= baseline`.

`PeekPublishedViewForTest`, строки 136–140 наблюдателя, только читает текущую генерацию и не увеличивает счётчик обращений. После начальной загрузки счётчик равен нулю; прогрев `AllocsPerRun` плюс 16 измеряемых вызовов оставляют его равным 17. Полное перечитывание на 32-м обращении в эти серии не входит. Таким образом проверяется обычное чтение уже загруженного снимка с прежним полным файловым разрешением пути, без размера YAML как дополнительной переменной.

Новый критерий не разрешает положительного прироста и не вводит новый абсолютный потолок. Оба измеренных числа выводятся в журнал теста. Существующие проверки обновления снимка в пределах 32 обращений остаются без изменений.

<a id="mutation"></a>
## 3. Отрицательный контроль

Контрольная мутация, редакция 2, вставляет в отдельную копию производственного `ResolveByPath` блок сразу после существующего `view := r.observe()`:

```go
cloned := make([]api.WorkspaceEntry, view.SerenaCount())
for i := range cloned {
	candidate, _ := view.SerenaCandidate(i)
	cloned[i], _ = view.Materialize(candidate)
}
runtime.KeepAlive(cloned)
```

Блок материализует все строки из той же наблюдённой генерации в сохраняемый срез. `runtime.KeepAlive` фиксирует использование результата копирования. Мутация намеренно возвращает копирование всех вложенных полей перед выбором одной записи, сохраняя выбранный результат и ровно одно обращение к наблюдателю за вызов.

Первый подготовленный вариант с дополнительным `ListWorkspaces` заменён после независимого замечания: он добавлял второе обращение к наблюдателю и пересекал порог периодического чтения внутри серии. В редакции 2 этой дополнительной переменной нет; первый вариант не следует использовать.

Минимальное различающее подтверждение: здоровый кандидат проходит новый тест; отдельная копия с этой мутацией падает именно на положительном приросте выделений памяти. Затем повторно проверяется здоровая копия. Чувствительность критерия нельзя объявлять подтверждённой только по статическому прочтению мутации.

Мутация **не входит в предлагаемые изменения**. Базовый [производственный файл](https://github.com/applicate2628/mcp-local-hub/blob/92f2d4350bfc22a5fa8099fd1b4ec199f9a19c22/internal/api/serena_routing/resolver.go) закреплён исходным коммитом. SHA-256 исходного и изменённого файлов, подтверждение восстановления и результаты контроля приведены в [RESULTS.md](RESULTS.md); итоговый набор тестовых файлов — в [candidate-manifest-v2.json](candidate-manifest-v2.json).

## 4. Проверено и не проверено

Выполнены: повторное чтение производственных исходников на закреплённом коммите; локальное сравнение теста до и после; проверка неизменности файлов вне целевой функции; вычисление SHA-256; собственное статическое ревью. Второй агент независимо прочитал точный дифф и относящиеся к нему закреплённые участки наблюдателя и Serena; существенных статических замечаний не обнаружил.

**Граница независимого чтения:** статическое ревью выполнено без Go-сборки, запуска тестов, `gofmt` и исполнения мутации. Ведущий исполнитель отдельно выполнил запуски, проверил прямые квитанции и провёл собственное ревью. Актуальные измерения и восстановление продукта представлены в [RESULTS.md](RESULTS.md).
