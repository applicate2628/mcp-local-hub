# R17: нативные результаты экспорта XML и границы следующей замены

**Дата:** 19 ноября 2026 года, МСК. **Решение:** сохранить действующий производственный `ExportXML`. Прямая передача вывода `schtasks /Query /XML` отклонена для наблюдённой среды: команда завершилась успешно, но вернула повреждённый XML. `Export-ScheduledTask` из установленного модуля ScheduledTasks — следующий кандидат; его полная эквивалентность ещё не доказана.

Это продолжение существующей [карты R17](../../plans/scheduler-contracts-2026-11-19.md#next), а не новая реализация или новый PR. Производственный исходник — [#660, `1b870e04f58bbf60fde2d2339fcd4ae9b50b24c3`](https://github.com/applicate2628/mcp-local-hub/pull/660). Исходные нативные запросы выполнены ранее 19 ноября; в этом продолжении их сохранённые байты проверены заново без повторного обращения к планировщику.

## 1. Доказательства и происхождение

Обнаружены две сохранённые серии на Comet, Windows 10.0.22631, OEM-кодовая страница 866, ANSI-кодовая страница 1251. Снимки COM получены диагностическим прямым `GetFolder(\).GetTask(name).Xml`, а не вызовом публичной Go-функции или производственного сценария #660; эта серия сравнивает системные способы получения определения. Никакой новой задачи эти серии не создавали: они читали одно известное определение и использовали прежнее отрицательное имя. Префикс имени не считается доказательством владения установленной задачей. Содержимое определения, имена учётных записей и локализованные ошибки не публикуются.

**Таблица 1. Реально выполненные серии и последующая проверка.**

| Действие | Время, МСК | Подтверждённый результат |
|---|---|---|
| COM → точный `schtasks /Query /TN … /XML /HRESULT` → COM | 15:02:02 | Три исходных процесса завершились с кодом 0, stderr пуст; до/после получены одинаковые определения |
| COM → `Export-ScheduledTask` с тремя именами → COM | 15:14:49–15:14:50 | Три исходных процесса завершились с кодом 0, stderr пуст; положительные/отрицательный исходы находятся внутри JSON |
| Прежний анализ сохранённых файлов | 15:22:48 | Был сохранён отдельный отчёт; его выводы не принимались без чтения исходных файлов |
| Новый независимый от прежнего анализатор сохранённых байтов | **17:24:02** | Сверены два исходных сценария, две квитанции, **12 потоков** stdout/stderr, четыре COM-снимка, два CIM-экспорта и числовой отрицательный исход; новых запросов и дочерних процессов анализатор не создаёт |

[`evidence.json`](evidence.json) сохраняет длины, SHA-256, времена исходных команд, версии и контрольные суммы установленных компонентов, а также пересчитанные сравнения. [`verify_saved_native_export.py`](verify_saved_native_export.py) — точный исполненный анализатор. Он читает сохранённые данные, строго декодирует Base64 и UTF-16LE, переводит строку в UTF-8 и проверяет весь наблюдённый результат. Запись результата допускается только в новый файл.

Первичные определения и потоки остаются в приватной рабочей области вне trash. Публичная квитанция позволяет проверить соответствие заявленных выводов, но не воспроизвести исходные частные байты без доступа к ним. Хеш доказывает совпадение байтов, а не их происхождение сам по себе; происхождение дополнительно связывают исходные сценарии, квитанции и сохранённые потоки. Завершение шести исторических процессов берётся из их исходных квитанций; новые дескрипторы тех процессов не открывались.

<a id="schtasks"></a>
## 2. Прямой schtasks: успешный код с повреждённым определением

Microsoft документирует `/XML` как экспорт определения и `/HRESULT` как формат кода завершения команды [1]. Это не обещает побайтной эквивалентности вывода тому, что сейчас получает Go через строку COM.

В сохранённом запросе исходная строка COM занимала **1427 байт UTF-8**, а стандартный вывод команды — **1462 байта**. Все отличия объясняются ровно двумя преобразованиями:

- единственный знак `§`, кодовая позиция Unicode **U+00A7**, заменён на управляющий символ **U+0015**;
- **36** последовательностей CRLF стали CRCRLF: перед переводом строки добавился ещё один возврат каретки.

Это сравнение полных байтов, а не только найденного фрагмента. В выводе нет маркера порядка байтов и ненулевых старших байтов; повторное декодирование этого уже полученного потока через UTF-8, CP866 или CP1251 не восстанавливает потерянный знак. Не установлено, какой внутренний участок Windows выполнил замену; вывод не обобщается на все версии Windows, локали и символы.

Исходный COM XML разбирается, полученный XML — нет: сохранённый анализатор сообщает ошибку в строке 11, позиции 64. U+0015 не входит в разрешённое множество символов XML 1.0 [4]. Поэтому одного нулевого кода команды или `utf8.Valid` недостаточно. Замена управляющего символа обратно на `§` не принимается как исправление: такой вывод не содержит общего способа восстановить исходный текст.

**Решение:** прямой маршрут «stdout команды → публичный результат ExportXML» не реализуется. Новая попытка того же варианта нужна лишь при новой документированной гипотезе и различающей проверке; неизменный запрос повторять не требуется.

<a id="cim"></a>
## 3. ScheduledTasks/CIM: точное имя прошло, иной регистр меняет XML

Проверялся установленный модуль **ScheduledTasks 1.0.0.0** и его команда `Export-ScheduledTask`. Команда документирована как экспорт определения в строку XML; предусмотрены формы имени/пути и `-InputObject` [2]. Это системный интерфейс управления; наличие его не доказывает, что внутренности Windows вообще не используют COM.

**Таблица 2. Нативные исходы одной сохранённой серии.**

| Запрос | Наблюдение | Граница вывода |
|---|---|---|
| Точное зарегистрированное имя, корневая папка | Одна строка, **1427 байт UTF-8**; побайтное совпадение со всеми четырьмя COM-снимками двух серий | Подтверждён один успешный экспорт, включая присутствовавший `§` |
| То же имя в верхнем регистре | Команда тоже успешна; 1427 байт, корректный XML, но другие байты | Единственное изменение — регистр имени в `RegistrationInfo/URI`; точный запрос и иной регистр не эквивалентны текущему контракту |
| Прежнее отрицательное имя | Ошибка `CimException`; в `MSFT_WmiError` поле `error_Code` типа UInt32 равно **`0x80070002`** | Это конкретный код конкретного запроса; независимое доказательство отсутствия и полная матрица ошибок не установлены |

Общая ошибка .NET и `CIMStatusCode=1` не подменяют вложенный Windows-код. Локализованный текст сообщения не используется для классификации.

Кандидат продолжения — получить каноническое имя из объекта задачи и экспортировать его, сохранив точную прежнюю область поиска. Форма `-InputObject` документирована [2], но её требуемое поведение ещё не выполнено на собственной разрешённой задаче. Документация `Get-ScheduledTask` содержит расхождение: текст `TaskName` допускает `*`, таблица параметра указывает отсутствие wildcard-поддержки [3]. Поэтому точность селектора проверяется на фактическом установленном интерфейсе, а не выводится только из таблицы.

## 6. Решение и следующий нативный шаг

1. Сохранить производственный COM-экспорт. Не добавлять неиспользуемый адаптер, переключатель или цепочку запасных реализаций.
2. Для #660 подготовлен отдельный [проверяемый сценарий собственных задач](NATIVE-FIXTURE.md). Синтаксический разбор штатным PowerShell прошёл; обычный запуск файла без `-Apply` заблокирован политикой хоста до исполнения кода. Требуется отдельное действующее разрешение по `AGENTS.md`, раздел Scope and safety: на один запуск с `RemoteSigned` только для нового процесса PowerShell и его потомков, а также создание и условное удаление двух отключённых задач. Постоянные политики не меняются; повторный отказ означает остановку, не переход к другому исполнителю. Пока этот допуск не предоставлен.
3. После допуска проверить конкретную скрытую и видимую корневые задачи через неизменённый производственный сценарий, с сохранённой областью List. Эта минимальная проверка не квалифицирует настоящий запуск, остановку работающей задачи или произвольные права доступа.
4. Затем квалифицировать кандидат ScheduledTasks/CIM: точность имени и области, отсутствие/отказ/недоступность, Unicode включая дополнительные плоскости, неизменность XML и совместимость с настоящими потребителями. Изменение кодировки или пересериализация не допускаются без доказанного контракта.
5. Остальные изменения R17 выполнять у их существующих владельцев. Для выявленных install-путей сначала зафиксировать минимальный различающий сценарий, затем исправлять сохранность определения и ошибок без незащищённого восстановления поверх чужой записи.

## 7. Самостоятельное ревью и пределы

Проверены происхождение данных, различие кода процесса и вложенного результата, кодировка и полный побайтный вывод, реальные потребители, сохранность исторических отказов, отсутствие изменения производственного Go/Rust и необходимость узкой нативной фикстуры. Собственное чтение дополнено независимым неавторским ревью контрактов; его автор не выдаёт пересланные нативные данные за собственный запуск.

В продолжении выполнен файловый анализатор и проверка подготовленных материалов. **Новых Go/Rust-сборок, тестов или измерений нет. Обе полные Go-команды из предыдущего этапа остаются FAIL.** Нативные запросы из таблиц 1–2 повторно не запускались. [Квитанция подготовки](fixture-validation.json) фиксирует ноль синтаксических ошибок, 2459 токенов и наличие `Apply` при `Parser.ParseFile`. Обычный `-File` без `-Apply` на предшествующей версии сценария завершился отказом `UnauthorizedAccess` до исполнения сценария: режим планирования не выполнен, JSON плана не получен. Это отказ политики Windows PowerShell, не автоматической проверки разрешений инструмента. Значение действующей политики не установлено из-за отдельного отказа загрузки `Microsoft.PowerShell.Security`.

Сценарий прошёл собственное и независимое неавторское статическое ревью. Сверка с настоящим Git blob выявила один лишний конечный LF в первоначальном подготовленном снимке исходника; снимок и единственный литерал ожидаемого хеша в сценарии исправлены. Синтаксис окончательного сценария проверен повторно, отказ запуска оставлен привязанным к прежнему хешу. Документация уточняет фактическую проверку SYSTEM/сеанса 0/интерактивности, границу 15-секундного ожидания выхода дочернего процесса, неограниченное ожидание его потоков и синхронных COM-вызовов. Сценарий не обещает общего предельного времени или атомарного удаления. Точные байты сценария и отдельного снимка исходника повторно сверены на Comet; рабочая копия #660 не редактировалась.

Нет заключения о полной поддержке Unicode, hidden/denied/unavailable, атомарном снимке, действующем Product или формальном внешнем ревью. Совпадение четырёх чтений обнаруживает наблюдённую стабильность, но не запрещает изменение между чтениями. Новые PR, слияния, объединение патчей, установки, изменение системных задач/политик и внешние квотные проверки этим этапом не выполняются.

## 9. Термины

COM — Component Object Model, компонентная модель Windows. CIM — Common Information Model, общая модель управленческих данных. XML — Extensible Markup Language, формат определения задачи. UTF-8/UTF-16LE — кодировки Unicode; LE означает младший байт первым. BOM — маркер порядка байтов. CR/LF — возврат каретки/перевод строки. URI — идентификатор определения внутри XML. HRESULT — 32-битный код результата Windows. SID — идентификатор безопасности учётной записи. SHA-256 — контрольная сумма. Stdout/stderr — стандартные потоки вывода/ошибок. PASS/FAIL — успешная/неуспешная проверка; Draft — черновой PR.
