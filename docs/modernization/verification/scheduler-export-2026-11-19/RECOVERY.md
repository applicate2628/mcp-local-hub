Стандартный поток ошибок содержит только проверенные сообщения подготовки модулей в формате CLIXML — сериализованном XML (Extensible Markup Language, расширяемый язык разметки) PowerShell. Оно сохранено отдельно в `recovery-observation-01.json`. **Новое удаление не полагается на это наблюдение:** сценарий повторно читает текущую задачу непосредственно перед возможным удалением.

## Единственная попытка и результат

До любых действий с Планировщиком создаётся новый `recovery-visible-intent.json` с режимом `CreateNew` и сбросом записи на диск. Существующий файл запрещает повторный запуск; его нельзя удалять или переименовывать для обхода этого ограничения. Даже ошибка последующей проверки расходует эту попытку и требует нового разбора.

Текущее состояние целевой задачи читается заново. Проверяются полное XML, имя и путь, маркер, URI (Uniform Resource Identifier, идентификатор определения), SID принципала, оба признака отключения, состояние `1`, `Hidden=false`, отсутствие триггеров, запрет запуска по требованию, интерактивный тип входа `3`, минимальный уровень привилегий `0`, единственное действие типа Exec `0`, пустые аргументы и отсутствие указанного исполняемого файла. После последней сверки следует ровно один вызов `DeleteTask`. Затем `GetTasks(1)` — перечисление с включением скрытых задач — проверяет отсутствие только точного целевого имени.

Новое свидетельство результата записывается отдельно в `recovery-visible-result.json` без перезаписи прежних файлов. Общий вывод содержит только состояние, логические признаки и разрешённый путь. Подробная ошибка остаётся в этом локальном свидетельстве.

Код завершения 0 требует `ABSENCE_OBSERVED` и успешной записи отдельного результата. Наличие только нового intent-файла, пустой/отсутствующий результат или `receipt_written=false` означает необходимость проверки только чтением; автоматического повтора нет. Изменение задачи или ошибка чтения до удаления прекращает мутацию. Ошибка после вызова удаления не превращается в заявление, что ресурс точно сохранён или точно удалён.

Планировщик не предоставляет атомарную операцию «сравнить и удалить»: внешнее изменение после последнего чтения полностью исключить нельзя. При известном или предполагаемом стороннем изменении этой задачи новый допуск не следует использовать до разбора. Нет общего таймера, запасного исполнителя, запуска задач, обновления определения, изменения других задач или очистки свидетельств. Этот шаг восстанавливает только ресурс; он не объявляет исходную проверку успешной и не квалифицирует публичный Go-интерфейс, Stop или RunOwned.
