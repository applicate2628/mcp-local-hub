## 2. Исправление daemon-помощника

После появления `TestOwnedIsolatedStdioFixture` в master прежний `TestMain` из #658 сначала создавал пакетный каталог состояния. Fixture завершала процесс через `os.Exit`; обычная отложенная очистка `TestMain` не исполнялась. Реальный контроль оставил один такой каталог, хотя протокол fixture завершился успешно.

Исправление классифицирует точный вызов до выделения каталога: проверяет единственный anchored selector, разрешённый режим и согласованность маркеров. Anchored selector ограничивает выбор полным именем теста с `^` и `$`. Смешанные роли и дополнительные аргументы отклоняются. Для обычного запуска сохраняется прежняя изоляция состояния.

Приватная fixture должна завершать процесс самостоятельно. Если `m.Run` неожиданно вернулся с кодом 0, helper-ветвь возвращает код 2. Это проверено отдельным бинарником с переименованной fixture: Go напечатал `PASS`, но реальный процесс завершился кодом 2. Переименование служит только внесению отказа в проверку и не входит в публикуемый код.

## 5. Границы среды и сохранённые отказы

Один промежуточный вызов форматтера произошёл вне окончательной среды с перенаправленным профилем. Последующий аудит прочитал существующие счётчики Go в пользовательском профиле: нового файла, соответствующего времени вызова, не найдено, но изменение уже отображённого в память счётчика исключить нельзя. Это ограничение сохранено; очистка профиля на C не выполнялась. Последующие исполнители направляют `TEST_TELEMETRY_DIR` и профильные каталоги на D и записывают telemetry mode `off`.

Первый самостоятельный API-proof остановился **до запуска helper**: проверка ожидала `off\n`, а Windows записала `off\r\n`. Исходный результат `completed=false`, пустой список команд и причина сохранены в API-архиве. Проверка v2 допускает только эти две точные кодировки, записывает реальные байты и их хеш; установленный parser telemetry удаляет окружающие пробельные символы.

Первоначальный поиск `bash` выбирал системный Windows launcher. Он не запускался. Для stdout-фикстуры отдельно выбран и закреплён существующий MSYS Bash; попытка прочитать WindowsApps reparse target сохранена как отказ статического аудита. Приватные оригиналы с путями пользовательского профиля не включены в публичный комплект; их хеши и редактированные наблюдения сохранены.

Перенаправление переменных среды не является системной песочницей. Разрешённость каждого выбранного теста установлена чтением его фактического пути исполнения. Команды не выполняли операций с установленным Hub или Task Scheduler.

## 6. Что требуется для полных наборов Go

Обязательные команды остаются открытыми:

```text
go test -count=1 -timeout 5m ./...
go test -tags=test_state_path_env -count=1 -timeout 5m ./internal/api/ ./internal/cli/
```

Статическая инвентаризация на master нашла 1 368 файлов тестов в 64 каталогах; в корневом модуле — 1 364 файла в 63 каталогах после исключения четырёх файлов вложенного third-party модуля. Это число файлов/каталогов, не число Go-пакетов или прошедших тестов.

**Таблица 5 — конкретные оставшиеся условия допуска.** Полные места в коде и аргументы команд сохранены в `admission-audit/README.md` и `external-tools.md` архива.

| Вход | Что ещё необходимо |
|---|---|
| GUI PowerShell fixtures | Исходный процесс и единственный присоединённый `Wait`; две новые опции не исправляют прежнее ожидание и не квалифицируют PID-based production kill |
| `perftools.DetectTools` | Допуск четырёх реальных `--version` вызовов до возможного Skip; их текущие сроки и вывод не ограничены |
| CMake / Hyperfine | Точные generator/toolchain/launcher и shell; прямой handler Hyperfine обходит gate регистрации, пишет временный JSON; нужен реальный consumer profile |
| oneAPI | Первый `EnvOverlay` может запустить существующий `setvars`; кэш `sync.Once` нельзя подменять так, чтобы последующий тест потерял настоящий вход |
| POSIX fake clang-tidy | Shebang `/usr/bin/env bash`, утилиты `head`/`tr` и стартовая среда требуют отдельного допуска |
| Windows junction fixture | `cmd /c mklink /J` выполняется до Skip; требуется учесть `cmd` AutoRun и владение созданной fixture |
| Canonical entry / Product | Обязательный Windows-тест требует квалифицированный абсолютный `MCPHUB_CANONICAL_ENTRY_FIXTURE`; отсутствие fixture означает отказ, а не разрешение обойти проверку |
| Serena и прочие нативные роли | Отдельные допустимые образы для 13 обнаруженных selectors; реальные acquisition/upgrade/rollback и установленный продукт не доказаны |

`go test -run '^$'` всё равно исполняет `TestMain`; он не заменяет компиляцию через `go test -c`. `-short`, закрытый gate модели и каталог на D сами по себе не доказывают допустимость полного набора. Исторические FAIL остаются привязанными к прежним источникам; здесь не заявлено их повторение на новом master.

## 7. Ревью, публикация и остаток программы

Собственное ревью проверило сохранение обязанностей #658, точный helper dispatch, совместимость обычного `TestMain`, отрицательные контроли, корректность архивирования и границы выводов. Независимые разборы дополнили его; они не заменяют требуемое внешнее ревью опубликованного commit.

Исходный #658 можно закрыть только после обратного чтения новой ветки, полного различия и опубликованных payload. Исходная ветка и checkpoint сохранения остаются доступны; закрытие не означает слияния. Отдельная квитанция фиксирует фактические ссылки и завершённую проверку публикации.

Архитектурное продолжение опубликовано отдельно в [#663](https://github.com/applicate2628/mcp-local-hub/pull/663): перенос известных нарушений подтверждён, но `archcheck verify` по-прежнему возвращает exit 1, а платформенный Skip сохраняет строгий статус FAILED. Остаток общей программы — настоящие Scheduler/owner права и действия, согласованная Serena с допустимым Product, потребители Relay/CMake, Rust у реального владельца, полные Go-наборы и точное внешнее ревью — остаётся в действующем плане с собственными условиями выхода.
