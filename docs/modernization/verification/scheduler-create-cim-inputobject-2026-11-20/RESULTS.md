# R17: разделение Create/ImportXML и проверка экспорта CIM

20 ноября 2026 года, Москва. Код опубликован в существующем [#660](https://github.com/applicate2628/mcp-local-hub/pull/660): **`b7831aabdb7162b3a39c78e73c3ab67558236d1d`**, дерево **`b55002a0255e8cd226c84afa00499c12c2906c0e`**, единственный родитель **`9721681633440d3593d37ffb8f580e5d98440da2`**. Свидетельства размещены в документационном #623; ветки не объединялись.

**Результат ограниченный:** `Create` больше не передаёт принудительную замену `/F`; `ImportXML` сохраняет её. Отрицательный контроль и проверки опубликованного кода прошли в своих границах. Отдельное нативное чтение установило структурное расхождение экспорта `InputObject` с COM; экспорт по каноническому имени этой же задачи совпал побайтно. Производственный экспорт не изменён. Общие критерии Go и полная квалификация R17 остаются открытыми.

## 1. Изменение и контракт

Дельта относительно родителя содержит **два Go-файла, +134/−1**: производственный метод меняется на +3/−1, новый тест занимает 131 строку. `windowsScheduler.Create` перестаёт добавлять `/F` к `schtasks /Create /TN … /XML …`; `ImportXML` оставляет явную замену. Параметр `/F` документирован Microsoft как подавление предупреждения при существующей задаче [1]. Стандартный ввод обоих дочерних процессов остаётся `nil`; `os/exec` подключает его к нулевому устройству [2]. Это не доказывает конкретный код возврата и поведение установленного `schtasks` при конфликте и EOF.

Новый тест использует существующий `schtasksPath`, направляя команду на тестовый исполняемый файл. Обработчик принимает только ожидаемую форму команды, проверяет пустой стандартный ввод, моделирует конфликт кодом **17**, сохраняет прежние байты и допускает явную замену только при `/F`. Проверяются свежий Create, повторный Create с другим определением и ImportXML с кириллицей и символом `§`, включая точные UTF-16LE-байты с BOM. У вспомогательного процесса есть собственный десятисекундный ограничитель. Настоящий Планировщик этот тест не изменяет.

Семь производственных вызовов Create уже предваряются Delete: по одному в `internal/autostart/windows.go`, `internal/api/install.go`, `internal/api/register.go`, `internal/api/weekly_refresh.go` и три в `internal/api/scheduler_mgmt.go`; точная семёрка и условия приведены в [аудите](AUDIT.md#consumers). Зависимости этих семи мест от неявного `/F` не найдено. Их собственные ошибки удаления, отката и внешней замены не исправляются этой дельтой.

## 3. Нативное сравнение экспортов

Это **отдельный наблюдатель**, а не запуск кода #660. Он прочитал одну существующую видимую корневую задачу через COM — компонентную модель Windows — и CIM — общую модель управленческих данных. `Get-ScheduledTask` получил имя с иным регистром, но вернул единственный объект с точными каноническими именем и путём. Использованы Windows PowerShell **5.1.22621.6133** и ScheduledTasks **1.0.0.0**. Команды получения и экспорта входят в официальный модуль [3, 4]. Изменяющие операции Планировщика отсутствуют.

Первый завершённый наблюдатель `-InputObject` дал **MISMATCH** за 3,171557 с. Прямой дочерний процесс завершился с кодом 0, но внешний наблюдатель правильно вернул 1 по результату сравнения. Это пример, почему код оболочки не заменяет проверку вложенного результата.

Последующее единственное различающее измерение добавило канонический экспорт `-TaskName/-TaskPath` и сравнение структуры. Оно завершилось за **1,768256 с**, подтвердив прежние хеши.

**Таблица 3 — UTF-8-представления одного определения.**

| Чтение | Байты | SHA-256 | Сравнение |
|---|---:|---|---|
| COM до | 1427 | `cc89e966659d61a42883c2f8038f6065f59c9a8438ff12ac7e87058e94493e94` | Исходное |
| CIM `-InputObject` | 2023 | `c8db5b364d923253b251cf25729a36b7bed1376c1538785b51c1ca07d436c692` | Не совпало с COM |
| CIM по каноническим имени/пути | 1427 | `cc89e966659d61a42883c2f8038f6065f59c9a8438ff12ac7e87058e94493e94` | Побайтное совпадение |
| COM после | 1427 | `cc89e966659d61a42883c2f8038f6065f59c9a8438ff12ac7e87058e94493e94` | Побайтное совпадение |

Компаратор исключает XML-декларацию, написание префиксов пространств имён и отступы между элементами; сохраняет порядок элементов, текст листовых элементов и значения атрибутов. Он запрещает DTD, смешанное содержимое, комментарии, инструкции обработки и `xml:space`, ограничивает размер и глубину. Значения сравниваются только в памяти. Результат содержит стандартные пути и виды различий; неизвестные имена маскируются.

**Таблица 4 — структурные различия COM → InputObject.**

Следовательно, различие **не сводится к форматированию**. По этим данным нельзя объявлять добавленные поля безвредными значениями по умолчанию, доказывать семантическую эквивалентность или повреждение задачи. Два COM-снимка определения побайтно совпали; изменения между чтениями не исключены. Атомарность интервала между чтениями не доказана.

`COMPARISON_COMPLETE` и `passed=true` последнего наблюдателя означают успешное завершение диагностики на стабильных снимках, **не равенство InputObject-экспорта**. Приватные XML, значения полей и сырые потоки этих двух завершённых наблюдателей не сохранены: доступны код сравнения, вычисленные хеши и квитанции, но не исходный XML-набор для независимого повторного вычисления. Настоящий продуктовый потребитель не запускался.

## 4. Сохранённые неуспехи диагностики

**Обвязка отрицательного контроля.** Первый runner получил ожидаемый тестовый FAIL, но искал буквальное `<nil>` в JSON, где Go записал `\u003c` и `\u003e`. Поэтому его квитанция осталась `completed=false` до применения производственной правки. Исправленная обвязка разобрала JSON, сверила исходные потоки, состояние дерева и файл теста, затем применила уже проверенный кандидат. **Контроль не запускался повторно.** Начальный сценарий, журналы и отказ сохранены отдельно от recovery.

**Подготовка закрытого каталога.** Первоначальная нативная попытка остановилась в фазе `protect` с `MethodInvocationException`, HRESULT `−2146233087`, до чтения задач и сохранения XML. Внутреннее исключение не удержано; конкретная причина исторического отказа **неизвестна**. Отдельная диагностика только в памяти успешно построила три правила; чтение каталога показало унаследованные права, без защищённого списка. Это не устанавливает причину первого исключения. Запись прав не повторялась. Дальнейший наблюдатель был ограничен хешами/путями структуры, не хранил приватные определения и не выполнял операции изменения прав.

Ожидание непосредственно созданных процессов подтверждено квитанциями. Полный срок и завершение **всего дерева потомков** этим не доказаны. Отсутствие активных терминальных сессий — отдельное наблюдение, а не доказательство дерева. Установок, изменения политики, изменений системных задач и ручного запуска CI не было.
