## 1. Требование

Общий цикл `executeInstallToWithSymlinkConsents` должен различать отсутствие задачи, пригодный сохранённый снимок её определения и неизвестный результат чтения. Неизвестный снимок не разрешает удаление; неуспешное удаление не разрешает последующее создание. Ошибка возвращается через существующий `failAfterRollback`, который выполняет компенсации ранее завершённых шагов.

Изменяются только блок допуска к замене в `internal/api/install.go` и новый тестовый файл `internal/api/install_scheduler_snapshot_test.go`. Другие ветки не объединяются; интерфейс `scheduler.Scheduler`, платформенные команды, prune, register, weekly и реализация существующих компенсаций не меняются.

## 3. Исполнение и свидетельства

Перед запуском фиксируются байты двух файлов и патчей в `source-manifest.json`, точный базовый коммит, дерево и чистота исходного клона. Отдельный клон создаётся из существующего локального репозитория той же ветки. Все рабочие каталоги, пользовательские профили, временные файлы и используемые кэши находятся под `<WORK_ROOT>`; используются только уже установленные инструменты, загрузка модулей и другого toolchain отключена.

План проверок:

1. Отрицательный контроль: исходный производственный код + только новые тесты, один проход. Ожидаются 5 корневых тестов и 10 подслучаев с ошибкой, а также ошибка пакета; проверяется причина, а не только ненулевой код команды.
2. Кандидат: та же выборка с детектором гонок Go (`-race`) и двумя повторами (`-count=2`). Ожидаются 30 тестовых записей PASS и одна пакетная, без FAIL/SKIP.
3. Соседний контракт `TestExecuteInstallTo_PassAPassB_Separation`: три подслучая и корневой тест, два повтора с `-race`; создание без запуска, запуск только logon-задач и прежний предупреждающий исход отказа Run. Исполнитель планировщика подставной.
4. `go build ./...` и `go vet ./...` кандидата. Полные наборы не квалифицированы для этой базы по сохранённым ограничениям TestMain/продуктовых входов; не объявлять их пройденными и не запускать заблокированный набор заново без изменённой предпосылки.
5. После публикации — чистый checkout точного нового коммита и повтор целевой выборки. Это проверка опубликованных байтов, не интеграция другой ветки.

Каждая реально выполненная команда сохраняет аргументы, код завершения, длительность, исходные stdout/stderr, контрольные суммы и квитанцию. Прогнозы результатов в этом документе не являются результатами исполнения. Отдельно фиксируются состояние исходников до/после, прочтение публикации и состояние активных командных сессий.

## 4. Открытые границы

- Успешный Delete и неуспешный Create по-прежнему требуют отдельного контракта восстановления текущей задачи. Слепое перемещение прежней компенсации перед Create может удалить или перезаписать внешнюю задачу.
- Ошибка Delete может иметь неопределённый нативный исход; подставной отказ до применения не доказывает сохранность настоящей задачи после ошибки.
- Проверка снимка и последующее действие не атомарны. Конкурирующая замена между Export/Delete и при восстановлении остаётся открытой.
- `ImportXML` использует принудительную замену `/F`; нативное владение и условный импорт этой правкой не реализуются.
- Никакие реальные задачи Windows не создаются, не изменяются, не запускаются и не удаляются данной серией. Время команд не является оценкой производительности продукта.
- Ожидание прямого дочернего процесса не доказывает завершение всего дерева процессов и не обеспечивает общий жёсткий срок. Общие Go-критерии, полная готовность PR и внешний одобряющий отзыв остаются отдельными условиями.

Сокращения: PR — запрос на включение изменений; XML — расширяемый язык разметки, здесь формат определения задачи; API — программный интерфейс; stdout/stderr — стандартные потоки вывода и ошибок; SHA-256 — алгоритм контрольной суммы; PASS/FAIL/SKIP — успешно/ошибка/пропущено.
