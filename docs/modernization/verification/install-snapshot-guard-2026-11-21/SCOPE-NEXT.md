<a id="граница"></a>
## 2. Следующая граница

В `executeInstallToWithSymlinkConsents` компенсация текущей задачи всё ещё добавляется **после успешного Create**. Если снимок и Delete прошли, а Create вернул ошибку, вызывается откат ранее завершённых шагов, но текущая задача ещё не зарегистрирована для восстановления. При отсутствии внешних изменений это оставляет удалённое определение невосстановленным. Это прежняя граница, не внесённый guard дефект [1, 5].

Перенос существующей компенсации перед Create небезопасен: она вызывает Delete по имени и затем `ImportXML`, который в Windows использует принудительную замену `/F`. При конфликте или неопределённом исходе Create такая компенсация может удалить либо перезаписать уже появившуюся внешнюю задачу. Предварительный повторный Export сам по себе не делает последующий импорт атомарным [1–3, 5].

Поэтому ближайший результат — **явный контракт восстановления сохранённого XML, при котором backend сам отказывает при занятом имени и не заменяет существующее определение**, плюс различающие проверки исходов Create. XML — формат определения задачи; backend — платформенная реализация. Наличие такого нативного свойства у предлагаемого пути нужно установить отдельно; исключение `/F` из аргументов само по себе здесь не объявляется доказательством всей гарантии.

<a id="результат"></a>
## 3. Проверяемый результат следующего среза

**Таблица 1 — минимальная матрица для текущей задачи, без расширения всей транзакции.** Это предлагаемые критерии, не результаты выполненных тестов.

| Исход после сохранённого снимка и успешного Delete | Требуемое различение |
|---|---|
| Create отказал до изменения; имя по-прежнему свободно | Восстановить прежние байты через квалифицированный путь без замещения; сохранить исходную ошибку Create |
| После Delete появилась внешняя задача; Create или восстановление обнаруживает конфликт | Сохранить внешние байты; не выполнять дополнительный Delete или принудительный импорт; вернуть различимый конфликт восстановления |
| Create вернул ошибку после возможного создания или при неизвестном применении | Оставить неопределёнными эффект и владельца обнаруженной задачи; совпадение XML не устанавливает право удалить её; не выполнять слепую очистку |
| Само восстановление вернуло ошибку или неопределённый результат | Сохранить доступный снимок, причину Create и отдельную причину восстановления; не сообщать об успешном восстановлении или удалении |
| Ошибка возникла на Delete, до входа в новый путь | Сохранить нынешнее прекращение шага; не подменять неизвестный исход Delete утверждением о неизменности нативной задачи |

Первый ограниченный результат можно получить без изменения общей установки: новая модель должна различать отказ Create до применения, конфликт с внешним определением и ошибку после возможного применения; статический разбор должен установить, какой существующий или минимальный отдельный платформенный путь способен выполнить указанный контракт. Затем подключение к одной ветви отказа Create становится отдельной проверяемой дельтой. Обычный `ImportXML` и намеренные сценарии замены нельзя глобально менять ради этого одного вызова.

При отказе восстановления контракт также должен определить, у кого остаётся снимок и как он доступен для следующего решения. Нынешняя локальная переменная `priorXML` сама по себе не обеспечивает долговременное сохранение.

Критерий завершения выбранного среза: известны точный источник операции, её входы/исходы и гарантии отказа при конфликте; модель обнаруживает нынешнюю потерю текущего определения и отличает безопасное восстановление от затирания внешней задачи. Если подтверждены только модель и командные аргументы, именно эта ограниченная область считается завершённой; нативная квалификация и подключение восстановления остаются явными последующими шагами.

<a id="ограничения"></a>
## 4. Сохраняемые ограничения

- Реальная неопределённость Delete, внешняя замена между Export/Delete, владение при последующем откате и безопасность существующего принудительного ImportXML остаются открытыми. Новый путь после отказа Create не закрывает их автоматически.
- Непустой XML не доказывает возможность нативного импорта. Модель сохранения байтов не заменяет настоящую проверку задач Windows.
- Полный install/register/upgrade/weekly, ошибки остальных компенсаций, реальные Run/RunOwned/Stop/Delete, общий срок дерева процессов и общие Go-критерии не входят в этот срез.
- Наблюдённая пауза между последним тестовым событием и завершением go-команды не имеет установленной причины. Адресная работа восстановления не объясняет её и не закрывает общий бюджет.
- Работа остаётся у владельца #660. Код #659, тестовые исправления #658 и параллельный Rust не переносятся; объединение веток или патчей не требуется. Повтор общей очереди откладывается до окончательных вершин веток.
