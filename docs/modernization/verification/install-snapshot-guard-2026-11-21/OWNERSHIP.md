## Соседние условия для ревью guard

На [точном исходнике install.go](https://github.com/applicate2628/mcp-local-hub/blob/11c286fb634cc63d2c6019a790ff376a1d834af9/internal/api/install.go) ошибки ExportXML и Delete подавляются, а восстановление текущей задачи регистрируется только после успешного Create. Следовательно, отдельное защитное условие перед Delete не устраняет прежнюю потерю восстановления при последовательности **успешный Delete → неуспешный Create**. Эту границу нужно оставить явно открытой либо отдельно обеспечить её восстановление.

[Windows-реализация](https://github.com/applicate2628/mcp-local-hub/blob/11c286fb634cc63d2c6019a790ff376a1d834af9/internal/scheduler/scheduler_windows.go) передаёт ошибку COM из ExportXML; пустое определение при успешном ответе даёт `ErrTaskCorrupt`. Delete превращает `ErrTaskNotFound` в успех. [Сопоставление ошибок COM](https://github.com/applicate2628/mcp-local-hub/blob/11c286fb634cc63d2c6019a790ff376a1d834af9/internal/scheduler/scheduler_com_windows.go) выделяет `task_absent → ErrTaskNotFound`, а отсутствие прав, повреждение и недоступность сохраняет как другие ошибки.

Комментарий [общего интерфейса](https://github.com/applicate2628/mcp-local-hub/blob/11c286fb634cc63d2c6019a790ff376a1d834af9/internal/scheduler/scheduler.go) описывает ошибку неподдержанного ExportXML для Linux/macOS. Общий guard требует отдельной оценки платформенной применимости. В этой проверке владельцев реализации этих платформ не читались; один комментарий не доказывает их фактическое поведение.
