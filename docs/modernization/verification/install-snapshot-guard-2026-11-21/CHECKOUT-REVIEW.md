## Границы результата

1. **Происхождение publication input проверяется владельцем операции.** Строки 104–110 сверяют структуру входа и привязку к контрольным суммам сценария и manifest. После получения объекта строки 126–134 проверяют реальное Git-дерево, родителя и байты исходников. Сам сценарий не доказывает, что `publication-input.json` ранее был сформирован именно из ответов GitHub; эту связь обеспечивает внешняя процедура публикации и чтения результата.

2. **Доказательства собираются для трёх основных команд.** `stage-exact-files`, `fetch-exact-commit` и `checkout-detached` проходят через `run`: сохраняются код возврата, снимки состояния до и после, исходные потоки и их контрольные суммы; ошибка послеоперационного снимка препятствует подтверждению успеха (строки 52–85). Служебные вызовы `git()` — включая `write-tree`, проверки родителей, дерева и списка путей — отдельные квитанции и исходные потоки не сохраняют. Их результаты участвуют в условиях допуска. Формулировка «отдельная квитанция каждого запущенного процесса Git» была бы шире реализации.

3. **Неуспешный переход может оставить подготовленный индекс.** Если staging завершился, а последующее сравнение дерева, fetch или checkout не прошло, сценарий прекращает работу без автоматического сброса индекса (строки 122–138). Рабочие файлы кандидата и свидетельства сохраняются в выделенной копии; повторный запуск потребует разбора её фактического состояния. Это не транзакция с гарантированным возвратом к начальному состоянию.

4. **Жёсткого срока завершения дерева процессов нет.** Основные команды ожидаются через неограниченный `child.wait()` (строка 64); служебные запросы Git имеют `timeout=60` (строки 38–41). Поля `whole_process_tree_deadline_enforced=false` и `direct_child_wait_bounded=false` отражают это корректно. Сценарий не заявляет и не реализует управление всем деревом дочерних процессов.

5. **Настроенные места записи находятся на D:, но это не файловая изоляция.** Исходники, журнал, runtime, временные каталоги и пользовательские каталоги явно размещены под `<WORK_ROOT>`; Git запускается из существующей установки на `C:`. Настройки отключают интерактивные запросы, credential helper, глобальную/системную конфигурацию и hooks. Они не являются общей гарантией отсутствия любой побочной записи со стороны произвольного унаследованного окружения или инструмента.

Результат этого документа — оценка замороженного сценария чтением кода. Факт успешного перехода и итоговую идентичность опубликованных исходников должны подтверждать отдельные квитанции реального исполнения.
