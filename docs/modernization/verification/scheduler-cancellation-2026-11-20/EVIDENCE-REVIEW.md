# Независимая проверка пакета свидетельств отмены

**Дата:** 20 ноября 2026 года. **Проверяющий:** `/root/cancel_verification`, отдельный исполнитель, не автор продуктовых изменений, тестовой коррекции или упаковщика.

**Результат:** в проверенном локальном архиве не найдено нарушений целостности, несогласованности квитанций или существенных расхождений между фактическими результатами и адресными выводами отчётов. Все проверки ниже выполнены независимо по доступным байтам, без исполнения вложенных скриптов, повторного запуска продукта или удалённых команд.

Это заключение относится к указанному архиву и точным снимкам кода. Оно дополняет собственное ревью основного исполнителя и не является формальным внешним PASS или общей приёмкой веток. **Получение архива обратно из GitHub и проверка полученных байтов на момент этого заключения ещё не выполнены данным проверяющим.**

## 2. Целостность архива и различие исходных и публичных байтов

Архив открыт независимо средствами стандартной библиотеки Python. Проверены CRC каждой записи, отсутствие повторяющихся имён, абсолютных путей, переходов `..` и записей символических ссылок. Перечень записей точно равен 157 строкам манифеста плюс сам манифест. Размер и SHA-256 всех 157 сохранённых файлов рассчитаны заново. Внешние копии `MANIFEST.json`, `execution-summary.json` и `source-identities.json` побайтно совпадают с архивными и с их записями в `archive-metadata.json` [1–3].

Для каждой строки манифеста отдельно проверены поля `source_bytes/source_sha256` и `saved_bytes/saved_sha256`. Признак `redacted` согласован с различием этих пар. Обезличены 27 файлов архива; это не означает, что все они являются командными потоками.

Из 86 потоков **83 не обезличивались**: их доступные публичные байты независимо совпали и с сохранённым хешем, и с исходным хешем квитанции. У трёх остальных потоков независимо проверены публичные байты и связи исходных хешей с квитанциями и манифестом:

- `cli/baseline/init-exact-source.stdout.log`;
- `scheduler/adjacent-baseline/clone-baseline.stderr.log`;
- `scheduler/control/clone.stderr.log`.

Исходные приватные байты этих трёх потоков локально повторно не получались. Их первоначальная проверка размера и хеша выполнена рассмотренным упаковщиком до обезличивания; локальная проверка не подменяет их публичными байтами. **Все восемь потоков JSON-событий тестов остались неизменёнными**, поэтому их независимый пересчёт основан на исходных потоках, а не на восстановленных или отредактированных событиях.

Для каждой команды проверены обе связи «квитанция → исходный хеш строки манифеста → сохранённый файл». Все 37 отдельных командных квитанций совпадают со своими строками в квитанциях этапов. Для шести команд получения опубликованных снимков отдельные командные квитанции не предусмотрены исполнителем; их строки и потоки проверены внутри двух соответствующих квитанций этапов.

В публичных байтах не обнаружены проверенные шаблоны исходного рабочего пути, пользовательского профиля, персонального Windows SID, токенов GitHub или закрытого ключа. Полных файлов с расширением `.go` в архиве нет. Это конкретные выполненные проверки, а не универсальное доказательство отсутствия любых возможных секретов.

## 3. Пересчёт фактических событий тестов

Независимо разобрано **391 JSON-событие в восьми тестовых потоках**. Проверены точные имена, количество повторов, состав пакетов, соответствие событий `run` конечным событиям и совпадение с квитанциями и сводкой. Проверены аргументы `-run`, пакет, `-count`, `-timeout` и наличие `-race`: отрицательный контроль запускается один раз без детектора гонок; остальные семь команд используют два повтора с детектором [2, 4].

У каждого из пяти конечных случаев отрицательного контроля найдено именно сообщение `error identity lost:`. Для нового `TestReconcileIPC_ParentCancellationReachesSchedulerList` подтверждены два успешных повтора в кандидате и два на опубликованном снимке.

Отдельно проверены четыре команды `go build ./...` / `go vet ./...`: их коды выхода равны нулю. Их результаты не учтены как исполнение тестов. Длительности и состав событий в таблице 3 отчёта RESULTS согласуются с командными квитанциями; сравнение производительности из них не выводится. Два сохранённых ответа `go version` одинаковы: `go version go1.27.4 windows/amd64`.

## 4. Привязка исходников, исполнителей и публикаций

Для всех этапов проверены предусмотренные исполнителем исходные и конечные хеши, HEAD, дерево и состояние рабочего каталога. У исторически неуспешного `scheduler/adjacent` сохранено `completed=false`, ошибка `reconcile-timeout-race failed` и только первоначальный допуск исходников. Финальные поля отсутствуют; данные позднейших этапов в эту квитанцию не добавлены. У процедур воспроизведения `completed=true` согласуется с подтверждённым ожидаемым отказом вложенной команды, а не с её успехом.

Кандидатные исходники трёх изменённых файлов повторно хешированы локально; SHA-256 и Git blob совпадают с ранее рассмотренными версиями. Архивные кандидатные патчи применены **только к строкам в памяти**, без изменения файлов или рабочего дерева: результат каждого из трёх файлов побайтно совпал с рассмотренным кандидатом. Записи публикации содержат ровно два изменённых файла #660 и один тестовый файл #658.

У CLI есть допустимое различие представления diff: сохранённый патч `difflib` содержит 26 добавлений и 17 удалений, а запись GitHub — 25 и 16. Независимый расчёт наибольшей общей подпоследовательности изменённого участка подтвердил минимальные 25 добавлений и 16 удалений. Проверка применения патча и полных байтов результата закрывает эту неоднозначность; различие выравнивания строк не является отличием кода.

Каждая из 13 квитанций связана с сохранённой версией своего исполнителя по **исходному** SHA-256. Проверены различные версии Scheduler-скрипта для отрицательного контроля, положительных запусков, исходного воспроизведения и опубликованного снимка. Изменённые публичные копии скриптов имеют отдельные сохранённые хеши и не выдаются за исполнявшиеся оригиналы.

Исходный CLI-манифест `2dc2c2b5d4078031b904af053b0ad4f8247b367ae966663f8ffb3f8ac21e5c39` сохранён как execution input; дополнительный манифест ревью `693b3123ef67e900e996668032c2352805956eff737a9fecc439812010fbf709` не подставлен в старые квитанции. Связи `retained_control_receipt_sha256` и `retained_baseline_receipt_sha256` совпадают с исходными хешами соответствующих сохранённых квитанций.

У обоих опубликованных снимков согласованы единственный родитель, полное дерево, пустое состояние рабочего каталога и кандидатные хеши до и после проверки. Архив не заявляет локальной интеграции #658 и #660.

## 5. Упаковщик и публичные отчёты

До исполнения упаковщика независимо прочитаны все 555 строк версии **`c098154a81ec19e5e1fffccb4b05378b635c7e90bd53507d3e97eed2f44561ac`**, 36 598 байт; проверен синтаксис Python без запуска. Рассмотрены допуск собственных входов, сохранение неуспешных этапов, связи версий исполнителей, учёт событий, обезличивание, различение исходных и публичных хешей и создание новых выходов только после допуска и проверки архива в памяти. Конкретного блокирующего дефекта в этой ограниченной области не найдено. Исходный хеш вложенной записи упаковщика совпадает с этой рассмотренной версией.

При чтении RESULTS и AUDIT существенных расхождений с проверенными результатами не найдено. Отчёты сохраняют следующие различия:

- остановленный до запуска контекст #660 и отмена после входа в подменённый CLI-планировщик — разные проверенные сценарии;
- новый тест #658 не квалифицирует реальное истечение срока обработчика во время работы планировщика;
- ожидаемый исходный FAIL не превращается в PASS;
- прямые команды завершены, но общий срок и завершение всего дерева процессов не доказаны;
- адресные проверки, сборка и анализ не являются полным прогоном тестов или общей готовностью веток.

Количество результатов литерального поиска в `scheduler/source-review.json` согласуется с AUDIT: 2581 отслеживаемый Go-файл, 10 прямых вызовов `errors.Unwrap` в тестах и восемь `t.Parallel()` в одном другом Scheduler-файле. Проверена идентичность сохранённого результата поиска и его связь с исполнителем; полный поиск по удалённому репозиторию этим проверяющим не повторялся. Наличие альтернативных вызовов, отражения или внешних потребителей из этих чисел не исключается.

Уточнено происхождение первоначальной ошибки декодирования: `UnicodeDecodeError` при неявном cp1251 и успешное чтение с явным UTF-8 действительно содержатся в **отдельном** `preflight-redacted.json`, а не внутри ZIP. Файл прочитан; его поле `original_sha256` является идентификатором исходной записи, чьи необезличенные байты здесь не предоставлены. Это уточнение не требует повторного продуктового запуска и не меняет результаты таблицы 3.

## 6. Пределы заключения и оставшаяся проверка

Данная независимая проверка подтверждает целостность доступного пакета, внутреннюю согласованность сохранённых первичных событий и соответствие адресных выводов этим событиям. Она не добавляет отсутствующие гарантии:

- реальная отмена уже запущенного COM-моста и завершение его потомков не исполнялись;
- общий внешний таймер компиляции, сборки, анализа и всего дерева процессов отсутствует;
- полные наборы Go, реальные установленные потребители и объединённый снимок веток не проверялись;
- новые выводы о производительности, отсутствии всех утечек или всех гонок не сделаны;
- для трёх обезличенных потоков и обезличенных служебных записей исходные приватные байты повторно локально не хешированы;
- исторические результаты вне этой серии, прочтение навыков другими исполнителями и актуальное состояние всей очереди PR не пересвидетельствованы этим проверяющим.

Следующий остающийся этап получения свидетельств — основному исполнителю прочитать опубликованный архив обратно из GitHub и сравнить его байты с архивом таблицы 1. До этого данное заключение не является утверждением о завершённой доставке публичного архива или всей задачи.

## 8. Термины и сокращения

- **CLI** — Command-Line Interface, интерфейс командной строки.
- **COM** — Component Object Model, компонентная объектная модель Windows.
- **CRC** — Cyclic Redundancy Check, контрольная сумма, используемая здесь для проверки целостности записей ZIP.
- **JSON** — JavaScript Object Notation, текстовый формат структурированных данных.
- **SHA-256** — криптографический алгоритм вычисления контрольной суммы содержимого.
- **SID** — Security Identifier, идентификатор безопасности Windows.
- **PR** — Pull Request, запрос на включение изменений.
- **HEAD** — выбранный коммит рабочего дерева Git; **Git blob** — идентификатор точных байтов файла в объектной модели Git.
- **PASS / FAIL / SKIP** — успешное завершение, отказ и пропуск проверки соответственно.
- **stdout / stderr** — стандартный поток вывода и стандартный поток ошибок процесса.
