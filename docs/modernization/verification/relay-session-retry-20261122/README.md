## 1. Причина и минимальные изменения

Relay связывает стандартные потоки клиента с сервером Model Context Protocol (MCP) по HTTP — протоколу передачи гипертекста. В опубликованной голове `f11cd6cf1f4031f3a2d7db60fb5d4edf19d0a4da` заголовок сессии становился доступен до полного принятия ответа `initialize`, а согласованная версия не передавалась дальше. GET после закрытия потока всегда ждал одну секунду, игнорируя серверное поле `retry`.

Инкремент исправляет эти границы и сохраняет ранее опубликованные ограничения ответа, ошибки разбора и вывода, а также запрет повторной отправки POST с неизвестным результатом. Он не добавляет зависимости, новый транспортный каркас или публичный программный интерфейс.

## 2. Проверенный контракт

### Версия, идентификатор и успешный вывод

Версия берётся только из соответствующего успешного `InitializeResult`. Проверяются `jsonrpc: "2.0"`, пустой или отсутствующий `method`, объект `result`, отличный от `null`, отсутствие поля `error` и совпадение идентификатора запроса. `protocolVersion` должен быть строкой с допустимой календарной датой `YYYY-MM-DD`, проверяемой через `time.Parse(time.DateOnly, ...)`. Совместимость версий выбирают конечные участники MCP; Relay не вводит отдельный список разрешённых дат [1, 2].

ID — идентификаторы сообщений JSON-RPC, протокола удалённого вызова процедур — сравниваются по значению JSON, текстового формата структурированных данных. Строки декодируются, поэтому эквивалентное экранирование совпадает. Числовой ID должен иметь целочисленное значение [3]: соседние числа больше `2^53` различаются, эквивалентные десятичные и экспоненциальные записи совпадают. `null`, отсутствие ID и ненулевые дробные значения не устанавливают соответствие; числовой ноль допустим.

Числа не округляются через `float64`. Локальный алгоритм нормализует коэффициент и десятичный показатель степени, корректируя последний переносом или заёмом по цифрам. Он не строит степень десяти и не разбирает гигантский показатель библиотекой больших целых. Поправка ограничена допустимым размером сообщения, число проходов по входу ограничено. Тесты включают длинные показатели около существующих пределов входа и ответа; это функциональная проверка, не измерение процессорного времени.

Подходящий ответ проходит прежние проверки размера, JSON и кодировки UTF-8. В stdout, стандартный поток вывода, должны успешно записаться сообщение и завершающий перевод строки. Затем одна блокировка публикует сессию и версию вместе. До этого GET не стартует по одному HTTP-заголовку. Ошибочный, пустой или несоответствующий ответ не обучает версии; поздний заголовок у `notifications/initialized` не обходит эту границу.

Следующие POST, GET и DELETE несут `MCP-Protocol-Version`. При отсутствии идентификатора сессии выученная версия всё равно передаётся следующими POST. Завершение `Run` очищает оба поля. Это наблюдение согласования, а не полная проверка всех схем MCP.

### Очистка ещё не принятой сессии

Если сервер уже выдал идентификатор, но ответ не принят клиентом, его сохраняет локально тот же POST-обработчик. При выходе он сначала закрывает тело ответа, затем при необходимости выполняет DELETE с независимым двухсекундным контекстом. Версия, известная только для этой очистки, не становится видимой обычным запросам. `Run` ждёт обработчик; отдельного неотслеживаемого владельца очистки нет. Исходная ошибка stdout сохраняется, ошибки DELETE журналируются по прежнему контракту.

### Серверный интервал и курсор

Server-Sent Events (SSE) — поток событий от сервера. Его `retry` принимается как непустая последовательность ASCII-цифр после удаления ровно одного пробела за двоеточием [4]. Ноль и ведущие нули допустимы; лишние пробелы, знаки, дроби и другие символы сохраняют прежний интервал. Начальное значение остаётся одной секундой.

Интервал меняется при чтении поля, включая конец потока без пустой строки, и сохраняется между повторными GET. Ожидание прерывается отменой контекста. Курсор `Last-Event-ID` фиксируется отдельно, только на границе полностью принятого события. Ошибка разбора либо stdout остаётся конечной и не разрешает повтор; POST не воспроизводится.

Цифровое значение больше `9223372036854` миллисекунд не помещается в `time.Duration` и завершает GET явной ошибкой `SSE retry exceeds supported duration`. Оно не переполняется и не игнорируется с последующим слишком ранним запросом. Это объявленная граница реализации, отсутствующая в самой грамматике SSE.

## 6. Ревью и ограничения

Собственное ревью охватило требования, корректность, безопасность, совместимость и сложность: весь производственный путь, оба новых теста и механическую дельту остальных файлов. До заморозки устранены обход принятия сессии поздним заголовком, потеря очистки при ошибке stdout и риск дорогого разбора огромного показателя через большие целые. Последний был риском по чтению кода, а не измеренным инцидентом. Обязательных открытых замечаний в рассмотренной области не осталось; запись и точные привязки — [source-review.json](source-review.json).

Независимо прочитаны исходники и производные инструменты. Дельта форматирования перечитана; окончательные байты связаны с предформатным ревью. Исходные записи лежат в архиве: `relay/REVIEW-prequalification.md`, `qualification/relay-source-independent-review-preformat.json`, `relay/formatter-independent-review.json`, `reader/relay-runner-independent-review.json`. Это не заменяет внешнего ревью точного опубликованного коммита.

Остаются следующие границы:

- **#626:** пиковая и удерживаемая память, длительная нагрузка, распределения задержек, параллельность, отмена и потери у реальных потребителей. Один успешный функциональный сценарий их не закрывает.
- **Поток, начатый POST:** возобновление такого SSE-потока не реализовано. POST-обработчик не сохраняет его курсор и не открывает запрос продолжения. Сохранение курсора и повторное подключение реализованы только для основного GET; этот путь проверен новым профилем. Повтор исходного POST с неизвестным эффектом не разрешается.
- **Окружения и наборы:** отсутствуют результаты полного стандартного/тегированного набора, Linux и установленного продукта. Нативный планировщик, права, учётные данные и внешние квотные агенты в запусках не участвовали.
- **Владение и сроки:** двухсекундный DELETE требует транспорта, соблюдающего контекст. Произвольный чужой транспорт или заимствованный ввод/вывод принудительно не прерывается. Исполнитель ограничивает непосредственного ребёнка; доказанного ограничения всего дерева процессов нет. Отсутствие нативных операций основано на проверенных командах и входах, не на перехвате системных вызовов.
- **Область доказательства:** результат относится к зафиксированной композиции. Он не доказывает квалификацию всего текущего `master`, самостоятельной ветки или будущего объединения других PR. Внешнее ревью опубликованной головы остаётся отдельным условием.
