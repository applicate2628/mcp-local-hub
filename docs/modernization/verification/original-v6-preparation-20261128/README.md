# Подготовка v6 и публикация восстановленной истории: отдельные результаты

Этот пакет фиксирует пять независимых результатов: завершённую подготовку обычных helper-программ, завершённую подготовку двух external helpers, отказ подготовки Product v6, фактическую доступность документального commit в GitHub при **FAIL** исходной обёртки и неустановленную точную команду оставшейся проверки ожидаемого отказа. Подтверждение полного приёмочного прогона из этих результатов не следует.

<a id="product-v6"></a>
## 4. Product v6: сохранённый отказ

Первичные parent и execution фиксируют **FAIL / CLOSED**, общий exit 1 и 72.68212140002288 с [6]. Копирование закрытых кешей и исходных immutable artifacts завершилось с exit 0. Третья команда `issue-and-compile-original-private-inputs` завершилась с exit 1 за 1.111742899985984 с. Все три команды физически завершены, их исходные читатели присоединены, native handles и captures закрыты. Повторно проверены шесть capture-хешей и три записанные пары карт по 3544 pins.

Причина отказа в закрытом stderr: `build_private_inputs_v6.ps1:65`, сообщение **Concrete reviewed release version/date required**. В этом script проверка находится перед созданием независимой Source-копии и её сборкой. Дальнейшая выдача готовых private Product inputs этим запуском не подтверждена.

Исходный JSON bindings содержит `release_version="0.4.60"` и строку `release_build_date="2026-11-28T11:11:34Z"`. Строка соответствует требуемому формату и календарю. Фактический тип значения после PowerShell `ConvertFrom-Json` **здесь не подтверждён**: отдельный runtime DATA probe v7 при подготовке этого снимка ещё не был принят. Причина на уровне преобразования типа остаётся гипотезой до его собственного результата. Этот отказ не засчитан как исходная оставшаяся проверка ожидаемого отказа.

## 5. Публикация истории

Независимое чтение GitHub подтвердило commit [4] `5e95aab6d9765701ec6c49ddcecc6cde3293eb65`, tree `a6b284f8634c1595880421ea02371e2462d93854`, parent `513898c2029fb29dd7f15ce3598f518e42666f7b`. В нём 16 путей: пакет исторических 717 сценариев, пакет двух восстановленных commit-объектов и patch-файлов, а также добавочный раздел канонического отчёта. Список Git blob-идентификаторов сохранён в [2]. Это публикация доказательств; включение двух исходных commit в кодовую ветку PR #666 здесь не утверждается.

У первоначальной команды `head` состояние `complete`. У `native-history-publication` установленный gate вернул native exit 0, но в первоначальном receipt остались `quiescence_state=unknown`, `original_readers_joined=false`, превышение интервала cleanup и `captures_measured=false`. Поэтому статус всей обёртки — **FAIL**, внешний процесс завершился с exit 1. Этот результат сохраняется буквально.

Отдельный поздний receipt фиксирует завершение обоих исходных читателей, EOF и закрытие pipe/capture, получение native exit 0, отсутствие активных процессов в job и закрытые handles. При этом он явно сохраняет `original_command_states_unchanged=true`, `qualification_passed=false`, `capture_access_issued=false` и `new_commands_permitted=false`. Поздний **CLOSED** не меняет исходную квалификацию. Запрещённые captures публикации не читались и не хешировались; размеры и остальные доступные поля приведены только как данные JSON receipts. Текст native gate не восстанавливался из закрытых для доступа captures, а правила gate и approvals не менялись.

<a id="remaining-refusal"></a>
## 6. Оставшаяся проверка отказа

[3] фиксирует ограниченную проверку 25 известных исходных input-файлов за 26–27 ноября и публичного контекста существующих PR. Каждый первичный input указан через путь относительно роли, размер и SHA-256. Изученный `execute_gate` выполняет build → vet → default tests → state-path-env tests → finalization; отдельной команды отрицательного контроля после двух успешных режимов в нём не найдено.

Маркер `literal-prior-build-refusal-v1` обозначает отказ при неприемлемом предшествующем завершении до нового scope. Он не задаёт самостоятельно согласованную оставшуюся проверку. Недавний DWORD prestart refusal, восстановленные namespace/prechild тесты и уже выполненный старый отрицательный oracle PR #666 также не подставляются вместо неё. Наблюдения `ResourcesFinalized=false` / native failed-owner late receive сами по себе не дают точного имени теста или argv.

Следовательно, остаются **NOT_RUN / UNRESOLVED**. Это ограниченный отрицательный результат поиска, а не утверждение, что нужной записи нигде не существует. Необходима исходная точная команда с ожидаемым результатом и областью приёмки либо отдельно рассмотренное изменение требования. Новая проверка вместо исходной не придумана.
