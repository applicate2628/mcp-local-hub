# Reader #627: ограниченная инвентаризация имеющихся зависимостей

**Результат: новых кандидатов для 11 недостающих пакетов не найдено в описанной области поиска.** Это не доказательство их отсутствия на всём компьютере. Reader, Cargo, сборка, тесты и внешние поставщики не запускались; зависимости не загружались и не устанавливались.

## 1. Точный вход

Список согласован с `consumer_rust_review` и независимо прочитан из `Cargo.lock` исходного снимка #627 [`b827398ef127a1556b7b2bdcdcec7fe03fa6651d`](https://github.com/applicate2628/mcp-local-hub/blob/b827398ef127a1556b7b2bdcdcec7fe03fa6651d/experiments/rust-anchored-read/Cargo.lock). Перед обходом вычислен ожидаемый Git blob `bf195e14a3b725f5a64c8e577de56e2b605018a3`; SHA-256 файла — `6cd7b98899c6afe742b1ca177e947b360e78b2662c4b6b7778eb1e32e619e026`.

Искомые пары имени и версии: `block-buffer 0.10.4`, `cfg-if 1.0.4`, `cpufeatures 0.2.17`, `crypto-common 0.1.7`, `digest 0.10.7`, `generic-array 0.14.7`, `libc 0.2.186`, `sha2 0.10.9`, `typenum 1.20.1`, `version_check 0.9.5`, `zeroize 1.9.0`. Все ожидаемые контрольные суммы архива из lock-файла сохранены в [машинной записи](reader627-dependency-inventory.json).

## 2. Область и фактический обход

Сначала прочитан верхний уровень `<WORK_ROOT>`: найдено 11 каталогов с `rust` в имени; отдельных верхних каталогов с `reader` или `anchor` не обнаружено. Только эти 11 каталогов затем стали корнями обхода. Не выполнялся поиск по всему D, по другим проектам или по C. Ранее проверенный другим исполнителем путь Cargo cache на C повторно не читался.

Использован существующий Python с `-I -B`, рабочий каталог `<WORK_ROOT>`. Режим изоляции не включает пользовательские модули, запись Python-кэша отключена. Код вызывает только чтение файлов и метаданных: `os.scandir`, `lstat`, `DirEntry.stat(follow_symlinks=False)`; атрибут Windows `ReparsePoint` (`0x400`) и символические ссылки отвергаются. Корневые пути и компоненты пути lock-файла проверены тем же способом. Имена `.git`, `target`, `targets`, `runtime`, `tmp`, `temp`, `trash`, `node_modules`, `gocache`, `gomodcache`, `.venv`, `venv` исключены из спуска.

Ограничения: не глубже пяти уровней каталогов от каждого корня, до 3 000 записей на корень, до 25 000 записей всего, до 25 секунд. Кандидатами считались точные архивы `name-version.crate` и каталоги `name`/`name-version`; отдельно фиксировались найденные обычные архивы. Каталог по имени не означал бы квалифицированные байты пакета.

## 3. Воспроизводимость и точные ограничения

Сохранены [программа обхода](reader627-dependency-inventory.py) и [результат](reader627-dependency-inventory.json). SHA-256 программы: `ad6875e3e6957eb57faa7fe3e3c4908e512d83bcd0c371b6fc8be7d44fe2609c`; результата: `8dd15dbe9b1189a656c5f46f4118361bfceae908bdb9ba2e31c9131e86597afc`.

Наблюдение началось 21.11.2026 в 09:20:26 UTC, то есть 12:20:26 МСК. Поиск не был атомарным снимком файловой системы. Не читались содержимое произвольно названных вложенных архивов, более глубокие каталоги и остатки четырёх корней после предела записей. На <REMOTE_DEVICE> программа не записывала файлы.

Для подачи программы два предварительных интерактивных сеанса Python не приняли рабочий ввод: первый штатно завершён командой `exit()`, для второго инструментом инициировано завершение собственной сессии, последующее чтение вернуло отсутствие этой сессии. После этого выполнен один описанный выше конечный процесс инвентаризации. Это техническая история запуска инвентаризации; она не является утверждением о завершении произвольного дерева процессов. Продуктовые процессы этой работой не завершались.
