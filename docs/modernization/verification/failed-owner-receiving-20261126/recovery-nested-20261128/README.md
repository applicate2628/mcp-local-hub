# B: точные адреса недостающих входов и проверка вложенных архивов

**28 ноября 2026 года, МСК. Блокер B остаётся открытым.** Установлены точные исторические пути receiver (приёмщика входов), его preimage и канонического manifest (описи состава); для manifest дополнительно установлен размер **1 348 байт**. Содержимое receiver, preimage, patch и manifest с требуемыми полными SHA-256 не восстановлено. Полная идентичность template9315 и каноническая привязка 12 уже полученных Go-файлов также остаются открытыми.

Этот пакет продолжает [предыдущий ограниченный поиск](../recovery-search-20261128/README.md). Он сохраняет новые первичные ссылки, данные разбора ещё не исследованных вложений и результаты собственного анализатора. Продуктовая квалификация, результаты Source52, P1 и прежние FAIL/UNKNOWN/HOLD сохраняют свои области.

## 2. Сохранённая контрольная точка S16

Архив `mcp-residual-ad-checkpoint-363b-v1.zip` имеет **37455817 B**, SHA-256 `912e9cff2f5105364aa664c11e5ba20c88048b78111eab99f6e3334f820642d0`. Его 682 ZIP-записи содержат 77673369 распакованных байт. Все **681 записи** внутреннего `CHECKPOINT-MANIFEST.json` сверены по длине и SHA-256; сам manifest исключён из собственного списка. Проверка CRC выполнена при полном чтении членов ZIP. [5]

Этот SHA отсутствует именно в переданном списке ранее проверенных native archive hashes. Это сравнение с конкретной областью предыдущего поиска, не утверждение, что архив никогда ранее не был известен. Его историческая идентичность S16 совпала. Поле сравнения в публикуемой сводке уточняет эту границу.

Разбор как данных обработал **603 уникальных объекта**, 53 Python AST (абстрактных синтаксических дерева), 10493 строковых/байтовых константы, 143 base64-декодирования и 12 сжатых потоков; счётчик раскрытых данных составил 165038542 B при пределе 256 MiB. Очередь исчерпана, совпадений четырёх полных target SHA-256 нет. Исходные программы из архива не импортировались и не исполнялись.

Два первоначальных XZ EOF объяснены сырым LF внутри явно обозначенного base64 в сохранённом `poll` text. Удаление только ASCII-пробелов/переносов в этом envelope воспроизвело заявленные **6619665 B / e3de50e5…** и **7313595 B / 977cf98a…**, с полным совпадением SHA-256, EOF и отсутствием остатка. Те же данные уже присутствовали в неперенесённых `result/content` копиях. Исходные ошибки и последующее объяснение сохранены отдельно. [6]

Поиск сохранённых файлов был ограничен шестью запросами. Один первоначальный поиск имел неполученное продолжение; ранжированная выдача не является полной описью всех сохранённых файлов. Произвольные вычисляемые или обфусцированные payload, неизвестное объединение transport chunks и исторические версии не покрыты.

Входы выбраны по сохранённой описи, с полными pins внешних контейнеров; общий поиск Git objects и принятые POSIX-тесты не повторялись. [7]

## 4. Цепочка current5e и граница manifest

Сохранённый `b-go-main-hold-current5e-stage-v1.py` содержит literal XZ+base64: **3228 B / 7950f243… → JSON 10620 B / c2d458d1…**, 11 строк точных byte edits. Явно перечислены шесть Go fixture-файлов, `go.mod`, plan, launcher, runner и fixture manifest. Декодированное описание правок прочитано как данные; его операции записи не запускались. Указанные 10620 B / c2d458d1… относятся к точному оригиналу. Публичный JSON содержит только роль-токенизированную проекцию локальных путей; его отдельный hash и преобразование записаны в source-evidence.json. Применять эту проекцию как точные byte edits нельзя. [8]

Fixture manifest преобразуется 15 правками из **13163 B / 77ab1fac…** в **13691 B / 079e7c6f…**. Его schema — `named-owner-go-branch-fixtures-v1`; synthetic methods, `production_run_executed=false` и `production_physical_receiver_executed=false` сохранены. Это отдельный документ от искомого **1348 B / e74ff2ed…**.

Stage-текст доступен через текстовое чтение с восстановленным завершающим LF. Его локальный hash квалифицирует именно эту DATA-копию; полные native bytes stage не объявляются полученными. Manifest и runner отдельно совпали с ранее опубликованными полными pins. Main5e и physical2b уже восстановлены, повторный поиск их как утраченных файлов не требуется. Полный состав controller нельзя вывести из совпадения только этих двух hashes или из счётчиков других review-пакетов.

Все **23 исходные команды / 46 читателей вывода** восьми подготовительных native-маршрутов закрыты. Каждый original process получен, дерево пусто, native handles закрыты, исходные readers присоединены; восемь внешних контроллеров получены с закрытыми captures. Это получение ресурсов инструментов восстановления, а не приёмка production controller. [9]

Размеры, SHA-256, inode/device, modification time и атрибуты не ослаблены. Сохранены обе точные правки анализатора и focused regression из девяти вариантов. Последующее изменение base64-политики проверено отдельным чтением одной строки; полный набор продуктовых тестов из-за этих DATA-инструментов не назначался.

RDC filename-поиск дал девять ответов с предупреждением о трёхсекундном ограничении и один недоступный search session. Более длинный параметр не снял фактическую отсечку. Нативный `rg` также не завершил обход до deadline. Прямые ENOENT-пробы проверяют только указанные пути. Эти результаты не доказывают отсутствия файлов во всех Windows-корнях. Отдельная неполученная попытка чтения большого текстового транспорта не используется как источник байтов; исходные native отчёты сохранены, публикация копирует их по точным pins.

## 6. Применимость A–D и следующий переход

Source52 `52a2d9ef…` сохраняет точную выбранную композицию #660+#669, 464 адресных PASS и POSIX **3 корня + 7 подтестов в каждом режиме**. Эти тесты не повторялись. Прежние #668 **5 корней + 15 подтестов** относятся к другому Source. Native autostart QA и установленный liveness getter остаются отдельными принятыми границами. [10–12]

Отчёт размещается поверх нового head, сохраняя параллельные изменения; прежние PASS Source52 не квалифицируют новую композицию.

Срез описания #664 от **28 ноября, 19:28:45 МСК** сообщает более поздний Source59f: default FAIL с UNKNOWN original receiver, API FAIL/CLOSED до тестов, CLI UNKNOWN/HOLD и tagged NOT_RUN. Настоящий пакет не читает UNKNOWN captures, не использует его cache и не переименовывает эти исходы. Исторические Source727/Source74e сохраняются.

Точная капсула consumer Source C `3ebe335a…`, tree `67c13b8f…`, уже опубликована в #631 на `c80fd6b4…`. Устаревшее ожидание её публикации исправляется в общем плане/описании PR; это не новый runtime или вывод о производительности. Go остаётся основным путём, Rust — экспериментом. Семь нулевых RPC-измерений C отделены от семи escaped-child counts Source59f. [13]

**Следующий переход B:** получить точный receiver либо его preimage+patch, template с полной идентичностью и canonical manifest; затем проверить его связь со всеми 12 восстановленными Go-файлами.
