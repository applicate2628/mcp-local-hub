## 3. Транспортные контейнеры и архивы

Из сохранённых транспортных контейнеров проверены **312 декодированных файловых объектов**: 238 + 38 + 36. Проверены размеры и SHA-256 вложенных данных; программы из них не запускались. Это записи, включая вложенные и повторные значения, а не количество уникальных файлов [3–5].

Для обхода JSON действует предел глубины; произвольные вложенные архивы и неизвестные кодировки не исследовались. Значение compressed_total = 268435456 байт — порог перед следующим архивом. В v1 уже принятый архив довёл фактическое чтение до **268496235 байт**, то есть на **60779 байт** выше порога. Порог времени 50 секунд проверяется перед архивами и при переходе к ZIP/TAR-элементам; текущую операцию чтения или декодирования он не прерывает. Это не строгий предел длительности отдельной операции. Данные исходных отчётов не исправлялись задним числом; семантика уточнена в [схеме](archive-evidence-schema-v1.md).

## 4. Завершение исходных ресурсов и UNKNOWN

Завершение команды поиска и полнота поиска — разные свойства. PASS обвязки означает успешное завершение её операции в указанной области; ошибки чтения и пропуски внутри отчёта остаются видимыми.

**Таблица 4 — отдельные области закрытия.** Читатель получает stdout/stderr исходного процесса; CLOSED требует получения окончания, закрытия pipe/capture, присоединения читателя и завершения исходного владельца.

|---|---:|---|
| Восемь включённых Git-запусков | 23 / 46 | CLOSED; три указанных native FAIL сохранены |
| Финализатор Git-отчёта | 2 / 4 | PASS/CLOSED, receipt 4d0cbc8407bd5625aca03ede34c57eba95c31256ad66b87e0d8f0e16cf9c5e88 |
| Шесть перечисленных архивных запусков | 12 / 24 | CLOSED; ограничения и ошибки данных сохранены |
| Подготовка публичных архивных представлений | 2 / 4 | PASS/CLOSED, receipt dd1e9bc0351113dad216c84fd67843db6d333fe977d06790cba12e506fc075a0 |
| Собственная структурная проверка root | 2 / 4 | PASS/CLOSED, receipt fcea5d822c46cdfa4e9207a4d6e7a5bd6a0ceeb7d148a522d31c4ebf38b9003e |

**Ранняя архивная попытка остаётся terminal UNKNOWN / native closure UNKNOWN.** Зависимый launcher был запущен до завершения ожидающего tool-write. Для этого launcher нет принятой durable native completion receipt. Отсутствие каталога запуска и ответ No session не доказывают завершения. Эта попытка исключена из таблицы 4; PID не используется как достаточная идентичность для завершения процесса. Исходные сведения сохранены в archive-recovery-summary-v2.json.

## 5. Сохранность, преобразования и применимость

Полные Git-отчёт и 5985 строк readset сохранены. Архивные JSON сохраняют все кандидатные записи, размеры, SHA-256, результаты совпадений, ошибки, пропуски, ограничения и очередь. Абсолютные машинные корни заменены логическими токенами. [Manifest преобразования](archive-transformation-manifest-v1.json) связывает исходные и опубликованные байты, отпечатки префиксов и число замен. Предварительная широкая опись явно сокращена до 266 выбранных путей; точные количества опущенных предварительных строк и SHA-256 полной описи сохранены.

Root повторно прочитал сохранённые данные как JSON, проверил исходные и публичные SHA-256 всех шести пар, точное структурное равенство четырёх полных JSON после объявленной замены префиксов, 13635 + 1 кандидатных записей, отсутствие совпадений, пустую итоговую очередь, отдельный UNKNOWN и 5985 строк Git readset. Это проверка сохранности данных, не повторный поиск и не тест продукта. [Структурный результат](structural-verification.json) относится к пакету до дополнительного пояснения бюджетов в schema; JSON поисковых данных остались точными. Окончательные файлы и SHA-256 перечислены в [artifact-bindings.json](artifact-bindings.json).

Собственный review root дополнен независимым чтением участника next_functional_boundary, который не писал архивные отчёты. Выполнено только внутреннее делегирование; внешние модели и квотное ревью не запускались, профиль модели runtime не сообщён. При публикации проверяется только дельта свидетельств и планирования; общие функциональные gates A–D остаются открытыми.

Три raw Git batch-файла являются транспортными копиями объёмом 203711168 байт. На момент фиксации поискового отчёта они сохранены вне trash. Перенос допустим только после обратного чтения публикации и подтверждения доступности исходных Git objects. Последующий факт переноса должен иметь отдельную квитанцию; первоначальный отчёт не переписывается. Уникальные исходники, исходные ошибки и неопределённые данные не являются мусором.

## 7. Источники и обозначения

1. [Git recovery report](git-recovery-report.json): доступные stores, инвентари, границы, исходные отказы и квитанции.
2. [Git readset](git-recovery-readset.jsonl): каждый прочитанный Git object ID, SHA-256, размер и доступные stores.
3. [Archive summary](archive-recovery-summary-v2.json) и [selection](archive-selection-v1.json): область, исключения, очередь и UNKNOWN.
4. [Archive v1](archive-content-v1.json) и [v2](archive-content-v2.json): полные записи кандидатов.
5. [Transport v1](transport-inputs-v1.json) и [v2](transport-inputs-v2.json): сохранённые контейнеры и декодированные входы.
6. [Transformation manifest](archive-transformation-manifest-v1.json), [schema](archive-evidence-schema-v1.md), [structural verification](structural-verification.json) и [final bindings](artifact-bindings.json).

Receiver — код приёма и проверки входов; preimage — точные байты до patch; manifest — каноническая опись и привязка состава. SHA-256 — контрольная сумма исходных байтов; Git SHA-1 — идентификатор Git blob с заголовком его типа и размера. МиБ = 1048576 байт. POSIX — семейство интерфейсов Unix; WSL — Windows Subsystem for Linux. EOF — окончание потока. PASS/FAIL — результат проверки в объявленной области; CLOSED — полученное завершение исходных ресурсов; UNKNOWN/HOLD — отсутствующий доказанный исход либо удерживаемое незавершённое состояние. Ни один из этих статусов не переносится автоматически на другую Source.
