**Результат:** повтор трёх POSIX-корней Source52 снят с плана. Полные исходники владельца с late-gate API найдены; подготовлен воспроизводимый наблюдаемый набор из 12 Go-файлов. Это продолжение #664; #668 остаётся владельцем исправления Go reader. Производственный код и исторические результаты этим документальным обновлением не меняются.

- Это успешный обычный маршрут. Прерванный Windows→WSL timeout/HOLD и позднее завершение исходного владельца остаются открытыми.

- Ошибки close вводятся тестовой точкой подстановки после реальных файловых операций. Настоящие сочетания ошибок метаданных/закрытия операционной системы остаются непроверенными.
- Прежние 5 корней/15 подтестов на `1b7655ae…` [сохраняют отдельную область][3]. Их нельзя сложить с таблицей 1 в один запуск на Source52.
- Дополнительные POSIX-сценарии, полные наборы, Unix/ARM64 и внешнее ревью актуальных коммитов остаются в плане.

## 2. Восстановленные исходники контроллера

Полные main5e и physical2b были восстановлены ранее; повторный глобальный поиск main не выполнялся. По прямому импорту найден соседний пакет `canonicalcaseowner`: шесть полных файлов, 84654 байта. Их содержимое дважды прочитано, сохранено как DATA и сверено по размерам и SHA-256.

Наблюдаемый набор теперь содержит пять production-файлов controller, один controller test и шесть owner-файлов. [Опись восстановленного набора][4] задаёт все 12 путей, размеры, хеши, исходные хеши и точную замену namespace. Шесть файлов совпадают с уже опубликованным кандидатом и повторно не копируются; сохранены только шесть отличающихся файлов.

**Таблица 3. Значимые восстановленные связи.**

| Восстановленный исходник | Статически установленная связь |
|---|---|
| controller `cases_windows.go` | Передаёт `Spec.TestOnlyLateGate`. |
| owner `owner_windows_amd64.go` | Определяет это поле, связывает gate после `retain(o)` до `prepare(ctx)`, удерживает исходный `Run` перед возвратом. |

[Старый опубликованный owner][5] не содержит поля `Spec.TestOnlyLateGate` и этих методов. Поэтому соединение current main/cases/gate со старым owner было бы статически несогласованным. Найденные полные owner-исходники закрывают этот конкретный пробел. Это не утверждение о результатах компиляции или исполнения нового набора.

Для четырёх controller-файлов выполнена единственная замена import namespace `b-native-next-52a2d-v1` → `__CANONICAL_EXTERNAL_STAGE__`; остальные байты не менялись. Полученные main `5e076834…` (24226 B) и physical `2b36397b…` (11633 B) совпадают с известными current pins. Хеши остальных нормализованных файлов остаются кандидатами до сопоставления с исходным canonical manifest.

Сохранённый owner envelope имеет SHA-256 `f7a93089af086bd57cefd6281e983c99ce39384e1181cb3412fd4cf830cf55e2`. Его шесть строк содержат полные корректные bytes/length/hash; агрегат `total_source_bytes` был записан как `null` из-за ошибки суммирования метаданных. Повторное чтение дало 84654 B. Опись [4] фиксирует оба факта; исходная квитанция не переписана.

Отдельный current5e manifest `079e7c6f…` описывает fixture-файлы и явно содержит `production_physical_receiver_executed=false`; `session.receiveFailedPhysical` и `session.publishTestOnlyLateGate` там синтетические. Он не заменяет недостающий manifest текущего production-контроллера.

## 3. Границы завершённого поиска

Продолжена только оставшаяся очередь D v3; E повторно глобально не сканировался. В цепочке v1 → v3 → v4 перечислены 191479 каталогов и 1918745 обычных файлов; хешированы 1390 выбранных кандидатов. В v4: 146594 каталога, 1332357 файлов, 803 кандидата, 2573008 прочитанных байт; очередь исчерпана за 85,043 с.

Отчёт v4: 1231070 B, SHA-256 `6b99572bf1e1bd5af469e0a1bbc2ac7d01fce4ea76436c5930850f55dc947327`; скрипт: `6836f63dcaa44a29c7320732a65b0b58daacb1f05df0e6d38cf7bddb3aeca97d`; предыдущий v3: `f1550f1007c590c7900f6c1cb11c3c2d32963721520aa5c79a89e7c8d65a12f7`.

Точных target-хешей и префикса 9315 среди кандидатов нет. Пустая очередь не означает полного чтения всех данных: сохранены пять отказов доступа к старым тестовым каталогам, шесть пропущенных reparse points и 937 каталогов списка исключений. В v4 3158 архивов только перечислены, их содержимое не исследовалось; лимит одного выбранного файла — 2 MiB. История Git, исключённые кэши и произвольные вложенные payloads этим поиском не охвачены.

Отдельное адресное чтение owner-каталога было основано на прямом импорте из уже найденного controller. Оно обнаружило исходники, не входившие в маски поиска receiver. Отрицательный результат filename/hash-поиска не выдаётся за доказательство утраты данных.

## 4. Проверки и следующий шаг

Выполнены собственная сверка оригиналов и независимые проверки POSIX, source-chain и owner API; прочитаны относящиеся к задаче правила репозитория и навыки архитектуры/контрактов, поиска причины, проверки источников и упрощения. Состав документационного изменения: корректировка действующего плана, этот отчёт, машинная опись и шесть текстовых копий восстановленных Go-файлов. Исторические source manifests и исходники прежнего кандидата сохранены.

Новые Go-сборки, native-тесты, полные API/CLI, установки, изменения Task Scheduler, CI и внешние квотные модели в этом восстановлении не запускались. При контрольном чтении Git HEAD и чистого status обе команды завершились с кодом 0; запрос отсутствующего `core.hooksPath` вернул штатный код 1, который общий диагностический конфиг ошибочно ожидал как 0. Диагностическая попытка сохраняет FAIL; все три исходные команды и шесть читателей закрыты. Это не отказ тестов продукта.

Следующий шаг B: получить недостающие точные входы таблицы 4 и связать их опись с 12 восстановленными Go-файлами. Затем завершить Test-map/TestSource, свежие Git controls, привязку и сборку P2, образы/private inputs; принять исходный процесс, дерево, поздний возврат и readers; только после этого выполнять обе полные команды. Новый глобальный поиск main5e и повтор принятой POSIX-выборки не назначаются.

Полный остаток A–D ведётся в [едином плане][6]. Старые V1/FAIL/UNKNOWN/HOLD остаются привязанными к своим исходникам.

**Происхождение работы:** основной исполнитель — восстановление и интеграция; два отдельных внутренних участника — проверка POSIX и controller contracts, ещё один — ограниченный поиск. Запрошенный и фактический путь — встроенная совместная работа ChatGPT и чтение через Remote Desktop Commander; внешний provider не запускался; отдельная идентичность модели/профиля runtime не предоставлена. Это внутренние проверки, не требуемое внешнее ревью коммитов.

## 6. Термины и сокращения

- **Receiver** — код получения и проверки входов; его полный текст является отдельным входом квалификации.
- **Owner** — объект, который сохраняет исходные ресурсы процесса и отвечает за их завершение.
- **Gate** — тестовая точка управляемого ожидания исходного вызова или читателя.
- **Manifest / опись** — полный список входных файлов с их точными идентичностями.
- **Source / TestSource / ProductSource** — конкретные наборы исходников с отдельно заданной ролью.
- **EOF** — подтверждённый конец потока; **WSL** — Windows Subsystem for Linux; **POSIX** — семейство интерфейсов Unix.
- **API** — программный интерфейс; **CLI** — интерфейс командной строки; **SHA-256** — криптографическая контрольная сумма.
- **PASS / FAIL / UNKNOWN / HOLD / NOT_RUN** — успех / отказ / неизвестный результат / удержание / не исполнено в указанной области.
