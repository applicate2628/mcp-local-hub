# Полное сохранение потоков закрытого full-v6

## Ревизия представления v2

Canonical diagnostics для отклонённого commit 264a0601b7d027652c12ec88ae4debd6c3bfb69f выделили 9 точных областей в трёх файлах: 4 префикса тестового пути и 5 парольных test-sentinel assignments. Все совпали с byte-pinned исходными фикстурами. Два runtime templates теперь содержат 8 дополнительных role markers; девятый marker находится в source-fixture-provenance.json. Активный renderer требует **24 роли** (22 прежние и 2 fixture roles). Original333 bytes/SHA, capture-index, источники FAIL/CLOSED и все runtime/native numeric records неизменны.

См. [точную безопасную диагностику](canonical-finding-locations.json), [план и публичные source pins](fixture-template-v2-plan.json), [DATA-преобразователь](prepare_fixture_template_v2.py) и [его квитанцию](fixture-template-v2-receipt.json). Source727 commit ref отсутствует на GitHub; каждый указанный exact source Git blob публично получен и проверен отдельно. Для исторического toggle требуется старый blob, а не изменённый текущий файл. Значения извлекаются как DATA из литералов закреплённых строк, без исполнения Go-кода. Новая private roles.json формируется отдельным explicit output; её нельзя публиковать. Для повторного получения двух fixture roles достаточны опубликованные blob pins и selector rules, исходные 22 operator roles по-прежнему предоставляются оператором.

Ранее замороженный v1 не изменялся. Его authored source-fixture-provenance.json также восстанавливается побайтно одной обратной заменой нового fixture marker; исходный SHA/размер и region закреплены в плане. Исторические данные проверок v1 далее сохранены как история. Новый scanner PASS не заявлен; native publication gate остаётся обязательным. Никакие код, policy, approval records, тестовые таймауты или критерии closure не изменены.

## 1. Результат и границы

Этот пакет закрывает побайтное сохранение всех **566 stdout/stderr captures от 283 команд** исторического прогона Source **727d66753814dc218e26d699e57402db2d13190a**. Его исходный результат остаётся **FAIL/CLOSED**: работа исходных процессов и потоков чтения завершена, а обязательная полная квалификация не пройдена.

Основные выводы, подробности ошибок, инвентарь проверок и первичные root receipts уже опубликованы в [original-full-v6-failure-20261128](../original-full-v6-failure-20261128/README.md). Отдельная закрытая API-проверка сохранена в [closed-api-failure-20261128](../closed-api-failure-20261128/README.md). Здесь сохранены оставшиеся байты и полное соответствие оригинальных потоков. Новый запуск продукта или тестов при подготовке этого пакета не выполнялся.

Исторические полные команды:

~~~text
go build ./... && go vet ./... && go test -count=1 -timeout 5m ./...
go test -tags=test_state_path_env -count=1 -timeout 5m ./internal/api/ ./internal/cli/
~~~

Полный default-инвентарь пакетов был получен для 64/64 invocations. В tagged-режиме получен API, а CLI не был запущен из-за сохранённой ошибки компиляции. Исторические 14 migration roots и два canonical-environment roots не получают PASS от этого пакета. Более старые FAIL/UNKNOWN, включая old full-v8, сохраняют свои прежние статусы. Пакет не переносит результаты между Source727 и последующими Source revisions.

## 4. Формат публикации

[Source bindings](source-bindings.json) задают каждый новый оригинал, его размер/SHA, опубликованный файл и обратимые преобразования. Обычные данные сохраняются точными байтами. В payload templates вместо host-specific путей и native owner SID стоят явные **role markers**. Оператор предоставляет оригинальные значения отдельно; пакет не содержит скрытого или закодированного значения пути.

Для JSON допускаются буквальная запись, удвоенные backslashes и четыре backslashes для вложенной строки JSON. Последний случай нужен для исходных test2json событий, внутри которых уже находился JSON-вывод. Это явное преобразование представления одной роли. Все восстановленные файлы обязаны совпасть с исходными SHA-256.

Часть ролей обозначает **synthetic test fixtures**. В версии v2 два дополнительных явных маркера заменяют исходный GUI home-prefix fixture и парольный diagnostic sentinel. Их значения не опубликованы в этом пакете: они восстанавливаются из точных публичных Git blobs по [плану и source provenance](fixture-template-v2-plan.json). Это источник фикстур, а не разрешение scanner. Native PID и handles не заменяются ролями.

Оригинальный вывод списка Source paths использовал разделитель **NUL, байт 0x00**. Его 3509 относительных имён опубликованы как читаемые LF-строки. Единственное правило восстановления — заменить каждый LF на NUL. Оба исходных captures имеют 160859 bytes и SHA **30c87a0defe033ff73447160b4c05e45e3c985b9c851aed52284bb59a393f27f**. Независимое построение такого списка из уже публичной Source map дало этот точный SHA. Обратный преобразователь также проверяет число записей и чистые относительные пути.

Файл **.gitattributes** содержит **`* -text`**, чтобы Git не менял CR/LF и контрольные байты при публикации.

## 5. Восстановление и проверка

Сначала восстановите два предыдущих пакета их собственными **reconstruct_sources.py** и соответствующими operator role values. Затем восстановите новые 333 оригинала этим пакетом. Все output directories должны быть новыми и отсутствующими. Пример использует явные переменные оператора:

~~~text
python ../original-full-v6-failure-20261128/reconstruct_sources.py --roles-json "$FullRoles" --output "$FullData"
python ../closed-api-failure-20261128/reconstruct_sources.py --roles-json "$ApiRoles" --output "$ApiData"
python reconstruct_sources.py --roles-json "$CaptureRoles" --output "$CaptureData"
python verify_all_captures.py --new-root "$CaptureData" --prior-full-root "$FullData" --prior-api-root "$ApiData" --receipt "$NewDataReceipt"
~~~

**reconstruct_sources.py** проверяет все опубликованные и восстановленные хеши до создания нового output directory. Он не исполняет сохранённые source files и не импортирует runtime code.

**verify_all_captures.py** читает только восстановленные данные. Он проверяет 65 receipts, все 283 записи команд, исходные признаки physical closure, 566 привязок потоков, их точные SHA/размеры, полную принадлежность к двум исходным literal phases и итоговые числа из таблицы 1. Успех означает **EXACT_CLOSED_FULL_V6_CAPTURE_DATA_VERIFIED**. Оригинальная классификация остаётся FAIL/CLOSED.

**materialize_from_closed_files.py** — отдельный DATA-only инструмент первоначального формирования payloads. Он принимает один явный closed root, проверяет закреплённый главный FAIL/CLOSED receipt и [точную карту 333 файлов](closed-source-map.json). Он читает только эти пути, не обходит диск, не запускает процессы, не читает Source/cache и не перезаписывает существующие payloads. Сначала проверяются все входные и будущие выходные байты, затем создаются только перечисленные новые payload files. Пользователю уже опубликованного пакета достаточно обратного преобразователя.

## 6. Проверка автора и независимое получение

Автор получил все 285 различных содержимых и сверил их SHA. Для большого default stdout использованы 29 ограниченных чтений; объединённые 72452 строки дали исходные **16629137 bytes** и SHA **4e7148e7fd547cd3478473b3b8432dfa98edba574fc5c880a1f258bac6074d74**. Нулевой список Source paths восстановлен как DATA по правилу разделителя. Для всех 333 новых оригиналов буквальный round trip совпал с исходными байтами.

[Data reconstruction proof](data-reconstruction-proof.json) отделяет эти проверки от выполнения опубликованных Python-инструментов. Автор их не запускал. Независимое materialization/reconstruction receiving, выполненное root перед публикацией, должно фиксироваться отдельной квитанцией с фактическими хешами.

[Disclosure review](disclosure-review.json) описывает проверки опубликованных payloads: host paths и owner SID заменены явными ролями, реальные секреты не обнаружены, исходные числовые идентификаторы сохранены.

## 7. Состояние ресурсов

[Resource disposition](resource-disposition.json) сохраняет статус KEEP для первичного закрытого run root до проверки опубликованных копий. Наличие манифеста само по себе не разрешает перенос в trash. Другие файлы старого run root, исходные native-owner receipts, cache artifacts, active/UNKNOWN scopes и уникальные operator role values требуют отдельного учёта.

Подготовка этого пакета не перемещала файлы и не меняла исходные receipts, Source, cache, текущие проверки, PR index, ветки или hooks.
