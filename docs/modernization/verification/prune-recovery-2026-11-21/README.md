## 2. Изменённое поведение

Исходные дефекты видны в [старой реализации][old-install]: снимок существовал только в памяти; ошибка `Delete` превращалась в предупреждение без проверки последствий; последующая компенсация использовала `ImportXML` и скрывала ошибку восстановления. На Windows импорт допускает замещение существующего определения. Новый отрицательный контроль воспроизводит последствия этих границ через install/adopt, не обращаясь к настоящему планировщику.

**Таблица 2 — решение существующего владельца восстановления.** XML означает сохранённое определение задачи; сравниваются исходные байты, включая кодировку.

| Наблюдаемое условие | Действие и результат |
|---|---|
| Не удалось перечислить исходные задачи | Существующее предупреждение; прореживание не начиналось. |
| Нет непустого XML, возможности `CreateXMLIfAbsent` или сохранённого снимка на диске | Предупреждение и пропуск этой задачи до `Delete`. |
| Снимок и возможность восстановления подготовлены | Копирование заимствованного буфера через `bytes.Clone`, сохранение существующим `retainInstallTaskSnapshot`, затем `Delete`. |
| `Delete` вернул ошибку, прежний XML успешно прочитан без изменений | Сохранить предупреждение и продолжить. Это наблюдение определения, не доказательство отсутствия побочного эффекта. |
| `Delete` вернул ошибку, прежнее определение не подтверждено | Прекратить дальнейшее прореживание, сохранить причину и имя задачи в существующей ошибке неполного восстановления. Не повторять удаление и не создавать задачу по предположению. |
| `Delete` вернул `nil` | Добавить компенсацию этого шага в очередь отката; подтверждение ответа не означает атомарной гарантии поколения задачи или завершения её процессов. |
| При компенсации прежний XML уже присутствует | Подтвердить наблюдение без изменения задачи. |
| При компенсации имя явно отсутствует | Существующий `restore`: `CreateXMLIfAbsent`, затем повторное чтение и проверка байтов. |
| При компенсации другое определение, неопределённое чтение или конфликт создания | Сохранить задачу и сообщить неполное восстановление с исходной причиной; не использовать `Delete`/`ImportXML` для освобождения имени. |

В [install.go][install] возвращённые компенсации добавляются в очередь отката **до** обработки ошибки поздней операции прореживания. Это необходимая адаптация вызывающего кода к новому возврату ошибки после частичного изменения. На прежней версии такой путь не был достижим: она возвращала только ошибку первоначального перечисления. Поэтому потеря прежних компенсаций не объявляется отдельным воспроизведённым дефектом старого коммита.

Ошибки компенсации входят в существующий `InstallSchedulerRollbackIncompleteError`. Имена текущего отказа извлекаются до объединения ошибок, чтобы не добавлять имена компенсаций повторно. В [install_task_rollback.go][rollback] метод `rollbackPruned` использует тот же владелец `installTaskRollback`; прежнее значение `createdXML == nil` сохранено как отказ захвата результата создания. Публичные интерфейсы планировщика не изменены: локальный интерфейс наблюдения сужен до реально используемой операции.

Внешние install/adopt сохраняют прежнюю классификацию неполного восстановления. Новые проверки подтверждают сохранение исходных причин, манифеста, происхождения данных, снимков клиента и тестовых маршрутизируемых ключей; незавершённое восстановление не выдаётся за успешную установку или полную очистку adopt.

## 4. Свидетельства и проверка байтов

[evidence.zip][evidence] — **70 619 байт**, SHA-256 `b58362201753892911c53c115ef7c5e329c1f15f5ef9bdb4e8f9b92f7fd6652c`. Архив содержит 44 записи: 43 файла с размерами/хешами и их `manifest.json`. Включены все основные командные stdout/stderr, квитанции шести фаз, описания подмен `overlay.json`, входные манифесты, исходники обёртки/захвата и сведения о форматировании. Для дополнительных read-only наблюдений Git сохранены метаданные и вычисленные снимки исходника в квитанциях; отдельные raw stdout/stderr этих наблюдений в этот комплект не включены.

[verify_evidence.py][verifier] читает архив без распаковки и без исполнения вложенных программ. Он проверяет хеш архива и каждой записи, точный состав, квитанции/потоки, события запуска/завершения без потерянных или повторённых терминальных событий, одинаковую новую выборку для контроля/кандидата, сохранённый FAILED соседнего набора и четыре файла репозитория из таблицы 1. Запуск из корня соответствующей копии репозитория:

```text
python -B docs/modernization/verification/prune-recovery-2026-11-21/verify_evidence.py
```

Это проверка сохранённых свидетельств и байтов, не повторное выполнение Go-тестов, не проверка всех файлов произвольной текущей ветки и не независимая аттестация компьютера. Версия Go зафиксирована отдельным выводом `go version`.

Обёртка переиспользует неизменённый владелец захвата `6f69fc63…`. Его поля `manifest_sha256`/`patch_sha256` относятся к прежнему входному допуску, что явно указано в `source_manifest_role`. Источник и выборки **этого** продолжения задаёт `scope_manifest_sha256=bec98450…`, обёртка — `scope_wrapper_sha256=9dd3bdc1…`, фактические подмены — `overlay_sha256`. Старые поля не используются для приписывания этому кандидату прежних запусков. В `summary.json` оставлена сессионная заметка об ошибочном вызове с буквальным незаполненным pin: отказ до чтения манифеста и команд. Отдельный raw лог этого вызова в архив не включён; код подтверждает порядок допуска, но заметка не считается самостоятельным runtime PASS.

Непосредственные процессы команд завершились, таймаутов не зарегистрировано. Сохранённый `settled` означает `wait` непосредственного дочернего процесса. Общий предел времени и завершение **всего дерева** этим механизмом не доказаны: `whole_process_tree_deadline_enforced=false`, `process_tree_settlement_observed=false`. Не превращать отсутствие флага неопределённости в нативную гарантию.

## 5. Ревью и незакрытые условия

Собственное ревью охватило требования, порядок снимок → изменение → компенсация, сохранение ошибок/имён, отказ замещения чужой задачи, интерфейсную совместимость и отсутствие второго механизма восстановления. Независимое чтение точных файлов таблицы 1 не нашло оставшихся необходимых исправлений; отдельно пересчитаны события и хеши данного комплекта. Оно дополняет собственное ревью и реальные команды, не заменяя их. Нового внешнего квотного ревью и ручного CI не выполнялось.

На текущем master `75dbc640…` отдельно рассмотрены потребители `BackendRunHold`: запрет запуска, сохранение прежнего удержания при объединении и временная копия для probe. Эта правка их не изменяет; `install_parsed_manifest.go` не переносился со старой базы. **Проверка составного источника с master не выполнялась.**

Открыты: нативные Run/RunOwned/Stop/Delete и завершённость действий; права и идентификаторы безопасности; отмена и срок жизни дерева; внешняя замена и неопределённость настоящего планировщика; права/учётные данные восстановления; сроки хранения снимков и расписания; сквозная установка/восстановление; полные обычные/tagged проверки на квалифицированных входах; внешнее ревью точной опубликованной головы. Байтовое равенство XML не доказывает идентичность поколения задачи, атомарность или завершение процессов. Успешный ответ удаления не добавляет такой гарантии.
