## 1. Что пересчитано

`replay.py` независимо проверил исходный ZIP из **198 файлов**, все извлечённые байты и **192 записи** манифеста экспортёра. Шесть корневых файлов дополнительно закреплены собственными точными длинами и SHA-256; закреплённая квитанция экспортёра содержит хеши остальных 192 файлов. Поэтому переносимая проверка распакованного пакета не зависит от доверия к изменяемому манифесту.

Проверены первоначальная передача из **123 файлов**, два дополнительных управляющих файла v2 и два v3. Все три плана привязаны к одному набору **121 входного файла**. Проверены каждый байт первоначального payload, длины, SHA-256, точный набор, управляющие скрипты и планы. Переносимый режим дополнительно читает все 121 соответствующий файл непосредственно из распакованного публикационного пакета.

Для исходников пересчитаны Git-деревья исходного master и полной композиции. Проверено точное изменение состава: **109 файлов**, из них **53 добавления**, **56 изменений**, **0 удалений**. Все 109 файлов изменений проверены по длине, SHA-256 и Git blob ID — идентификатору объекта с его Git-заголовком. В полном локальном режиме заново прочитаны и проверены **все 3323 физических файла**, всего **50 823 826 байт**. Выданная helper таблица снимка в точности совпала с полным закреплённым составом.

Для каждой команды проверены точные аргументы, рабочий каталог, ограничение времени, ожидаемый код выхода, журналы запуска и завершения, сохранённый ввод, stdout и stderr — стандартный вывод и поток ошибок. Результаты Git для индекса и дерева сравниваются с ожидаемыми байтовыми строками с разделителями NUL; результаты импорта объектов сравниваются со всеми ожидаемыми blob ID. Оба результата helper сравниваются с независимо построенным объектом Source, а не только друг с другом.

Основания: закреплённые `next-step/run_source_v3.py`, `prepare-plan-v3.json`, первоначальный payload, `candidate/manifest.json`, `candidate/source-files.json` и `evidence/native-source/records/…`. Их точные версии приведены в таблице 3.

## 4. Воспроизведение проверки

Полный рабочий режим использует существующие каталоги `next-step/`, `candidate/source/`, `execution-evidence/` и исходный ZIP рядом с ними:

```sh
python replay.py --root /path/to/serena-next > audit.json
```

Для компактной публикации распакуйте `bundle.zip` в отдельный каталог. В нём `next-step/` содержит управляющие файлы, `candidate/` — полный манифест и 109 изменений, `evidence/native-source/` — ровно 198 файлов доказательств. Ранее проверенный `pack_execution.py` в пакете восстанавливает первоначальный payload и управляющий payload v2; эти операции не исполняют проект:

```sh
python /unpacked/bundle/pack_execution.py --output /outside/transfer.b64
python /unpacked/bundle/pack_execution.py --v2-control --output /outside/v2-control.b64
python replay.py --root /unpacked/bundle --layout bundle \
  --payload /outside/transfer.b64 --v2-control /outside/v2-control.b64 \
  > bundle-audit.json
```

Файлы вывода packer должны быть свежими; существующие результаты сохраняются. Сам `replay.py` ничего не записывает, кроме JSON в stdout. Он не импортирует packer, restorer, runner или код проекта и не запускает подпроцессы.

Переносимый режим реально проверен на подготовленном публикационном каталоге. Его `PASS` относится к доступным байтам: все 198 записей, управляющие файлы, все 121 вход, изменения, таблица снимка, деревья, коммит и командные доказательства. Он явно сообщает `evidence_zip.rehashed="NOT_RUN"` и `full_source_rehash="NOT_RUN"`, потому что исходный транспортный ZIP и все базовые исходники сознательно не дублируются в компактном пакете. Чтобы добавить эти две проверки, передайте `--evidence-zip /original/a5-source-evidence-v3.zip` и `--source-root /complete/materialized/source`. Предоставленный неполный или изменённый каталог приводит к ошибке, а не к молчаливому пропуску.

## 5. Границы вывода и собственное ревью

В собственном ревью проверены привязка контрольных сумм, наборы файлов, соответствие аргументов и сохранённого ввода, сохранение исходных отказов, ограничения процессов и отсутствие скрытого исполнения в replay. Конкретных дополнительных дефектов, опровергающих фактический результат Source v3, не найдено.

Существующее ограничение внешнего владельца процесса подтверждено v2: его срок относится к удерживаемому прямому дочернему процессу. Это ограничение не устранено увеличением одного срока в v3. Внутренняя защита дочерних процессов helper средствами Windows Job — отдельный механизм; успешный v3 не подменяет самостоятельную квалификацию отмены и завершения всего внешнего дерева.

Исходный master ZIP **17 461 518 байт**, SHA-256 `2e688e6e1e84cc062b3213a50f59f8cad61fac730a2afe44ecaba7f2937d09ac`, отсутствует в данном архиве доказательств. Проверена его сохранённая квитанция получения и привязка проверок runner; этот аудит не перечитывал сам master ZIP. Это отличается от фактически перечитанного транспортного ZIP доказательств и всех локальных 3323 файлов.

Нативные checkout/export представлены полными проверками физического состава в runner и экспортёре; локальный аудит независимо сопоставил их результаты с полным исходным составом и снимком. Он не выполнял новое удалённое чтение этих каталогов. Подготовка Source не подтверждает тесты, работу продукта, публикацию Product, запуск Serena, задачи Windows Scheduler или Rust-контракты. В исходных квитанциях тесты остаются `NOT_RUN`, Product/Serena — `false`.
