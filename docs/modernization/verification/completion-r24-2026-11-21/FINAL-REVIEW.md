## 3. Замечание к сборке публикации

**Место:** README, строка 127 и определение ссылки на строке 160. **Условие:** публикация текущего каталога до добавления `cleanup.json`. **Последствие:** ссылка не открывается, а читатель не может проверить описанные детали последующего переноса двух удержанных readonly-фикстур. На момент этого ревью helper очистки ещё проходил отдельное статическое ревью; завершённый перенос этих двух каталогов здесь не подтверждён.

Минимальное завершение: добавить фактическую квитанцию с результатами проверки/переноса и привязкой к двум исходным фикстурам. Если перенос останется незавершённым, текст должен прямо сохранить этот статус, а ссылка — указывать на существующий документ с таким статусом. Это не опровержение уже подтверждённого переноса ненужных Base64-файлов: для них имеются отдельные локальные и удалённые квитанции.

Ожидаемая квитанция записи 21 описания не считается пропущенным доказательством уже заявленного успеха: README прямо говорит, что описания подготовлены и окончательная запись/чтение будет подтверждена позже. Аналогично локальное дополнение основной Rust-доски проверено по `board.candidate.md`; опубликованный итог этого документа должен входить в последующую квитанцию оформления, а не выводиться из одного наличия локального кандидата.

## 4. Границы формулировок

README сохраняет существенные ограничения доказательств:

1. Чистая точная база плюс перечисленный Go overlay не названы исполнением целого нового опубликованного коммита. Совпадение опубликованных деревьев проверяется отдельно.
2. Общие обычный и тегированный Go-наборы остаются NOT_RUN для R24. Прежние общие FAIL 402,220887 с / 313,08449 с правильно отнесены к `f755d374fab317e1037deecd5dac8ffabbcdde36` с незакоммиченной `internal/cli/gui_force_test.go`, без переноса на `231c80e5`.
3. Нативные примитивы #643, loopback/отказы #650 и функции выбора пути/окружения #635/#637 не названы полной продуктовой квалификацией. Исторические 76 debug-проверок в #631 не представлены как новый release-прогон.
4. Проверка ZIP доказывает целостность и внутреннюю согласованность опубликованных свидетельств. `runtime_authentication=NOT_ESTABLISHED` сохранён по смыслу; без внешнего доверенного хеша архив и манифест допускают совместную замену.
5. Старые поля первоначальных квитанций R21 не выданы за источник полномочий R24, а прежние хеши инструментов — за новый снимок на момент упаковки.
6. Ограниченное ожидание прямого дочернего процесса не выдано за доказательство срока или завершения всего дерева процессов.
7. Отзывы COMMENTED не выданы за APPROVED. Отдельные ветви, текущий общий FAIL, реальные внешние входы и запрет слияния сохранены.

Число «96 файлов и около 20 тысяч строк» подтверждается статическим Rust-разбором: 96 файлов и 20 468 добавлений в сравнении по трём точкам. Это аргумент о размере предлагаемого объединения, а не подтверждение интеграции с текущим master. Слова о сохранённом master и отсутствие merge здесь сопоставлены с локальными квитанциями и областью выполненных записей; нового независимого обращения к удалённой ветке этот аудит не делал.

Обозначения PR, Draft, HEAD, blob/tree, SHA-256, CRC, PASS/FAIL/SKIP/NOT_RUN/UNKNOWN, overlay, API/CLI/CI, EOF/I/O/TCP/RAM/SID и MCP пояснены в README. «Конечные сценарии» в таблице 2 означают конечные события PASS; текст перед таблицей корректно предупреждает о повторном учёте конфигураций.
