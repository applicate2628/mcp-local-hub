# Применённые навыки R24

В R24 прочитаны и применены **15 различных релевантных навыков**. Повторное применение одного навыка несколькими участниками не увеличивает число. Вспомогательные страницы того же пакета также не считаются отдельными навыками. Подбор связан с конкретными решениями, а не с достижением максимального количества.

**Таблица 1. Применение навыков к работе.**

| № | Навык | Применение |
|---:|---|---|
| 1 | Personal Context | Восстановление продолжения из предоставленного контекста и сохранённых материалов; прежние разрешения и новые указания о консолидации не запрашивались повторно. |
| 2 | Git Workflow and Versioning | Коммиты с одним родителем, сравнение ожидаемой вершины при записи, отсутствие принудительной перезаписи истории, проверка полного включения перед закрытием. |
| 3 | Code Review and Quality | Собственное ревью требований, корректности, безопасности, совместимости и сложности; независимый разбор конкретных функций и тестов. |
| 4 | Ponytail | Объединение только изменений одного владельца; сохранение независимых PR и сокращение повторяющихся исторических описаний. |
| 5 | Architecture Review | Разделение наблюдения и полномочий, первоначального владельца и получателя результата; проверка границ времени жизни и прав. |
| 6 | Dispatching Parallel Agents | Параллельные независимые разборы Rust, сборки Serena и квалификации; отдельный владелец каждой правки, единая публикация у основного исполнителя. |
| 7 | Source-driven Development | Проверка точных коммитов, деревьев, исходных файлов и первичных журналов; пропуск исправления доказывался байтами, а не только отсутствием коммита среди предков. |
| 8 | Planning and Task Breakdown | Пять ограниченных кандидатов, порядок проверка → публикация → чтение → закрытие; компактный действующий остаток с конкретными недостающими входами. |
| 9 | Deprecation and Migration | Закрытие поглощённых PR с сохранением веток, полезного кода, тестов и полной истории; изменение базы #637 без переписывания истории. |
| 10 | Go Testing and Verification | Точные селекторы и обязательные результаты корней, детектор гонок, две конфигурации, отдельные build/vet и общие непроведённые тестовые критерии. |
| 11 | Go Project and API Design | Сохранение зон ответственности проекции окружения, дерева, транспортного владельца и publisher; минимальные изменения внутренних контрактов. |
| 12 | Go Concurrency Lifecycle | Проверка однократного первоначального Close, публикации его результата под mutex, ожидания I/O и поведения отменённого/истёкшего контекста. |
| 13 | Ponytail Code Simplification | Отказ от укрупнения Rust-цепочки в 96-файловый PR; отозвано ошибочное предложение менять уже исправленную документацию. |
| 14 | MCP Boundary | Различение частного тестового наблюдения, настоящей квалификации Model Context Protocol и допуска установленного продукта; перенос тестов не расширяет полномочия. |
| 15 | Review Go Engineering Change | Проверка совместного эффекта #639/#647 и #643/#645/#651; локализация условия и последствия каждого изменения, сохранение донорских тестов. |

Канонические рекомендации [Orchestrarium](https://github.com/applicate2628/Orchestrarium/blob/main/shared/AGENTS.shared.md) прочитаны в срезе Git blob `88810caa9134c201677bb09818ec2bc63fca49a8`. Они использованы для проверяемых контрактов и самостоятельности исполнителя; роли не воспроизводились формально. Навыки интерфейса и иллюстраций не подключались: этот срез не меняет пользовательский интерфейс.

Применение навыка не является само по себе доказательством корректности. Такими доказательствами служат исходники, конкретное ревью, журналы команд, хеши, сравнения деревьев и прочитанное обратно опубликованное состояние.
