# R17: результат пяти положительных чтений публичного Go API

**19 ноября 2026 года согласованный однократный запуск завершился пятью PASS и конечным PASS.** Программа Go работала через настоящий Windows-планировщик на закреплённом исходнике #660. По безопасному чтению приватной квитанции владельца обе собственные задачи удалены, `cleanup_complete=true`; отдельное наблюдение после завершения подтвердило отсутствие обоих точных имён. Результат чтений и результат очистки учитываются раздельно. Отдельная файловая сверка 21 закреплённого файла завершилась PASS; её область и результат приведены в разделе 5.

Идентификатор запуска `RunId`: **`027ca2dd03624a318f469ad87b259bff`**. Результат относится только к пяти условиям таблицы 2 на созданной для этого запуска отключённой видимой/скрытой паре. Исходный [согласованный сценарий](README.md) и исторический [отказ при пустом вводе](empty-input.jsonl) сохранены как отдельные свидетельства.

## 2. Фактические пять чтений

В [исходном журнале Go](executed/positive-go.jsonl) **12 записей JSON Lines**: одна запись допуска `admission`, пять записей начала `begin`, пять результатов `result` и одна конечная запись `overall`. Порядок результатов совпал с согласованным; все пять полей `pass` имеют булев тип и значение `true`, а не строковое представление.

**Таблица 2. Проверенные условия и фактические результаты.**

| № | Публичный вызов / метка журнала | Фактические условия | Результат |
|---:|---|---|---|
| 1 | `Status(visible)` / `status-visible` | Ошибки нет; `name_exact=true`, `owner_exact=true`, `runtime_disabled=true`, `state_disabled=true` | **PASS** |
| 2 | `ExportXML(visible)` / `export-visible` | Ошибки нет; `xml_exact=true`, `utf8_valid=true`, `unicode_marker_preserved=true` | **PASS** |
| 3 | `Status(hidden)` / `status-hidden` | Ошибки нет; точные имя и сырой принципал; оба признака отключённого состояния равны `true` | **PASS** |
| 4 | `ExportXML(hidden)` / `export-hidden` | Ошибки нет; точное совпадение XML-байтов с ожидаемой UTF-8-строкой, корректная UTF-8 и сохранённый маркер `Ж§` | **PASS** |
| 5 | `List(prefix)` / `list-visible-only` | Ошибки нет; `exactly_one=true`; единственная строка совпала с видимой задачей по имени, сырому принципалу и обоим признакам отключённого состояния | **PASS** |

У каждого результата `error_present=false`, `is_task_not_found=false`, `is_unavailable=false`. Условия таблицы 2 соответствуют фактическим сравнениям в [Go-программе](positive_probe.go): `Owner` сравнивается без нормализации, XML — по байтам, а строка списка повторно проверяется тем же подмножеством полей, что и `Status`.

Допуск зафиксировал `manifest_valid=true`, `backend_type="*scheduler.windowsScheduler"`, `error_present=false`, `pass=true` и ожидаемый коммит. Конечная запись содержит `status="PASS"`, `pass=true`, `panic_recovered=false`, `task_status_subset_only=true`, `last_result_semantics_qualified=false`. Её `duration_ns=2490548200` — время Go-программы в наносекундах, то есть 2,4905482 с; единичное измерение не используется как оценка производительности.

`last_result_observed=0` встречается только в двух результатах `Status` и результате `List`, после совпадения имени и принципала. Это наблюдение не является условием PASS. Закреплённый `taskStatusFromCOM` не заполняет `LastResult`; ноль не доказывает успешное выполнение действия. Сценарий не вызывал запуск действий задач.

Файл `go-child-start.json` намеренно остаётся снимком начала: в нём `settled=false`, `capture_complete=false`, признаки записи потоков равны `false`, `exit_code=null`. [Владелец](Invoke-R17PublicGoPositiveFixture.ps1) сохраняет этот файл до передачи манифеста и ожидания завершения; окончательное состояние сохраняется в `result.json`. Начальный снимок не является сообщением о незавершённом процессе после окончания запуска.

Для каждого удаления код владельца сначала получает задачу заново через `GetTask`, затем выполняет `Assert-OwnedDisabledTask`: проверяет точное имя, принципал, отключённое состояние, видимость, отсутствие триггеров, ограничения действия и равенство полного XML исходному снимку успешной регистрации. После `DeleteTask` он перечисляет задачи с включением скрытых через `GetTasks(1)` и присваивает `cleanup="removed"` только при отсутствии точного имени. Эти условия связаны с фактической квитанцией из таблицы 3 через проверенный исходник владельца.

**Новый XML-снимок непосредственно перед удалением отдельно не сохранялся.** Поэтому подтверждение защитной проверки перед удалением опирается на исходник и итоговую квитанцию; отдельного сохранённого свежего определения для независимого побайтового повторения этой проверки нет. Чтение, проверка и удаление неатомарны. Наблюдение отсутствия задач после завершения приведено в разделе 5.

Согласованная ветвь очистки после семантического FAIL Go в этом запуске **не исполнялась**: все пять чтений прошли. Этот PASS не является проверкой путей ошибки stdin, сохранения потоков, неизвестного завершения или изменённого определения.

[source-catalog.json](executed/source-catalog.json) содержит размеры и SHA-256 **13 первичных файлов**. Пять публичных файлов перенесены побайтово, а их локальные размеры и хеши сверены с каталогом:

- [launch-result.json](executed/launch-result.json) — 413 байт;
- [execution-preflight.json](executed/execution-preflight.json) — 1697 байт.

Каталог фиксирует нулевой размер `positive-go.stderr.txt` и `launch.stderr.log` с SHA-256 пустого содержимого. Хеши потоков владельца также записаны в `launch-result.json`. Сам каталог фиксирует заявленную идентичность файлов; он не заменяет чтение содержимого приватной квитанции или независимое наблюдение Планировщика.

[outer-execution.json](executed/outer-execution.json) — составленная по сообщениям Remote Desktop Commander сводка внешних кодов и времени. Это производный документ, а не побайтовая копия нативной квитанции. Внешние коды основного запуска и отдельного наблюдателя равны 0; они получены из сообщений исполнителя и не выведены из внутренних полей `pass`.

Журнал Go содержит безопасные признаки сравнения, длительности, классы ошибок и оговорённое числовое наблюдение `LastResult`. В нём нет исходного XML, строк учётных записей, необработанных ошибок или имён задач. Публичное намерение запуска и каталог содержат только заранее согласованные имена собственной пары. Приватные XML, манифест, принципалы и полная квитанция владельца в отчёт не включены.

Исторический отрицательный контроль сохранён без изменения значения его результата: [empty-input.jsonl](empty-input.jsonl) содержит две записи, `manifest_valid=false` и конечный `FAIL`; [квитанция сборки и контроля](build-execution.json) фиксирует код Go **1**. Это ожидаемый отказ при EOF до `scheduler.New()`, а не положительное чтение и не успешный код процесса. [Отдельная предшествующая серия](../RESULTS.md) сохраняет собственную область проверки.

## 6. Собственный аудит и остаток

Собственное чтение сопоставило согласованные пять условий с [Go-исходником](positive_probe.go), затем с 12 фактическими записями. Проверены порядок вызовов, строгие булевы значения, допуск настоящей Windows-реализации, конечный PASS, сохранение оговорок `TaskStatus` и `LastResult`, совпадение идентичностей входов и пяти публичных файлов с каталогом. Для отдельного наблюдения сверены исходник, обе квитанции, размеры, хеши и точная пара имён. Начальная запись процесса отделена от окончательной квитанции; сводка внешних кодов — от первичных файлов. Приватные данные не использованы как публичные примеры. Файловая сверка раздела 5 дополнительно подтвердила приватные связи по закреплённым исходным байтам. В проверенных свидетельствах внутренних противоречий не обнаружено. До выполнения анализатора исправлено только неточное название диагностического счётчика: `verified_files` заменено на `inspected_files`, чтобы при отказе по хешу прочитанный файл не назывался успешно проверенным. Это не меняло критерии PASS и не потребовало повторения нативного запуска.

Подтверждены успешные положительные чтения конкретной отключённой пары и отражённая владельцем условная очистка этой пары. Результат не квалифицирует весь `TaskStatus`, `NextRun`, семантику `LastResult`, произвольное сопоставление принципалов, всю поддержку Unicode, конкурентные изменения, отказы в доступе, таймауты, действительную отмену, `Run`, `RunOwned`, `Stop` или производственный `Delete`. Проверка маркера `Ж§` подтверждает сохранение именно этих символов в проверенных XML. Завершение этой обычной ветви не доказывает гарантированный общий срок или полное завершение дерева процессов при внешнем прерывании.

Общие Go-критерии этим отдельным запуском не выполнялись и общим PASS не объявляются. Прежние полные FAIL сохраняются. Устанавливаемый Product, интеграция Go/Rust и объединение веток этим результатом не квалифицированы. Остаются другие нативные состояния и отказы, отмена, результаты выполнения действий, более широкое сопоставление принципалов и отдельно разрешённые изменяющие операции.

## 7. Термины и сокращения

API — Application Programming Interface, программный интерфейс; COM — компонентная модель Windows, используемая производственной реализацией Планировщика; JSON Lines / JSONL — отдельные JSON-объекты по строкам; XML — расширяемый язык разметки; UTF-8 — кодировка Unicode; SHA-256 — контрольная сумма содержимого; PID — идентификатор процесса; UTC — всемирное координированное время; МСК — московское время, UTC+3; EOF — конец входного потока; stdin, stdout, stderr — стандартные ввод, вывод и поток ошибок процесса; PASS / FAIL — выполнение / невыполнение конкретных условий приёмки; Product — подготовленный устанавливаемый комплект продукта. Поле `capture_complete` означает получение обоих потоков, а `stdout_written` и `stderr_written` отдельно подтверждают сохранение их содержимого.
