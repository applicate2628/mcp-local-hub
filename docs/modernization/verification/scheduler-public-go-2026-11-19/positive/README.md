## Манифест и oracle

PowerShell создаёт ровно одну новую собственную видимую/скрытую пару, как V2: CREATE-only, отключение при регистрации, ноль триггеров, текущий интерактивный принципал с минимальными привилегиями, запрет запуска по требованию, отсутствующий исполняемый файл. Полное исходное определение и неизменённая проверка `Assert-OwnedDisabledTask` остаются у этого владельца.

После регистрации владелец сохраняет приватный `go-manifest.json`: `head`, уникальный `prefix` и две записи `name`, `hidden`, `xml`, `owner`. `owner` — сырой `Definition.Principal.UserId`, без нормализации имени учётной записи. Go получает один JSON через stdin в UTF-8. Программа ограничивает ввод 64 КиБ, требует корректный UTF-8, один JSON без лишних полей, точную пару имён, порядок visible/hidden и маркер `Ж§`.

| № | Вызов | Условия PASS |
|---:|---|---|
| 1 | `Status(visible)` | Нет ошибки; точные `Name` и `Owner`; `RuntimeState=TaskRuntimeDisabled`, `State=Disabled` |
| 2 | `ExportXML(visible)` | Нет ошибки; байты совпадают с UTF-8 исходной XML-строки; UTF-8 корректен и `Ж§` сохранён |

| 5 | `List(prefix)` | Нет ошибки; ровно одна строка, соответствующая видимой задаче по проверяемому подмножеству полей |

`LastResult` выводится только как наблюдение и только после совпадения имени и принципала. В закреплённом [taskStatusFromCOM](https://github.com/applicate2628/mcp-local-hub/blob/1b870e04f58bbf60fde2d2339fcd4ae9b50b24c3/internal/scheduler/scheduler_com_windows.go) это поле не заполняется. Его нулевое значение не доказывает успешное выполнение действия. Весь `TaskStatus`, `NextRun` и семантика последнего результата не квалифицируются.

JSONL — отдельные JSON-объекты по строкам — содержит admission, начало/результат каждого чтения и конечный PASS/FAIL. Выводятся только безопасные признаки, длительности, известные типы ошибок и оговорённый `LastResult`. Имена задач, XML, принципалы и необработанные ошибки не печатаются. На первом несовпадении дальнейшие чтения прекращаются. PowerShell требует пять результатов в точном порядке, булев тип каждого `pass` и единственный конечный PASS.

## Новый допуск и однократное владение

До создания задач обязательны явно выбранный новый `RunId` и SHA-256 проверенного Go-бинарника (`ProbeSHA256`). Повтор с тем же каталогом запрещён. Владелец создаёт `intent.json` через `CreateNew`; он открывает бинарник с `FileShare.Read`, проверяет его хеш и удерживает этот дескриптор в течение ресурсного блока. Все пути работы остаются под `D:\dev\ChatGPT`.

Манифест сохраняется до старта помощника. После старта, но до передачи stdin, записывается `go-child-start.json` с идентичностью образа, PID — идентификатором процесса — и временем начала из удерживаемого объекта `Process`. JSON передаётся как явные UTF-8-байты, без наследования стандартной текстовой кодировки stdin.

Дочерним Go и PowerShell назначаются `TEMP`, `TMP`, `USERPROFILE`, `APPDATA`, `LOCALAPPDATA` и `PSModuleAnalysisCachePath` внутри каталога этого запуска. Их `PATH` содержит только системный Windows PowerShell и системный каталог Windows. [launch_positive.py](launch_positive.py) также задаёт отдельный рабочий профиль родительскому PowerShell внутри разрешённой области. Его `--apply` запускает один процесс с `-ExecutionPolicy RemoteSigned`; настройка действует для этой сессии и наследуемого окружения, не записывается как постоянная политика и не повышает привилегии ([область действия политики Windows PowerShell](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_execution_policies?view=powershell-5.1#set-a-different-policy-for-one-session)). По умолчанию launcher только печатает план, без запуска PowerShell и создания файлов.

Штатно владелец ждёт завершения Go и обоих `ReadToEndAsync`. Лишь после этого устанавливаются `settled=true` и `capture_complete=true`. Принудительного `Kill(Go)` нет: он не доказывал бы завершение дочерних PowerShell-процессов. Гарантированный общий срок и полное завершение дерева при внешнем прерывании здесь не заявляются.

Получение потоков и сохранение файлов — отдельные свидетельства. После обязательного ожидания каждый полученный поток сохраняется независимо, включая путь ошибки stdin; пустой stderr также сохраняется. Поля `stdout_written` и `stderr_written` подтверждают запись, а `persistence_errors` содержит приватные ошибки записи. Первая ошибка запуска, передачи ввода, ожидания или разбора остаётся основной и не заменяется ошибкой записи. Отказ сохранения не отменяет установленное завершение и не блокирует свежую проверку владения перед очисткой; если более ранней ошибки нет, такой отказ делает результат чтений неуспешным.

## Новая политика очистки

**Семантический FAIL Go сам по себе не отменяет доказательство владения.** После подтверждённого завершения процесса и получения обоих потоков PowerShell независимо перечитывает собственные задачи и сравнивает исходное полное XML, принципал, отключение и остальные неизменённые ограничения V2. Если эта проверка проходит, условная очистка разрешена и при FAIL чтений; `reads_passed` при этом остаётся false. Это отдельно согласованная политика данного запуска, без изменения поведения или истории V2. Фактическая серия завершилась PASS; ветвь очистки после семантического FAIL в ней не исполнялась.

При неизвестном завершении/capture, неподтверждённом создании, отсутствии снимка или несовпадении свежего определения задача сохраняется. Нет повторов Delete, UPDATE, новых запусков действий или попыток вернуть старое определение поверх изменённого. Сравнение и удаление неатомарны. Результат Go и результат очистки записываются раздельно в новый `result.json`; приватные определения и ошибки остаются в собственном каталоге запуска.

Зафиксированный PASS относится только к таблице 1 на этой отключённой паре. Он не квалифицирует Run/RunOwned/Stop, производственный Delete, отказы в доступе, таймауты, конкурентные изменения, полную поддержку Unicode, весь `TaskStatus` или устанавливаемый Product.

## Термины и сокращения

API — программный интерфейс; COM — компонентная модель Windows; JSON Lines — по одному JSON-объекту на строку; manifest — манифест проверяемых входов; oracle — условие приёмки; EOF — конец входного потока; `DEVNULL` — пустой ввод процесса, сразу возвращающий EOF; capture — получение потоков процесса; persistence — сохранение полученных данных; SID — идентификатор безопасности Windows; XML — расширяемый язык разметки; UTF-8 — кодировка Unicode; SHA-256 — контрольная сумма содержимого; МСК — московское время, UTC+3; Product — подготовленный устанавливаемый комплект продукта.
