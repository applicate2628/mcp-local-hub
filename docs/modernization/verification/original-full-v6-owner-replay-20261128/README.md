## 1. Подтверждённый результат

Все **130 отдельных native-owner JSON receipts** исторического закрытого full-v6 побайтно восстанавливаются из уже сохранённых 65 package receipts. Общий размер оригиналов — **348272 bytes**. Для каждого восстановленного оригинала получен его исходный SHA-256, закреплённый главным receipt **6cd606a5ec4e6e1a3e74d4b8324786cc98dffe8cd587f4a41c89a751ea7f0c4a**.

Историческая классификация остаётся **FAIL/CLOSED**. Это проверка сохранности данных. Новое получение native custody, запуск продукта или тестов и перенос квалификации здесь не выполнялись.

## 2. Точный рецепт

JSON не разбирается в числовые значения для повторной сериализации. Используется исходный текстовый диапазон поля **proof**. Это сохраняет порядок ключей, string escapes, логические значения и исходную запись чисел, включая **NativeBirthFILETIME**, превышающий точный целочисленный диапазон JavaScript Number.

Для всех 130 оригиналов достаточно одного и того же правила:

1. Проверить точный SHA и размер исходного package receipt.
2. Найти исходный текст объекта **inventory_owner** или **owner**, затем текст его поля **proof**.
3. С первой строки ничего не снимать. Со всех последующих строк снять ровно **четыре пробела embedding indentation**.
4. Добавить один завершающий **LF, байт 0x0A**.
5. Проверить точный размер и SHA восстановленного оригинала.

Все 130 вариантов дали исходные SHA. Отдельно автор прочитал первую оригинальную contained inventory receipt: **2504 bytes**, SHA **e9fe759628a03382ab235a777a9b7d73534198759e4d3b843957512378e027b3**. Полученный рецепт совпал с её фактическими байтами. Для остальных 129 byte identity подтверждена совпадением с оригинальными SHA из root-received owner relations. Первоначальный независимый root audit уже проверял все 130 исходных файлов; его SHA — **f02bf04c80d0e84a5989297f742662ea874bbf7743c78ab3da947305004849d5**.

Числовые значения, даты, PID, handles, пути и поля ошибок не меняются. Никаких эвристических предположений о canonical JSON, округления чисел или повторного кодирования Unicode этот рецепт не требует.

## 3. Независимая проверка

Сначала восстановите исходные данные трёх перечисленных пакетов их собственными преобразователями и явными operator role values. Затем выполните DATA-only проверку с новыми путями для результата:

~~~text
python reconstruct_owner_receipts.py --captures-root "$CaptureData" --prior-full-root "$FullData" --prior-api-root "$ApiData" --receipt "$OwnerDataReceipt"
~~~

По умолчанию программа проверяет все 130 байтовых оригиналов в памяти и записывает только итоговую квитанцию. Для создания самих original JSON files можно дополнительно указать **--output-originals "$NewOwnerDirectory"**. Каталог должен быть новым и отсутствующим; существующие файлы не перезаписываются.

Программа проверяет полную связь с original native-owner inventory главного receipt, 65 parent receipt hashes, все 130 размеров и SHA, а также итоговые **348272 bytes**. Успех обозначается **ALL_130_ORIGINAL_OWNER_BYTES_RECONSTRUCTED**. Это DATA verification: исходное FAIL/CLOSED сохраняется, original native-owner files не открываются, процессы и native waits не создаются, Source/cache не читаются.

Автор выполнил именно текстовый DATA replay и проверку SHA, описанные выше. Опубликованный Python replayer автором не запускался. Независимое root receiving этого replayer оформляется отдельной квитанцией.

## 4. Условия дальнейшего хранения

После независимого DATA replay и проверки опубликованных неизменяемых копий native-owner original bytes не остаются единственными полезными копиями на машине: они полностью восстанавливаются по этому пакету и трём закреплённым источникам.

Это покрывает именно **130 owner receipts**. Остальные файлы run root, active/UNKNOWN scopes, исходники, cache artifacts, operator role values и незапубликованные изменения учитываются отдельно. Сам пакет не перемещает файлы и не изменяет ранее выданные receiving results.

Пакет полного сохранения 566 captures остаётся неизменным; эта небольшая добавка закрывает его явно оставленный вопрос о recoverability отдельных owner JSON files.
