## 1. Исходная проблема и граница изменения

База изменения — точный прежний #628 `9c2ae02bc1c3a5cf2e1fcd16101043d63bbd6fd9`, дерево `4c3f40e4ef80ab1d96c9a99ae72a1aa8d4ba56fe`. Работа выполнена в отдельной чистой копии этой ветки. `master` и другие PR в неё не объединялись. Исходники status/liveness/identity/RSS и зависимости этой области совпадали с `master=a7d92d2852c4f6eb8afb0569ef76a545e38aacf7`; целые деревья не объявляются одинаковыми.

На обычном успешном Windows-пути `supervisorStatusDaemons` вызывал отдельные `IsPidAlive`, `VerifyPIDIdentity` и `ResidentSetSizeByPID`: три открытия одного числового PID [1–2]. После закрытия дескриптора проверки идентичности прежний процесс мог завершиться, а позднее открытие ради памяти — получить другой объект с переиспользованным PID. Тогда строка прежнего процесса могла содержать чужой рабочий набор. **Это вывод из последовательности исходников и правил времени жизни объектов; нативный падающий прогон старого коммита с повторным использованием PID не заявляется.**

Продолжен существующий #628, поскольку это тот же вопрос нативного Go-наблюдения и его реального потребителя. Новый PR не создан. Предыдущий измерительный файл и пять файлов его доказательств сохранены без изменений. Исторические численные результаты двух полей собственного процесса не относятся к новой статусной операции; серии измерений повторно не запускались. Самостоятельный #659 остаётся исправлением наблюдения владельца порта у `internal/api` и в эту ветку не переносился.

Изменение затрагивает **девять Go-файлов, +817/−15 строк; из них 646 добавленных строк — два тестовых файла**. Ни Rust, ни общий реестр PID, ни долговременный кеш дескрипторов для этого не понадобились. Показатель скорости всего приложения не измерялся.

## 2. Реализованный контракт

`ObservePIDStatus` выполняет одну синхронную операцию: `OpenProcess` → начальный `WaitForSingleObject(handle,0)` → прежний `verifyHandleIdentity` → необязательный рабочий набор → конечный `WaitForSingleObject(handle,0)` → проверяемый `CloseHandle`. Для современных Windows достаточно `PROCESS_QUERY_LIMITED_INFORMATION | SYNCHRONIZE`; наследование запрещено. Права завершения процесса и чтения его адресного пространства не запрашиваются [3–5].

**Таблица 1. Границы результата и отображения.**

| Ситуация | Поведение |
|---|---|
| Обязательная проверка прошла | `State=Alive`, ошибка отсутствует; память может быть известной или неизвестной |
| Объект завершился до чтений или к конечной проверке | `State=Dead`; память не выдаётся как пригодный результат; независимые ошибки сохраняются |
| Отказ открытия дескриптора по доступу или отказ ожидания | Нативный результат сохраняет `Unknown` и исходную ошибку; статус использует прежнюю консервативную проекцию `Restarting`. Сохранённое исключение `OpenProcess → ERROR_INVALID_PARAMETER` даёт `Dead` вместе с исходной ошибкой, без фактического ожидания |
| Ошибка образа/создания либо закрытия | Ошибка не заменяет другие причины; обычная строка не получает пригодную память и не считается успешно проверенной |
| Память неизвестна либо равна нулю | Поле `ram_bytes` опускается; отсутствие необязательной метрики само по себе не меняет `Running` |
| Путь команды изменился между проверками | Второй `PIDIdentityProof` сравнивается с proof, с которым выполнено наблюдение; несовпадение запрещает использовать результат для другого ожидания |
| Порт отверг строку | Ранее прочитанная необязательная память отбрасывается; общий классификатор портов не переписан |
| Есть незавершённая остановка `stopPending` | Сохраняются квитанция остановки и прежний отдельный скалярный путь памяти для `Stopping`/`Failed`; новая обязательная проверка там не добавлена |
| Платформа не Windows | Новый callback равен `nil`; сохраняются прежние платформенные функции и тестовые подмены |

Результат, ожидаемая идентичность и ошибка локальны одной строке status. Периодический контроль живости, решения о перезапуске и завершении, целевая готовность и удерживаемые владельцы процессов не используют новый callback. Дополнительных горутин, блокировок и передаваемых наружу дескрипторов нет. Старый скалярный RSS-helper использует выделенное общее чтение по дескриптору и сохраняет своё прежнее поведение.

Один дескриптор связывает **объект**, но не делает все чтения атомарным снимком во времени. Процесс может завершиться сразу после конечного ожидания; снимок портов получен отдельно. Сопоставление с сохранённым временем по-прежнему допускает расхождение **до двух секунд**. Это не точное доказательство первоначального создания supervisor и не полномочие завершать процесс.

Намеренные различия с прежним путём: конечное ожидание обнаруживает поздний выход; ошибка закрытия больше не игнорируется в новой операции; память может быть прочитана до отрицательного результата проверки порта. Поэтому полная тождественность всех отказных ветвей и ускорение каждой строки не заявляются.

## 3. Самостоятельное и независимое ревью

Root самостоятельно проследил обязательность идентичности, ресурсы, независимые ошибки, совместимость, ограничения и весь новый diff. Независимо прочитаны нативный контракт и реализация, затем целое изменение с потребителем. Авторское ревью CLI отдельно от независимого заключения. После окончательного `gofmt` Root проверил, что различия с независимо прочитанными файлами ограничены выравниванием двух объявлений и завершающими пустыми строками.

В первоначальном новом тесте найден и исправлен P2: ожидание по уже закрытому числовому дескриптору как якобы усиленная проверка освобождения. Такое значение может быть уже выдано другому объекту [6]. Поздний вызов удалён; остаются результат настоящего `CloseHandle` и проверка единственности попытки. Исправление подтверждено повторным независимым чтением. Дополнена адресная проверка отказа конечного ожидания после получения известной памяти.

Собственное чтение также выявило необходимость связывать результат с конкретным ожидаемым `PIDIdentityProof`: разрешение команды через `PATH` или символическую ссылку может измениться между этапами. Добавлены сравнение proof и тест реального status producer со сменой двух локальных каталогов поиска; файлы-фикстуры не исполняются.

На окончательном прочитанном коде дополнительных обязательных правок не обнаружено. **Это не внешний Codex PASS и не три отдельных квотных безопасностных ревью из runbook.** Они не запрашивались. Документы независимого разбора включены в архив как свидетельство чтения; их собственные ограничения и привязка к контрольным суммам сохранены.

Прежние тесты измерительного helper запускались как регрессионные после выделения общей операции RSS; benchmark с выборками не запускался.

## 6. Воспроизведение и сохранённые доказательства

[Архив свидетельств](evidence-redacted.zip), SHA-256 **`e56160d239212d200dc9c358bc1277e6148c5620580d6d63012e431ab554cc1b`**, содержит команды runner, квитанции, все соответствующие stdout/stderr, отрицательную мутацию и исходный текст, а также документы ревью. `MANIFEST.json` связывает исходные контрольные суммы с сохранёнными копиями. Машинные пути и пользовательские SID заменены метками; исходные журналы сохранены вне trash. Публичные копии имеют собственные хеши; они не выдаются за побайтово неизменённые исходные журналы.

В сохранённом `run_checks.py` перечислены точные фильтры тестов и переменные окружения. Для самостоятельного повторения нужны установленный совместимый toolchain, локальные зависимости и собственные изолированные каталоги вместо меток. Это не команда установки или автоматического получения отсутствующего окружения. Для воспроизведения нативного child-теста обязательна явная граница времени `-timeout`.

Проверка точного опубликованного коммита выполняется отдельно после публикации; её коммит, команды, результаты и квитанция закрепляются в review этого PR. Результат до публикации не подменяет такую квитанцию. Исходные файлы, обязательные результаты и диагностические остатки не помещаются в trash; полностью завершённые ненужные временные каталоги допускают безопасное перемещение без автоматической очистки корзины.

## 8. Термины и сокращения

**PR** — запрос на включение изменений; **Draft** — черновик; **PID** — идентификатор процесса; **RSS** — resident set size, здесь размер рабочего набора в байтах; **RAM** — оперативная память; **CLI** — интерфейс командной строки; **IPC** — межпроцессное взаимодействие; **PPID** — идентификатор родительского процесса; **CIM** — общая информационная модель управления; **SID** — идентификатор безопасности Windows; **DACL** — список разрешений и запретов доступа Windows; **API** — программный интерфейс; **Job Object** — объект Windows для группировки и ограничения процессов; **SHA-256** — алгоритм контрольной суммы в 256 бит; **JSON** — текстовый формат структурированных данных; **stdout/stderr** — стандартные потоки вывода/ошибок; **EOF** — конец потока; **toolchain** — набор инструментов компиляции; **callback** — вызываемая получателем функция; **race detector** — детектор гонок данных. `Alive`, `Dead`, `Unknown` обозначают живость, завершение и неизвестный результат соответственно; ни один статус сам по себе не означает полномочия создателя.
