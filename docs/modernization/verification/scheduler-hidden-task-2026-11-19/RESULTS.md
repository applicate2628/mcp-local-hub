## 1. Причина и решение

До изменения производственный PowerShell-сценарий сначала получал `$f.GetTasks(0)`, затем выбирал точное имя и выполнял операцию. Microsoft определяет флаг `0` как перечисление без скрытых задач, `TASK_ENUM_HIDDEN=1` — с ними [1,2]. Поэтому доступная скрытая корневая задача ошибочно превращалась в `task_absent`. Платформенные `Stop` и `Delete` поглощают ошибку отсутствия; вызывающая сторона могла получить успех без попытки остановки или удаления [3].

Исправлен общий выбор коллекции перед диспетчеризацией: поименные операции используют флаг `1`, `list` — прежний `0`. Корневая папка, точное чувствительное к регистру сравнение, текстовый формат JSON, кодировка UTF-8, числовые состояния и типы результатов сохранены. Отдельных исправлений в каждой Go-обёртке не требуется.

**Таблица 1. Поведение в выбранной границе.**

| Запрос | Прежний скрытый объект | Исправленный скрытый объект |
|---|---|---|
| Status / ExportXML | Ошибка отсутствия | Достигается прежнее чтение целевой задачи |
| Stop / Delete | Успешный ответ без системного действия из-за поглощённого отсутствия | Достигается прежняя ветвь целевого действия; Stop сохраняет проверку Running |
| RunOwned — защищённый запуск | Проверка существующего определения не достигается | Достигаются прежние проверки определения и допуска |
| List — общий список | Скрытая задача исключена | Скрытая задача по-прежнему исключена |

Область `List` сохранена намеренно. Его потребитель `SchedulerUpgrade` затем удаляет и создаёт задачи; ошибки сохранения определения и восстановления в этом пути остаются отдельными дефектами R17 [4,5]. Безусловное включение скрытого перечисления расширило бы вход такого массового изменения.

`RunOwned` сохраняет проверку имени, ожидаемой команды, роли и аргументов, структуры XML — языка разметки определения задачи, идентификатора безопасности Windows SID, включённости и состояния, а также наблюдаемого изменения определения. Скрытость не выдаёт разрешение обойти проверки; перехода на обычный `Run` нет. Повторное чтение не становится атомарной защитой от внешнего автора.

## 2. Точные исходники и критерии тестов

**Таблица 2. Окончательные Go-файлы.** SHA-256 — контрольная сумма содержимого; все пути относительно корня репозитория.

| Путь | SHA-256 |
|---|---|
| `internal/scheduler/scheduler_com_windows.go` | `e2594cbe0a0cca61038a09ea7d37a701132be378bec6b935236e8b4233ed43fa` |
| `internal/scheduler/scheduler_hidden_task_windows_test.go` | `7d2d7f678c025b706ca9711071ba4f03a69b2b6db9199b36db57297768ea7671` |
| `internal/scheduler/scheduler_owned_run_windows_test.go` | `a30c2944ea1b7bcf95fecb1a33b165cec76e3a832300cb422660c951b00e0f8e` |

Новый тест содержит 12 случаев. Реальный PowerShell исполняет полный производственный сценарий; заменяется только создание и подключение `Schedule.Service`. До запуска требуется ровно одно совпадение заменяемой строки, иначе тест завершается до исполнения. Искусственная коллекция действительно учитывает флаг скрытости. Её методы не создают, не читают и не изменяют системные задачи.

Критерии проверяют точное имя, исходный XML и Unicode, числовое состояние и владельца; различают работающую и неработающую скрытую задачу, отсутствие точного имени при наличии соседних задач, прежнюю область списка и исключение перечисления. `Stop/Delete` дополнительно обязаны оставить ровно один ожидаемый маркер для целевого объекта. Положительный JSON без вызова не проходит. К прежней проверке `RunOwned` добавлены скрытое допустимое определение и скрытое определение с неверным SID.

Восьми корневым функциям адресной выборки соответствуют 51 событие тестов/подтестов при одном повторении. Все имена и события сохранены в квитанциях. Тестовые подмены не доказывают реальное поведение коллекции Windows или наличие скрытой задачи на компьютере пользователя.

Длительность активного теста в сообщении общего тайм-аута не означает его индивидуального пятиминутного зависания. Стек фиксирует место исполнения в момент остановки. В обычном полном прогоне `internal/scheduler` прошёл за 19,405 с, `internal/autostart` — за 0,198 с. `internal/tray` прошёл за 0,053 с: этот результат отличается от предыдущего полного прогона R16, где был отказ tray; сейчас выделен отказ GUI. Ни один из этих результатов не заменяет нативную проверку Task Scheduler.

Причины общих отказов не объявляются автоматически прежними или исключительно вызванными окружением. Для такого вывода нужен соответствующий контроль. Адресные PASS и успешные build/vet не заменяют обе обязательные полные команды.

Не подтверждены реальная скрытая задача Task Scheduler, отказ в правах доступа, системные Stop/Delete/Run и освобождение ресурсов такой фикстуры. Эти действия не выполнялись. Существующий opt-in системный smoke не является проверкой скрытой задачи и не запускался по требованию этой правки. Удаление регистрации не доказывает завершение приложения или дерева процессов.

Прежние ограничения корневых путей и чувствительности к регистру остаются. Включение Hidden не доказывает универсальное отсутствие при любых правах доступа и внешнем изменении. Владение исполнителем задачи не становится владением её дескриптором безопасности; новые гарантии полномочий не заявляются.

Прямой ExportXML без собственного COM остаётся отдельным срезом. Его кандидат `schtasks /Query /TN … /XML /HRESULT` требует проверки полноты классификации исходов и строгой кодировки для существующих UTF-8-потребителей. Текущая проверка Unicode искусственного XML этого не заменяет. Сохранность определений при замене, внешнего поколения при восстановлении, расписания и проекции состояния остаётся в карте R17 [5].
