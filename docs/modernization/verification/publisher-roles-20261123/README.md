## 4. Препятствие для namespace-фикстуры

Первый широкий прогон B1 сохранил отказы трёх native namespace-тестов из-за отсутствующей привязки частной фикстуры. Затем подготовленный штатный launcher был действительно запущен. Он завершился с кодом 1 за 4,37 с и сообщением `recovery namespace fixture: Access is denied.`; новый корень фикстуры не был создан, тесты не исполнялись.

Последующая диагностика воспроизвела ту же операцию открытия предков через `CreateFileW`, без изменения прав. Она установила конкретное препятствие:

```text
C:\Program Files\WindowsApps
CreateFileW → Win32 error 5 (Access is denied)
```

Для проверяемой фикстуры требуется `READ_CONTROL` — право прочитать сведения о защите объекта, вместе с правом чтения его атрибутов и удержанием дескриптора. Предки исходников, временного каталога и `go.exe` прошли такую же проверку; все диагностические дескрипторы закрылись. Дополнительный контракт для пути установленного Store-варианта PowerShell не выполнен. В `C:\Program Files\PowerShell\7` и `7-preview` альтернативного исполняемого файла нет.

Этот отказ не исправлялся ослаблением проверки, изменением списков доступа, политик выполнения или переносом установленного runtime. Для продолжения нужен отдельно допустимый PowerShell-путь и окружение. Установка или изменение окружения требует отдельного разрешения согласно инструкциям репозитория; разрешение на обычные правки и тесты его не заменяет.

Полный стандартный и тегированный состав API — программного интерфейса приложения — и CLI — интерфейса командной строки — пока не допущен. Обязательные `NOT_RUN` остаются; условие завершения раздела B не выполнено.
