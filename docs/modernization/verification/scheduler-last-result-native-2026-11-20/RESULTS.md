# R17: нативная передача LastResult через Status и List

**20 ноября 2026 года, московское время. Два публичных чтения текущего кода завершились PASS:** `Status` и `List` вернули **`267011` (`0x41303`)**, совпавшее с прямым чтением настоящего свойства `IRegisteredTask.LastTaskResult`. Использована уже существующая задача; задачи Планировщика не создавались, не изменялись, не запускались и не удалялись. Предыдущие одноразовые допуски и RunId не использовались повторно.

Проверен производственный коммит **`9721681633440d3593d37ffb8f580e5d98440da2`**, дерево **`016c9faa5aaedb3ed7db2e6b23066913824a4f09`**. До и после подготовки и нативного чтения собственная исходная копия имела эти идентичности и чистое состояние. Производственные исходники в этой серии не менялись.

Доказательство относится к **передаче наблюдаемого ненулевого COM-кода через два публичных метода**, где COM — компонентная модель Windows, API — программный интерфейс. Microsoft обозначает `0x41303` как `SCHED_S_TASK_HAS_NOT_RUN`: задача ещё не запускалась [2](#ref-2). Это не результат завершённого действия с кодом `87` и не полная системная приёмка. Прежние общие Go-проверки коммита `97216816` остаются FAIL.

Имена скриптов и квитанций ниже обозначают элементы [архива свидетельств](evidence-redacted.zip). [Сводка исполнения](execution-summary.json) доступна отдельно. Обезличенные копии отличаются от оригиналов: `MANIFEST.json` сохраняет исходные и опубликованные контрольные суммы раздельно.

## 4. Доказанное свойство и его пределы

**Подтверждено:** настоящий ненулевой результат существующей задачи прошёл путь `IRegisteredTask.LastTaskResult` → производственный PowerShell-мост → внутренний JSON → `TaskStatus.LastResult` и совпал в двух публичных методах текущего коммита [1](#ref-1), [4](#ref-4), [5](#ref-5). Нативное свойство наблюдалось как `System.Int32`; его тип соответствует знаковому 32-разрядному `LONG` контракта Windows [1](#ref-1), [3](#ref-3).

**Вывод из кода и условий сравнения:** старый дефект, при котором `LastResult` оставался нулевой инициализацией Go, не прошёл бы ненулевой эталон `267011`. Старый коммит в этой нативной серии не запускался; это рассуждение не обозначается как новый отрицательный нативный контроль. Отдельный ранее исполненный отрицательный контроль реализации сохранён в [предыдущем отчёте](../scheduler-last-result-2026-11-20/RESULTS.md#checks).

## 5. Аудит, завершение процессов и сохранение свидетельств

Собственный просмотр сопоставил требования с читателем, прямым наблюдателем, обвязкой и декодированными квитанциями. Проверены допуск до обращения к Планировщику, отсутствие изменяющих вызовов, ненулевой независимый эталон, точность сравнения полей, требование одной строки списка, разграничение типов `System.Int32` и Go `int`, отказ при неполной серии, связь подготовки и бинарника, сохранение первоначального отказа и ограничения доказательства.

Независимое статическое ревью обвязки с SHA-256 `728c5d9fa0431fc65c565b6f38657c6cec935740420f344697cf68e433c34216` завершилось без неустранённых дефектов в проверенной ограниченной дельте. Это результат статического просмотра, не выполнение каждой ветви восстановления и не замена обязательного внешнего ревью всего PR.

**Историческое замечание P3 к `run_observation.py`.** Текст `observe_candidates.ps1` сначала читался в аргумент `-Command`, а контрольная сумма файла вычислялась повторным чтением диска после запуска процесса. При конкурентной замене файла эта сумма могла бы описывать другие байты; она не является защитой от такой подмены. Факта подмены не обнаружено. Исторические исходник и квитанция сохранены; предварительный read-only отбор не переисполняли. В выполненной основной обвязке `snapshot_bytes` читаются один раз, и их же байты используются для вычисления хеша и передачи PowerShell. Это устраняет указанную неоднозначность связи этих входных байтов, но не устанавливает атомарность системных наблюдений.

Все непосредственные команды в успешных подготовительной и нативной квитанциях имеют `settled=true`; их стандартные потоки ошибок пусты. Завершение непосредственных детей не выдаётся за доказательство всего дерева процессов.

После серии отдельный наблюдатель завершился с кодом `0`; его внешняя оболочка также явно сообщила `0`. ## 9. Термины и сокращения

**COM** — компонентная модель Windows; **API** — программный интерфейс; **JSON** — текстовый формат обмена данными; **JSONL / JSON Lines** — отдельные JSON-объекты по строкам; **XML** — расширяемый язык разметки; **UTF-8** — кодировка Unicode; **КиБ** — 1024 байта; **нс** — наносекунда, одна миллиардная доля секунды; **SHA-256** — криптографическая контрольная сумма для сверки содержимого; **SID** — идентификатор безопасности Windows; **CIM** — общая модель управленческих данных; **PR / Draft** — запрос на включение изменений / черновик; **UTC / МСК** — всемирное координированное / московское время, МСК = UTC+3; **stdout / stderr** — стандартный вывод / стандартный поток ошибок; **PASS / FAIL** — выполнение / невыполнение конкретных условий приёмки; **native / нативное обращение** — работа с настоящим системным объектом; **mock / модель** — контролируемая замена системного объекта; **Product** — отдельно подготовленный и квалифицированный устанавливаемый комплект продукта; **P3** — обозначение низкого приоритета замечания в использованном ревью; **RunId** — идентификатор единичного запуска; **принципал задачи** — учётная запись, от имени которой выполняется её действие. `settled` относится к завершению конкретного непосредственного процесса, а `stable_private_snapshots` — к сравнению содержимого сохранённых снимков.
