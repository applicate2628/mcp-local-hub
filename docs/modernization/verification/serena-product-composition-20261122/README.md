# Serena/Product: воспроизводимая композиция исходников

**22 ноября 2026 года. Подготовлены только входы для последующей квалификации.**
Набор `core` содержит 35 Go-файлов и два PowerShell-файла; `extended` содержит
74 файла. Их исходные версии, разрешённые пересечения и точные выходные байты
закреплены в [manifest.json](manifest.json). Исполнение программы, тесты,
сборки, установка, выдача издателя и Product не выполнялись.

**English scope.** These are source-only candidate deltas on a pinned master.
The complete prospective tree was calculated in memory; no Git tree object
or commit was created. Neither the file manifest nor its hashes issue a
publisher source epoch, a qualified executable, or installation authority.

## 4. Роли образов и допуск издателя

**Таблица 4. Три разных входа.** PE — формат исполняемого файла Windows.

| Образ | Исходник и роль | Граница |
|---|---|---|
| Обычный runtime Product | `./cmd/mcphub`, роль PE `product` | Отдельно собираемый и допускаемый комплект runtime |
| Serena qualification publisher | `./internal/cli`, теги `test_state_path_env,serena_qualification`, роль PE `serena-qualification` | Не проходит обычный Product admission |
| Командный тестовый Product #657 | `./internal/cli`, тег `test_state_path_env`, роль PE **`product`** | Исполняет тесты; fixture содержит пустой `source_epoch`, обычный runtime этим не заменяется |

`build.ps1` прямо запрещает `SourceSnapshotPath` вместе с
`TestStateIsolatedProduct`. Режим #657 поэтому не выдаёт Serena publisher.
Потребитель командной fixture отдельно проверяет хеши, исходный canonical
entry set и, для командного сценария, совпадение выполняющегося образа с
Product этой fixture.

Существующий издатель требует реальный чистый выбранный источник:
`tools/test-serena-publisher/main_windows.go` отказывает при
`dirty_selected_source=true`. Go overlay сам по себе этого условия не
выполняет. Общий `PreparePublisherSource` выбирает и экспортирует полный
состав, фиксирует состояние Git и выдаёт snapshot; исправление обнаружения
staged deletions сохранено в `extended`.

После фиксации текущего источника остаются самостоятельными входами допуска:
существующий Windows/amd64 Go и его фактический GOROOT, заполненный кэш
модулей с закреплённым генератором ресурсов, свежий приватный work root,
исходные сроки и закрытие ресурсов, отдельный обычный Product с точным
SHA-256, предназначенные UV/Python и приватный run root. Удалённые рабочие
каталоги должны оставаться внутри `D:\dev\ChatGPT`.

Требования и разделение ролей определяют
[README издателя #635](https://github.com/applicate2628/mcp-local-hub/blob/f639b97ccc56eb18d314d52951d1b5d167d11e5f/tools/test-serena-publisher/README.md),
[инструкция #637](https://github.com/applicate2628/mcp-local-hub/blob/1ebe00c5dbac448488d980072e689b1126875dde/docs/testing/serena-qualification.md)

Воспроизводимый порядок последующей фиксации:

1. Создать отдельный свежий checkout точного master из §2. Сохранить байты
   Git blob без преобразования окончаний строк. Основную рабочую копию и

2. Проверить manifest и скопировать ровно `sets.extended.paths` из
   `extended/` по относительным путям, двоично, как обычные файлы с правами
   `0644` и Git-режимом `100644`.
   Остальные 3235 файлов оставить исходными. README, manifest и генератор
   данного комплекта в вычисленное дерево не входят.
3. Сверить полный состав: 3309 файлов, ровно 39 добавлений и 35 изменений,
   без удалений и посторонних файлов. Сопоставить байты 74 входов с выходными
   хешами manifest. При подготовке индекса выбирать только этот точный
   список путей.
4. При последующей фиксации проверить подготовленное дерево через обычный
   Git и потребовать `d7932bf914b736526d76f97559d17499b88fbfb2`. Создать
   отдельный исходный коммит с единственным родителем `75dbc640…`,
   записать его настоящий идентификатор, затем независимо прочитать дерево
   и байты обратно. Коммит не вычисляется заранее: его идентичность зависит
   также от метаданных и сообщения. Слияния PR для этого не требуются.
5. Перед издателем вновь подтвердить исходник и его допуск. Передавать
   существующему `PreparePublisherSource` весь этот checkout и настоящий

## 6. Выполненная проверка и открытая квалификация

Выполнены статическое сопоставление исходных blob, чтение разрешённых
пересечений, материализация и обратная сверка всех 111 выходных файлов:
точное множество путей, длины, SHA-256 и Git blob. Повторно проверено,
что между общими путями core/extended различаются ровно три файла из §3.
Полное предполагаемое дерево из §5 рассчитано в памяти; его исходное
основание независимо воспроизведено из листьев Git.

**NOT_RUN — не запускалось:** компиляция, `go build`, `go vet`, обычные и
tagged Go-наборы, PowerShell-выполнение builder, выдача source snapshot,
издателя и Product, установка Serena, настоящий Ready, consumer-intent,
supervisor, отмена/восстановление и завершение полного дерева процессов.
Внешнее ревью новых итоговых коммитов этим материалом не получено.

Комплект предназначен для независимого ревью и последующего сохранения
через существующий PR #664. Подготовка файлов не означает готовность
самостоятельных PR, выполнение полного плана A–D или основание для закрытия
доноров. Изменения checkout `mcphub`, ветвей, PR, установок и публикаций
в рамках подготовки этого комплекта не выполнялись.

**Термины.** MCP — Model Context Protocol, протокол взаимодействия с
инструментами; HTTP — Hypertext Transfer Protocol, протокол передачи
запросов и ответов; TCP — Transmission Control Protocol, транспортный
протокол; CLI — Command-Line Interface, интерфейс командной строки.
ASCII — базовая семибитная таблица символов; SHA-256 — Secure Hash Algorithm
с 256-битным результатом. UV — используемый менеджер Python-пакетов;
GOROOT — корень выбранной установки Go. Ready — запись подтверждённой
готовности; endpoint — адрес обслуживания; finalizer — завершающий этап,
получающий результаты закрытия ресурсов. Fixture — контролируемый тестовый
вход; source epoch — идентичность полного исходника, выдаваемая штатным
владельцем; TestMain — вход подготовки и завершения тестового пакета Go.
