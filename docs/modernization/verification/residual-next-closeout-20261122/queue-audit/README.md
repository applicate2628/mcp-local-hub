## Почему прежнее ревью #655 не покрывает текущую голову

Полный список `commit_id` отправленных ревью #655 состоит из одного
элемента: `2defe618259f7db4144824d19927b032300d160d`. Точное сравнение с
`1a5a7dd04fe732df5c539860dde813c8c703586d` возвращает `ahead_by=1`,
`behind_by=0`: ревью закреплено на непосредственном прежнем состоянии [5,7].

Новый коммит от 22 ноября меняет два производственных файла CLI — интерфейса
командной строки: `serena_prepared_run.go` и
`serena_prepared_wrapper_close.go`. Прочитанные изменения отделяют полученную
ошибку `Serve` от доказательства закрытия wrapper и классифицируют отказ
привязки порта после получения результатов освобождения. Добавлены
Windows-тест на 257 строк и три файла доказательств [7–8]. Это новые
производственные условия после ревью от 18 ноября. Старый отзыв о порядке
`Prepare`/finalizer не является ревью этих последующих изменений.

Отсутствие актуальной записи ревью не отрицает собственное или независимое
чтение, описанное в материалах PR. Здесь проверена именно опубликованная
привязка отправленных отзывов GitHub к точным коммитам.

## Границы вывода и последующий контроль

Этот срез не доказывает отсутствие уникального кода в донорских ветках,
полное поглощение их изменений или семантическую эквивалентность. Оснований
для закрытия PR из него не выводится; закрытия не предлагаются.

Новые головы, которые root опубликует после этого интервала, требуют
отдельного обратного чтения и проверки `commit_id` ревью. Данный снимок
остаётся квитанцией состояния до таких публикаций. Новые проверки кода,
нативные сценарии, CI — непрерывная интеграция — и внешние модельные ревью
здесь не запускались.
