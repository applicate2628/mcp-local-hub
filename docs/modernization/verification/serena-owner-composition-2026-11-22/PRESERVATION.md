# Полная дельта и сохранение источников Serena

Эта записка фиксирует подготовительное доказательство состава. Последующие результаты исполнения приведены в [отчёте](README.md); исходная версия записки и все упомянутые локальные материалы сохранены в `serena-next/` внутри [архива свидетельств](serena-composition-evidence.zip).

Это source-only доказательство состава публикации, построенное на полных деревьях Git. Поведенческое сохранение составных файлов опирается также на прочитанный diff и ревью; равенство множества путей само по себе его не доказывает.

## Полнота исходных деревьев

GitHub read API вернул `truncated=false` для четырёх рекурсивных деревьев. Сравнение выполнялось по всем конечным объектам — путь, mode, type и blob/commit identity — без предварительного ограничения расширением `.go` или каталогом `internal/api`. Локальный расчёт дерева из этих объектов воспроизвёл каждый исходный Git tree SHA. Это проверяет полноту полученного дерева независимо от короткой таблицы PR changed files. Записи доступны в [source-subtraction-proof.json](source-subtraction-proof.json); исходные JSON находятся в `source/`.

## Вычитание донорских дельт

**Таблица 2. Куда попала каждая дельта.** Здесь число составных строк считается отдельно для каждого донора, поэтому один общий файл может встречаться в двух строках таблицы.

| Источник | Изменённых путей от общего основания | Точный donor blob в результате | Согласован с другими обязанностями | Неучтённый остаток |
|---|---:|---:|---:|---:|
| Уже целевой #643 | 9 | 7 | 2 | 0 |
| #648 | 11 | 7 | 4 | 0 |
| #652 | 10 | 5 | 5 | 0 |

Объединение **21 донорской path-role записи** #648/#652 содержит **18 уникальных путей**. Это ровно множество записей [manifest18.json](manifest18.json). Среди них 12 точных donor blobs и шесть составных файлов. В целевом дереве 8 файлов добавлены, 10 изменены. Семь остальных путей из 25-file композиции уже находятся в #643 и остаются прежними; удаления и побочные изменения исключены сравнением всего спроецированного дерева с родителем.

[donor-to-composed.patch](serena-composition-evidence.zip) показывает остаточную разницу каждого несовпадающего donor blob с окончательным файлом. [publication.patch](serena-composition-evidence.zip) показывает только 18 изменений относительно точного #643. В машинном доказательстве нет утверждения, что составные файлы побайтно равны донорам.

## Документы, архивы и прежние результаты

**Все 628 non-Go leaves одинаковы** в общем основании и трёх головах, включая все 109 путей в `docs/` и `.plans/`. Между каждой донорской головой и #643 non-Go delta также пуст. Пути со стандартными архивными расширениями `.zip`, `.tar`, `.gz`, `.tgz`, `.7z`, `.rar` в этих четырёх точных деревьях отсутствуют. Главное доказательство отсутствия уникального архивного остатка — полное равенство всех non-Go identities, а не один поиск расширения.

Следовательно, **из самих голов #648/#652 нет ни одного документа или архива, который нужно доперенести в #643**. Условие получения отсутствующих donor-doc bytes для этой дельты не возникает.

При этом описания PR ссылаются на исторические документы и evidence на *других* commit. Эти ссылки не следует терять или ошибочно приписывать дереву донора:

- #648: [R25 publication648.json](https://github.com/applicate2628/mcp-local-hub/blob/a4c6de78d867d9e99ee596c15251ac7d4a522737/docs/modernization/verification/completion-r25-2026-11-21/publication648.json) и [R25 audit](https://github.com/applicate2628/mcp-local-hub/blob/a4c6de78d867d9e99ee596c15251ac7d4a522737/docs/modernization/verification/completion-r25-2026-11-21/AUDIT.md). Точные 995 bytes publication receipt получены через GitHub, сохранены локально и проверены по blob `88ecb747033e535042806e92f76e1106aa0476a1`; SHA-256 `92bdb6979ad9eefd62a2efc67b733d6e25a4d571d20c1bee6d3118c504962576`. Этот receipt относится к старому parent+overlay, не к новой композиции.
- #652: исторические sharing RED, batch GREEN и migration failures/continuations остаются связанными с исходными commit, image и комментариями, перечисленными в [сохранённом описании #652](serena-composition-evidence.zip). Успех чтения, полученный на иных combined sources, не превращается в standalone/current-head результат.
- #643: сохранены ссылки на R24 и исходные #645/#651 imports; [описание #643](serena-composition-evidence.zip) не меняет прежние границы квалификации.

Для #648 прочитаны точные GitHub directory indexes R25, включая отдельный каталог `serena/` и `archive/`: `public.zip` там имеет blob `a9e233b36694000e69f876cbd02c0a6783534f88`, размер 2 047 483 bytes. Этот архив находится на `a4c6de78…`, отсутствует в головах donor/target и не является их уникальной Git-дельтой. Его содержимое в этом этапе не скачивалось и заново не квалифицировалось. Наличие/размер/blob из индекса не объявляются проверкой содержимого архива.

Все три текущих PR description сохранены дословно, с локальными SHA-256 в [source-subtraction-proof.json](source-subtraction-proof.json). При замене описания #643 полезный минимальный перенос — краткая таблица происхождения, ссылки на donor heads, эти исторические источники и явное разграничение старых и новых результатов. Копия всего общего R25 bundle увеличила бы PR и добавила бы несвязанную ответственность; для сохранности он уже адресован immutable commit.

## Публикация и пределы доказательства

`manifest18.json` предназначен для одного append commit с единственным родителем `44f9a3a…`. Локально рассчитанный ожидаемый tree только с 18 Go replacements — `d0493719ec58b8b737d25a95316bbf65122b0d2c`. Добавление README/evidence как новых файлов изменит этот tree; root должен явно учесть дополнительные пути, а не сравнивать иной состав с данным code-only hash.

Перед закрытием #648/#652 необходимы readback опубликованных files/tree/parent, отсутствие неперенесённых строк preservation map и сохранённые ссылки на исходные головы/историю. Закрытие PR само по себе не удаляет branch или immutable commit; удаление веток и force-push не входят в задачу. Полная исходная история master не добавляется в #643.

На этом этапе выполнялись чтение GitHub, локальные byte/hash/tree comparisons и подготовка файлов. Никакие Go/native процессы, remote actions, refs, CI или установки не запускались. Десять квалификационных фаз исполняет root отдельно; в этой записке нет их предполагаемых PASS. Сохранённый formatting receipt подтверждает только свой конкретный format stage и неизменность его входов.
