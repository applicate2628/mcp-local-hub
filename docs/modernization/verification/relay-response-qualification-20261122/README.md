# Relay: ограничение ответов и сохранение ошибок

**Адресная квалификация двухфайлового кандидата завершена.** Проверены пределы HTTP/SSE, передача ошибок, однострочный вывод JSON и отказ от повторной отправки POST при перенаправлении. Найденные на Comet завершённые запуски восстановлены и сверены, затем выполнены только отсутствовавшие соседние проверки, сборка и `go vet`. Код кандидата не менялся при восстановлении результатов.

SSE — Server-Sent Events, поток событий сервера. MCP — Model Context Protocol. JSON-RPC — протокол удалённых вызовов в формате JSON. Здесь Relay соединяет HTTP-транспорт со стандартными потоками ввода и вывода (`stdio`). Проверка `-race` обнаруживает гонки доступа к памяти в выполненных сценариях.

## 2. Исправленное поведение

Успешное конечное HTTP-тело, диагностическое тело HTTP-ошибки и накопленные данные одного события SSE ограничены существующим пределом HTTPHost: 4 МиБ, то есть 4 194 304 байта. Разделительные переводы строк между полями `data` учитываются в пределе события до добавления данных. Этот предел отдельного сообщения не является оценкой общей памяти процесса.

Ошибки чтения ответа, разбора SSE и вывода сохраняются в результате `Run`, включая совместно наблюдавшиеся причины. Отмена останавливает работу, но не превращает независимую ошибку в успех. Работники POST и слушатель SSE присоединяются до возврата. Для ошибок POST используется отдельная блокировка: потенциально заблокированный чужой `Stdout` не задерживает отмену контекста.

Перед записью проверяются размер, UTF-8 и синтаксис JSON. Компактизация сохраняет данные строк и большие числовые идентификаторы без преобразования через `float64`; каждое принятое сообщение занимает одну строку `stdio`. Первая ошибка синтаксиса, короткой записи или вывода запрещает последующие записи в повреждённый поток.

POST не следует перенаправлению, способному повторить действие. Для этого используется копия `http.Client`, объект вызывающей стороны не изменяется. GET возобновляется после чистого завершения потока; ошибка parser/output завершает слушатель. Курсор SSE фиксируется на пустой строке после успешного получателя. Незавершённый блок с данными не выдаётся и не продвигает курсор.

Завершённые пустые и служебные события MCP допускаются без передачи в JSON-получатель. Пересылаются непустые события без имени либо с точным именем `message`. Тип события сбрасывается на каждой границе блока; значимые пробелы ID сохраняются, ID с NUL игнорируется, пустое поле ID сбрасывает курсор. Это устраняет также дефект неопубликованного предшественника `d49b1ca3…`, который отклонял начальное пустое событие SDK.

При отсутствии явно заданного клиента POST сохраняет свой предел 60 секунд, GET живёт до завершения контекста `Run`, DELETE имеет собственный предел 2 секунды. Явно предоставленный клиент сохраняет политику тайм-аута. Значения по умолчанию не записываются в экспортируемое поле между повторными `Run`.

## 5. Допуск и ограничения

Новые проверки использовали только заранее имеющиеся инструменты и модульный кэш. Загрузки отключены: `GOPROXY=off`, `GOSUMDB=off`, `GOVCS=*:off`, `GOTOOLCHAIN=local`, `GOENV=off`, `GOWORK=off`, `-mod=readonly`. Профиль, временные каталоги, телеметрия и новый кэш сборки находятся в отдельной области `D:\dev\ChatGPT`. Нативный временный путь проверен через `GetTempPath2W`.

Новые response tests используют конечные входы в памяти и подставной `RoundTripper`; они не создают внешних серверов, SDK-сессий или дочерних процессов. Проверки таймеров используют `testing/synctest`. Соседний набор ограничен закреплёнными 17 именами. `TestMain` пакета работает со своим временным состоянием. Реальные Scheduler, установленный Hub, внешние агенты, учётные данные и установки не использовались.

Полный Go test gate, нативные CLI fixtures и реальный GET-SSE/SDK consumer profile остаются **NOT_RUN**. `build` и `vet` всего дерева не означают выполнения тестов всего дерева. Прямые запущенные процессы завершились; гарантии общего предела времени и завершения всего дерева потомков этот runner не добавляет.

Открыты отдельные результаты: объявленная сервером задержка `retry`; согласованный заголовок `MCP-Protocol-Version` в последующих запросах; реальный потребитель GET-SSE с возобновлением, удержанием результата, измерениями памяти/задержек/потерь и проверкой завершения исходных сессий. Ошибки `Body.Close`, произвольно блокирующий чужой reader/writer/callback и строгая проверка схемы JSON-RPC не закрыты этим инкрементом. CMake #624 `5ee707f…` не изменялся.

Собственное ревью: [self-review.md](self-review.md). Отдельное внешнее ревью должно относиться к точному опубликованному коммиту. Полная приёмка ветки, слияние и закрытие остальных пакетов не заявляются.
