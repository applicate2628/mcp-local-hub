## 1. Результат и область

**Очистка неиспользуемого хвоста `parsed.records` уменьшила наблюдаемую удерживаемую Go-память в этой диагностике; полезный результат обоих вариантов совпал.** Строгая обработка исходных событий подтвердила по **18 уникальных строк наблюдений** на вариант, по **7 успешных тестовых завершений** — root и шесть подслучаев — и одному успешному завершению пакета. Отказов и пропусков нет, обе команды завершились с кодом 0.

Сравнивались два явно закреплённых overlay на одной базовой версии #624 `81dcf67db013ba2879878c2ee6fe07aa0bb4aec3`:

- **`before-clear`**: окончательный diagnostic helper плюс прежний `cmaketrace.go` без очистки хвоста; остальные исходники остаются от указанной базы.
- **`current`**: тот же diagnostic helper и текущий `cmaketrace.go` базовой версии с `clear(parsed.records[len(records):])`.

Это не сравнение двух полных исторических checkout. Варианты различаются ровно выбранным production-файлом, а его содержательный переход уже рассмотрен в [REVIEW.md](REVIEW.md). В работе использовались сохранённые первоначальные CMake trace/oracle; CMake и установка заново не запускались.

**Первичная трасса получена настоящим CMake на синтетическом fixture-проекте R22** — специально подготовленном тестовом проекте; происхождение артефактов сохранено в [манифесте R22](https://github.com/applicate2628/mcp-local-hub/blob/b1d932ea8925ef3324d539e5de006daeae65ba2a/docs/modernization/verification/completion-r22-r23-2026-11-21/README.md). Этот проект не заявлен репрезентативной нагрузкой клиента, реального проекта или продукта. Наблюдаемое сокращение удерживаемой памяти относится к данному входу и диагностическому сценарию; переносить его величину в бюджет production-памяти или задержки без соответствующей нагрузки нельзя.

Наблюдения относятся к **памяти всего Go-процесса при явно удерживаемых владельцах и принудительных сборках мусора**. Они не являются точным размером объекта `Result`, пиком памяти, resident memory, пропускной способностью или обычной задержкой production-запроса. По три образца в каждой группе дают описательные медиану и диапазон, без вывода о статистической значимости.

Полные проверенные данные: [retention-result.json](retention-result.json). Табличные показатели без округления: [retention-cohorts.csv](retention-cohorts.csv). Обработчик: [reduce_retention.py](reduce_retention.py).

## 2. Удерживаемая память

Для каждой строки из `ResultsAndWire.HeapAlloc` вычтен `Before.HeapAlloc` **той же строки**. `Before` записан после двух сборок мусора до запуска работников; в `ResultsAndWire` обе группы владельцев — результаты и закодированные тела — ещё живы после двух последующих сборок. Затем по трём таким разностям одной группы рассчитаны медиана, минимум и максимум.

**Таблица 1. Изменение `HeapAlloc` относительно собственного baseline при удержании результатов и тел. Медиана [минимум; максимум], МиБ.**

| Сценарий | Работников | `before-clear` | `current` |
|---|---:|---:|---:|
| `selected-32` | 1 | 11.154 [11.153; 11.154] | 1.672 [1.671; 1.677] |
| `selected-32` | 4 | 44.615 [44.613; 44.621] | 6.688 [6.687; 6.688] |
| `selected-1000` | 1 | 11.115 [11.115; 11.115] | 2.195 [2.195; 2.195] |
| `selected-1000` | 4 | 44.462 [44.462; 44.462] | 8.780 [8.779; 8.784] |
| `last-marker` | 1 | 11.138 [11.138; 11.138] | 1.623 [1.623; 1.623] |
| `last-marker` | 4 | 44.552 [44.552; 44.559] | 6.492 [6.492; 6.493] |

МиБ — мебибайт, 1 048 576 байт; исходные счётчики в JSON содержат целые байты. Одинаковые округлённые границы не означают отсутствие небольшого разброса. Например, для `selected-32` с одним работником точные медианы составляют **11 695 968 → 1 753 352 байта**, а с четырьмя — **46 782 072 → 7 012 784 байта**.

Во всех строках capacity среза записей остаётся **17 578**. Следовательно, эта правка не уменьшает сам backing array: она убирает ссылки из отброшенных элементов. Совпадение результата и наблюдаемое снижение held snapshot согласуются с этим механизмом; величина разности остаётся измерением всего процесса, а не точным размером освобождённых строк или отдельного `Result`.

После удаления владельцев результатов фаза `WireOnly` сохраняет только тела. Например, для `selected-32`, один работник, медиана `WireOnly.HeapAlloc − Before.HeapAlloc` равна **41 256 байт до очистки** и **41 432 байта после неё**. После удаления тел все 36 значений `Released.HeapAlloc − Before.HeapAlloc` находятся в пределах **−1008…6648 байт**. Малый отрицательный остаток допустим: контейнеры и другая служебная память входили в baseline, затем могли быть освобождены. Эти значения не объявлены точным размером wire body или отсутствием любой другой памяти процесса.

## 3. Равенство полезного результата

Закреплённый helper для каждого работника сравнивает полный `Result` с независимым CMake oracle, проверяет публичные поля и явно объявленную проекцию. Успешное завершение root также означает выполнение конечной повторной проверки исходных oracle/trace/fixture hashes. Reducer дополнительно потребовал одинаковые SHA-256 и длину закодированного тела, число внутренних/публичных записей и capacity во всех образцах соответствующего сценария обоих вариантов.

**Таблица 2. Одинаковые семантические показатели обоих вариантов. Размер тела указан на одного работника.**

| Сценарий | Внутренних записей | Публичных записей | Размер тела, байт | Публичный результат |
|---|---:|---:|---:|---|
| `selected-32` | 32 | 32 | 33 720 | Полезные записи и индексы сохранены |
| `selected-1000` | 1000 | 0 | 919 | Явная проекция четырёх коллекций по существующему ограничению публичного результата |
| `last-marker` | 1 | 1 | 8238 | Полезная последняя запись и индексы сохранены |

Ноль публичных записей у `selected-1000` — предусмотренная исходным oracle проекция; внутренние 1000 записей сохранены. Helper проверил причины, числа пропущенных элементов и отсутствие именно четырёх объявленных коллекций, а не просто принял маленький ответ. Предел публичного тела — **262 144 байта**. Это тело публичного JSON до отдельной транспортной оболочки MCP.

Полные body hashes находятся в `semantics_equal_across_all_rows_by_case` результата. Reducer сравнивает записанные helper хеши и размеры; сами исходные wire-байты отдельными файлами ему не передавались. Более сильная проверка полного семантического результата выполнена внутри закреплённого helper и подтверждается успешными тестовыми событиями.

Каждый вариант содержит три сценария, два количества работников и три образца: 18 строк. Это **45 измеренных вызовов Trace** и ещё три вызова прогрева по структуре успешно завершённого helper. Прогрев не входит в `WorkNanoseconds` строк.

## 5. Сборка мусора и перекрытие работников

GC — garbage collection, сборка мусора. В каждом из 36 наблюдений счётчик `NumGC` увеличился **ровно на два** от `AfterWork` к `ResultsAndWire`, от `ResultsAndWire` к `WireOnly` и от `WireOnly` к `Released`. Reducer требует как минимум два, поскольку автономные циклы могли бы добавить больше. Внутри измеренной работы, от `Before` к `AfterWork`, наблюдалось **8–13 циклов**. Между соседними образцами также проверен новый baseline с дополнительными коллекциями и монотонность кумулятивных счётчиков.

Количество созданных работников не было выдано за доказательство одновременного выполнения. Для каждой строки проверены размер массива интервалов и условие `0 ≤ start ≤ end ≤ WorkNanoseconds` на общей монотонной шкале. По полуоткрытым интервалам вычислены максимальное наблюдаемое перекрытие и пересечение всех работников. Все 18 образцов с четырьмя работниками — девять на вариант — имеют **положительное общее пересечение четырёх интервалов**. Его длительность находится в диапазоне **57.1936–83.7904 мс**. Это наблюдаемое перекрытие, а не обещание одинакового старта или распределения процессорного времени.

## 6. Привязка входов и границы свидетельств

Оба варианта используют **Go 1.27.4, Windows/amd64, GOMAXPROCS=4**. Хеши инструментов совпали. Окружения совпали после явной нормализации только принадлежащих фазам временных/домашних путей. `GOGC`, `GOMEMLIMIT` и `GODEBUG` в предоставленном окружении не заданы; reducer не выдумывает их фактические числовые значения. Сборки используют `GOFLAGS=-mod=readonly` и существующие offline-зависимости, без race-инструментирования.

## 7. Проверка reducer и воспроизведение отчёта

Go `test2json` разделил каждую длинную диагностическую строку на два `output`-события; первые части имеют длину 1024 символа. Reducer восстанавливает строки по имени Test до разбора вложенного JSON. Затем он требует ровно семь полных жизненных циклов тестов и один пакет, 18 уникальных комбинаций case/client/sample в заданном исходниками порядке, точную схему и типы значений, входные хеши, ожидаемые semantic counts, согласованные body hashes и свойства GC/интервалов. Дубли JSON-ключей, недостающие строки, любые fail/skip и неполный вывод отклоняются.

**21 локальная проверка reducer прошла**, включая реальные раздробленные строки, эквивалентность нераздробленной строки, отрицательные мутации для пропущенных/дублированных строк, GC, интервалов, типов, trace/body pin, семантических счётчиков и тестовых событий. Проверки также подтверждают, что малый отрицательный released-baseline delta и дополнительные автономные GC допустимы. Отрицательные примеры создавались только в памяти; исходные журналы не изменялись. Свидетельство: [reducer-selfcheck.json](reducer-selfcheck.json).

Самостоятельное ревью проверило расчёт знаков, единицы, независимые временные границы, отсутствие смешения allocation/retention, соответствие helper/manifest/receipt, сохранение сырых строк и fail-closed поведение при неполных входах. Candidate и runner не менялись. В этой фазе исполнялся только Python для обработки предоставленных данных; новых Go/CMake/удалённых запусков не было.

Повторная обработка тех же закреплённых байтов требует нового выходного пути — существующий результат не перезаписывается:

```text
python r25-audit/cmake/reduce_retention.py --runtime-dir r25-audit/runtime --output <new-result.json>
```

JSON — JavaScript Object Notation. MCP — Model Context Protocol. RSS — resident set size, физически резидентная память процесса; эта диагностика её не измеряет. SHA-256 связывает точные байты; факт исполнения дополнительно опирается на исходные свидетельства runner.
