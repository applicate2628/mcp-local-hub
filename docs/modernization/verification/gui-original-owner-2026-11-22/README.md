# GUI: исходный тестовый процесс и различимые проверки остановки

**22 ноября 2026 года, московское время.** Два сценария принудительной остановки GUI (графического интерфейса) исправлены у существующего владельца [#664](https://github.com/applicate2628/mcp-local-hub/pull/664). Тесты удерживают исходный процесс и дожидаются единственного `Cmd.Wait`; ранний код выхода без фактической остановки больше не удовлетворяет проверке.

**Проверенная область:** три адресных корневых теста Windows с детектором гонок — 10 тестовых/подтестовых PASS и 3 пакетных PASS, FAIL=0, SKIP=0; компиляция CLI-тестов, полные build и vet успешны. Отдельный отрицательный контроль дал ожидаемые exit 1 и два FAIL, которые сохранены. Полные наборы Go и установленный продукт не запускались.

## 1. Дефект и исправление

Прежние `TestForce_KillRewritesPidportWithCurrentPID` и `TestForce_KillRaceLost` создавали внешний sleeper, но не связывали результат сценария с ожиданием исходного процесса. Ошибка во владении fixture могла смешиваться с конкурентной блокировкой или дать ранний результат до нужного шага.

`startForceKillTestSleeper` сохраняет `exec.Cmd` и его `Process`. Одна горутина вызывает `Cmd.Wait`; остановка, cleanup и защитный таймер используют этот же объект. Тест не получает право завершать процесс из нового поиска PID. Setter в `internal/gui/test_seams.go` временно заменяет уже существующий test seam и возвращает восстановление предыдущего значения; новых глобальных переменных нет.

Rewrite теперь требует наблюдаемую активную запись с текущим PID и именно запрошенным свободным портом. RaceLost требует завершение Wait до post-kill hook, ровно один вызов остановки, один hook, реально полученную конкурентную блокировку и типизированный код 3. Ошибка очистки или превышение срока остаётся ошибкой даже внутри дерева причин, содержащего отмену.

Изменены **два файла**, 280 добавленных и 132 удалённых строки. Остальные байты тестового файла проверены восстановлением исходника после вычитания точных добавлений. Производственный алгоритм остановки по PID этим изменением не переработан.

Обёртка сохраняет исходные потоки, команды, момент запуска, завершение и отдельную проверку ожидаемого результата. Контроль заменяет только возврат `stopHolder()` в callback на no-op. Исходная cleanup с `Process.Kill` и единственным Wait остаётся. Совпадение отрицательного оракула отмечено отдельно и не меняет FAIL на PASS.

Для двух положительных native-сценариев и контроля проверено по одному сообщению запуска и завершения исходного helper с закреплённым путём образа. Все прямые процессы команд завершились без таймаута. Сводные результаты доступны в [qualification.json](qualification.json).

## 4. Архив и воспроизводимость

[gui-owner-evidence.zip](gui-owner-evidence.zip) содержит **28 записей**, в том числе отдельный исходный Windows-архив с 1346 записями. Внешний архив: **766200 байт**, SHA-256 `7b5cb19644e66910e4dd69e077c361c79845b8087e2d9771f0545c9c08788010`, Git blob `2e5050d5c856399c90b33875df535807508fa9d6`. Размеры, суммы и порядок проверки — [archive.json](archive.json).

Сохранены все девять фаз, исходные/launch/final records команд, stdout/stderr, Go JSON, три отдельных набора original/formatted/control, физические preimage, исходники runner/formatter/exporter и доказательства точного состава. Незавершённая фаза или несовпадение исходного потока блокировали создание архива. После получения проверены CRC, длина и SHA-256 каждого члена обоих архивов. Исполнимые файлы, рабочие профили, кэши и частные диагностические файлы в комплект не входят.

Документы `gui-owner-candidate` внутри ZIP сохраняют своё первоначальное состояние **до исполнения**. Они не переписаны задним числом; фактические результаты приведены в таблице 2 и исходных квитанциях. Перенос подтверждённо избыточной Base64-копии в trash зафиксирован отдельно; единственный нужный ZIP и доказательства сохранены вне trash.

Идентичность публикации бинарного архива проверяется по ожидаемому Git blob при загрузке и по дереву опубликованного коммита. Повторное скачивание бинарного ZIP через GitHub connector не заявляется. Проверка текста, дерева, родителя и полного diff публикации оформляется отдельной квитанцией обратного чтения.

## 5. Ревью и оставшиеся границы

Основной исполнитель самостоятельно прочитал полный diff, изменённые тесты, TestMain, сценарий команды и запуск GUI-сервера, проверил требования, корректность, безопасность, совместимость и сложность. Полный текст собственного ревью сохранён в архиве. Успешные адресные проверки не заменяют производственную квалификацию.

Открыты: производственная остановка по PID, завершение всех работников GUI, общий deadline и завершение дерева процессов, POSIX, полные обычный и tagged наборы Go, допустимые CMake/Hyperfine/oneAPI и Product/Serena-входы, установленный продукт. В ранних ветвях отмены возврат команды GUI сам по себе не доказывает присоединение всех работников. Ни один из этих пунктов данным инкрементом не закрывается.

Общий порядок и остальные критерии находятся в [действующем плане](../../../../.plans/2026-11/open-pr-integration-20261117.md) и [отчёте предыдущего P0](../p0-safe-test-gates-2026-11-21/README.md).

## 6. Термины

PR — запрос на включение изменений; GUI/CLI — графический интерфейс/командная строка; PID — идентификатор процесса; SHA-256 — контрольная сумма; Git blob/tree — идентификатор содержимого файла/дерева. Overlay — явно перечисленная подмена файла на неизменной физической базе. Fixture — собственный тестовый вход. PASS/FAIL/SKIP/NOT_RUN — успех/отказ/пропуск/не запускалось. `-race` включает детектор гонок Go. Ожидание `Cmd.Wait` относится к исходному запущенному процессу; оно не тождественно доказательству завершения всего его дерева.
