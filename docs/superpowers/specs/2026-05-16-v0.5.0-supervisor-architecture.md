# v0.5.0 mcp-local-hub supervisor architecture

**Status:** Accepted spec, v6 (revised after deep-sec review rounds
1–5 — total 11× P0 + 55× P1 + 20× P2 surfaced across drafts). v6
addresses Round 5 findings: reconcile-prune identity uses BARE
task-name form (matches production `install.go:1092` + 1639-1642);
`mcphub strict-mode` exits with explicit `STRICT_MODE_BUSY` when
locks are held; `lookupProcessIdentity` helper carries basename +
CommandLine for the 3-gate ownership check; supervisor-events.log
envelope mirrors `gui_event_log.go` byte-symmetric (`schema_version`
string + `body` key); `supervisor.lock` lives in NEW
`internal/api/supervisor_lock.go` so the CLI body doesn't import
`internal/gui`; named-pipe transport authorized as
`github.com/Microsoft/go-winio` dependency; strict-mode two-resource
mutation pins write order + rollback semantic; `quiesce-timers` IPC
command introduced for graceful transient drain; canonical-template
snapshot rendered by v0.4.x-pinned template renderer; v0.4.x
`ChronicCycles` history clean slate documented as intentional;
resume re-uses existing journal intent; `exiting` state rows added
to transition table; netstat snapshot cached per migration; DST +
laptop-sleep catch-up in maintenance evaluator; `rollback-warnings.json`
schema pinned; supervisor child spawn uses NEW
`process.StartWithJob` for assign-at-create.

**Date:** 2026-05-16

**Goal:** Replace the N-scheduled-tasks-per-daemon architecture of
v0.4.x with one `mcphub supervise` long-lived parent process that
owns every MCP daemon as a child process under an OS-appropriate
lifecycle primitive (Windows Job Object — strong containment; Linux
`PR_SET_PDEATHSIG` direct-child or systemd-user-service with
control-group kill — beta; macOS process group + kqueue observation
or LaunchAgent-owned restart — preview).

**Motivation:**

- **Process tail compression** — operator sees one `mcphub.exe`
  plus N children instead of N scheduler-managed orphans on crash.
- **Atomic upgrade story** — old supervisor exits, new supervisor
  reconciles, ~10s blip via MCP client retry semantics.
- **Removes the v0.4.x corrupt-state self-quarantine machinery** —
  no 5-min watchdog poll cadence; child-exit observation is
  immediate.
- **Cross-platform foundation** — by removing Windows-specific
  Task Scheduler dependency, mcphub becomes a CLI tool that runs
  from any shell. The supervisor binary IS the lifecycle primitive.

Optional managed modes (`--linux-managed` / `--darwin-managed`) tie supervisor lifecycle to the init system; operator should not invoke from shell in those modes. | Removes the v0.4.x "lifecycle = scheduler entry" model. |
| Q8 | Autostart-at-logon | **Three independent per-OS backend contracts under one CLI surface: `mcphub autostart {enable, disable, status}`.** Windows backend: Task Scheduler logon-trigger; strict-mode shim arg `<Arguments>supervise --strict-mode</Arguments>` (Task Scheduler `execType` schema has no `<Environment><Variable>` per `scheduler_windows.go:106-153`). Linux backend: systemd user unit; `--linux-managed` upgrades to `KillMode=control-group`. macOS backend: LaunchAgent plist; `--darwin-managed` ties supervisor lifecycle to launchd. **Strict-mode mutation has ONE canonical command**: `mcphub strict-mode {enable, disable}`. Refuse-if-held with explicit exit code beats silent block. Write order + rollback prevents the v4 split-brain class. |

### Package ownership

- **`internal/cli/supervise.go`** — `mcphub supervise` cobra command. Hosts FIFO event loop, reconcile driver, IPC listener wiring, child-exit reaper. Imports `internal/api`, `internal/process`, `internal/scheduler`. **Does NOT import `internal/gui`.**
- **`internal/api/supervisor_intent.go`** — `supervisor-intent.json` types + atomic read/write.
- **`internal/api/supervisor_state.go`** — `supervisor-state.json` types + read/write.
- **`internal/api/supervisor_events.go`** — JSONL event-log helper; envelope byte-symmetric with `internal/api/gui_event_log.go:19-25` (`schema_version` string + `body` key).
- **`internal/api/supervisor_ipc.go`** — IPC types (request/response JSON), wire encoding, handshake validator. Pure types + helpers; no listener body.
- **`internal/api/supervisor_lock.go`** — NEW `supervisor.lock` singleton primitive (PID + start_time, stale-PID detection). Generalized from `internal/gui/single_instance.go`. Available for `mcphub supervise` and for the IPC client (handshake pre-read).
- **`internal/api/dacl_shared_windows.go`** — extracted shared SID allowlist + SECURITY_DESCRIPTOR builder used by both `SecureWriteClientConfig` and named-pipe creation.
- **`internal/process/jobobject_windows.go`** — existing file extended for `process.StartWithJob` (assign-at-create via `STARTUPINFOEX` + custom `syscall.CreateProcess` wrapper). Existing post-Start `Assign` preserved for non-supervisor callers.
- **`internal/process/start_with_job_windows.go`** — NEW. Wraps `syscall.CreateProcess` with `STARTUPINFOEX.lpAttributeList` carrying `PROC_THREAD_ATTRIBUTE_JOB_LIST` so the child enters the supervisor's Job Object atomically.

## State file architecture (detail)

### managed-entries.json (existing — preserved)

- Owner: `internal/api/managed_entries.go`.
- Root shape: `{"version": int, "entries": [{client, server, installed_at}]}`.
- v0.5.0: read-only from supervisor.

### daemon-intent.json (existing — preserved exactly)

- Owner: `internal/api/daemon_intent.go`.
- Root shape: `{"tasks": map[string]DaemonIntent}` only (`daemon_intent.go:231-233`). No `version`, no top-level `updated_at`. `DisallowUnknownFields()` at line 577 rejects extras.
- Per-entry: `{"desired", "reason", "updated_at"}` per `daemon_intent.go:219-223`.
- Keys: canonical leading-backslash per `canonicalIntentTaskKey` at `daemon_intent.go:275-283`.
- `reason`: `user-stop` (TTL'd via `IsActiveStop(now)`), `user-disabled` (permanent), `chronic-failure` (auto-set by recovery).
- v0.5.0 supervisor reads unchanged via existing `ReadDaemonIntent`. Byte-symmetric for rollback.

### supervisor-intent.json (NEW)

- Owner: `internal/api/supervisor_intent.go`.
- Schema version 1:

  ```json
  {
    "version": 1,
    "updated_at": "RFC3339Nano",
    "daemons": [
      {
        "task_name": "\\mcp-local-hub-memory-default",
        "server": "memory",
        "daemon": "default",
        "command": "node",
        "args": ["./mcp-memory-server.js"],
        "env": { "MEMORY_PATH": "..." },
        "workspace": "C:\\Users\\...\\repo",
        "port": 9128,
        "manifest_hash": "sha256:..."
      }
    ],
    "maintenance_timers": [
      {
        "name": "\\mcp-local-hub-workspace-weekly-refresh",
        "kind": "workspace-weekly-refresh",
        "command": "mcphub.exe",
        "args": ["workspace-weekly-refresh"]
      }
    ],
    "strict_mode": false
  }
  ```

- `task_name` is the canonical leading-backslash form (storage shape). Reconcile-prune diff strips the prefix at compare time (Q12).
- No `principal` field, no `settings.priority`. Non-current-user RunAs classified as Unsupported in migration; default priority inherits as `NORMAL_PRIORITY_CLASS` (no `SetPriorityClass` infra in v0.5.0).
- Fixed-cadence maintenance timers — no cron parser. Two `kind` values: `workspace-weekly-refresh`, `server-weekly-refresh`. Both fire Sunday 03:00 local with DST + sleep catch-up (see maintenance timer scheduler section).
- **Unknown `kind` is forward-compat-safe**: logged `warn` with event `unknown-maintenance-kind` and skipped; the file is NOT quarantined.
- `strict_mode`: canonical truth. Mutated only via `mcphub strict-mode {enable, disable}` (Q8).
- Write: atomic via shared state-file helper. Read: supervisor on start + reload.

### supervisor-state.json (NEW)

- Owner: `internal/api/supervisor_state.go`.
- Schema version 1:

  ```json
  {
    "version": 1,
    "daemons": {
      "\\mcp-local-hub-memory-default": {
        "state": "running",
        "current_pid": 12345,
        "pid_generation": 7,
        "started_at": "RFC3339Nano",
        "restart_history": [
          {"at": "RFC3339Nano", "exit_code": 1, "signal": null}
        ],
        "backoff_until": "RFC3339Nano",
        "quarantine_since": "RFC3339Nano",
        "queued_action": null
      }
    },
    "transient_pids": [
      {"pid": 23456, "kind": "workspace-weekly-refresh", "started_at": "RFC3339Nano"}
    ],
    "maintenance_fired_at": {
      "workspace-weekly-refresh": "RFC3339Nano",
      "memory-weekly-refresh": "RFC3339Nano"
    }
  }
  ```

- `daemons[*].queued_action`: optional `{kind: "respawn"|"none", reason}` recording pending action while in `exiting` state; cleared on transition out of `exiting`.
- `transient_pids[*]`: maintenance-timer fire-and-forget children that are NOT Job Object members. Used by `quiesce-timers` IPC + graceful exit + cold-start reaper.
- `maintenance_fired_at[kind]`: last successful fire timestamp per timer; used by the DST/sleep catch-up evaluator.
- Write: every state transition flushed BEFORE side effect.
- Read: supervisor on start.

### supervisor-events.log (NEW)

- Owner: `internal/api/supervisor_events.go`. Envelope byte-symmetric with `internal/api/gui_event_log.go:19-25`.
- Schema version 1:

  ```json
  {
    "schema_version": "1",
    "ts": "RFC3339Nano",
    "severity": "debug|info|warn|error",
    "source": "ipc|lifecycle|restart-policy|migration|autostart|reconcile",
    "event": "...",
    "task_name": "\\mcp-local-hub-...",
    "body": { "..." }
  }
  ```

- `severity`: `info` normal; `warn` recoverable; `error` unrecoverable per-daemon; `debug` env-gated.
- Per-entry size cap matches `internal/api/watchdog_log.go:25-36`: 16 KB hard cap; identity fields never truncated; non-identity oversize truncates longest field with `_truncated:true`.
- 10 MB rotation with single `.log.1`; rotation entry `event: "log-rotated"` written to new file.
- Flock-protected appends for concurrent IPC / reconcile / restart-policy / migration writers.

### watchdog-state.json (existing — preserved unchanged)

- Owner: `internal/api/watchdog_state.go`. Fields per `watchdog_state.go:276-281` with DisallowUnknownFields.
- v0.5.0 supervisor does NOT extend or write. Diagnostic surface via existing `mcphub watchdog status`.
- **`CooldownEntry.ChronicCycles` counter at `watchdog_state.go:266` is NOT seeded into supervisor-state.** After v0.4.x → v0.5.0 migration, `mcphub watchdog enable --server X` clears the daemon-intent stop intent and the supervisor's failure window starts fresh — quarantine cycle restarts from zero instead of pre-loaded. **This is intentional**: v0.5.0 explicit operator action via `watchdog enable` indicates the operator has investigated and wants a clean slate. Documented in `mcphub watchdog enable --help`: "After migration from v0.4.x, this resets the failure window for the named server; supervisor will quarantine again after 10 failures in 30 min."

## Migration journal (detail)

### Journal layout

```text
<state-dir>/migration-journal-<UTC-timestamp>/
  prepared
  pre-os-mutating                # AFTER first successful kill
  os-mutating-complete
  committed
  legacy-tasks/<task>.xml ...
  legacy-tasks-classification.json
  canonical-template-snapshot.xml          # rendered by v0.4.x-pinned template
  pre-migration-strict-mode
  derived-supervisor-intent.json
  killed-daemons.json
  netstat-cache.json                       # netstat -ano snapshot, refreshed after each kill
```

### Lock ordering

1. `migration.lock` (flock, exclusive).
2. `--once.lock` (flock, exclusive) per `internal/cli/watchdog.go:498-529`.

**Universal contract**: every v0.5.0 lock acquirer takes `migration.lock` BEFORE `--once.lock`. LIFO release. Refuse-if-held in `mcphub install` exits with `INSTALL_BUSY` (exit 8); refuse-if-held in `mcphub strict-mode` exits with `STRICT_MODE_BUSY` (exit 9).

### XML deviation-only classification

The canonical-template-snapshot is rendered by the **v0.4.x-pinned template renderer** at `internal/migration/v04x_template_defaults.go`, NOT by the v0.5.0 install code. The pinned renderer covers v0.4.0..v0.4.x default field values:

- `MultipleInstancesPolicy`: v0.4.0..v0.4.2 emits `IgnoreNew`; v0.4.3+ emits `StopExisting` (per `scheduler_windows.go:106-153` historical inline comment dated 2026-05-07). Classifier checks both values as defaults.
- `<RestartOnFailure>` count + interval at default values.
- All other fields rendered exactly as the v0.4.x template.

For each `mcp-local-hub-*` task enumerated via `EnumerateAllMcphubTasks()` (independent of current-user filter at `scheduler_windows.go:341-356`), classify each XML field against the pinned-template defaults:

**Default match → silently preserved.**

**Deviation preserved through supervisor + autostart shim:**

- `Settings.RunOnlyIfNetworkAvailable` (true when operator flipped) → supervisor delays spawn until network reachability check passes.

**Deviation preserved through autostart shim only:**

- Non-LogonTrigger triggers on the supervisor's own shim (the supervisor itself is autostarted via the shim).

**Deviation that aborts migration (unless `--discard-scheduler-customizations`):**

- `Principal.UserId` not equal to current Windows user.
- `Principal.LogonType` other than `InteractiveToken`.
- Custom `<Actions>` other than the v0.4.x canonical single `<Exec>`.
- `IdleSettings.StopOnIdleEnd=true`, `WakeToRun=true`, `RunOnlyIfIdle=true`.
- `<Priority>` deviation from `7` → silently dropped on migration with one warning line per affected task (no `SetPriorityClass` infrastructure in v0.5.0; default child priority is `NORMAL_PRIORITY_CLASS` which is what `<Priority>7</Priority>` maps to).

**Unknown XML element → warning line plus preservation through autostart shim XML** (forward-compat for v0.4.x updates that ship new schema fields).

### Pre-unregister daemon stop

For each legacy `mcp-local-hub-*` daemon task (NOT weekly-refresh / watchdog tasks):

1. Parse legacy task XML `<Exec>` argv to get `--server` and `--daemon`.
2. Resolve expected port via `portForTask(normalized, manifestPortMap(""), workspaceTasksByName())` — same lookup the production `stopKillCore` uses at `install.go:1869`.
3. **Resolve PID + basename + CommandLine via NEW `lookupProcessIdentity(port)`** — extends `lookupProcess` at `internal/api/processes.go:283-309` to also shell `wmic process where ProcessId=... get Name,CommandLine,CreationDate`. Returns `(pid, basename, commandLine, createdUnix, ok)`. **Reads the `netstat -ano` snapshot from `netstat-cache.json` (refreshed once per kill loop iteration)** to avoid O(N tasks × full netstat scan) cost on AV-instrumented hosts. **3 retries spaced 1s apart if `ok=false`** — covers transient AV-scanner stalls; if still `ok=false` after retries AND no `mcphub.exe daemon --server X --daemon Y` is in the system-wide process list (via a separate `wmic process get Name,CommandLine` snapshot), treat as unbound and skip. If a matching `mcphub.exe daemon` IS in the process list but port lookup keeps returning `ok=false`, abort with `MIGRATION_PORT_LOOKUP_INCONSISTENT` and retry guidance.
4. 3-gate ownership check using basename + commandLine + createdUnix from step 3:
   - Image basename = `mcphub.exe` (Windows) or `mcphub` (POSIX).
   - CommandLine contains `daemon --server <server> --daemon <daemon>`.
   - createdUnix precedes `migration.lock` acquisition time.
5. If gate passes, append `{pid, server, daemon, start_time, port}` to `killed-daemons.json`.
6. **`touch pre-os-mutating` on the FIRST successful pass through this step** (atomic check-and-touch on every iteration; after the first kill, the marker file exists and subsequent touches are no-ops).
7. **`taskkill /PID <pid> /F /T`** (Windows — `/T` critical because hub.exe spawns npx/uvx grandchildren per `internal/api/install.go:2163-2174`). POSIX: SIGTERM to process group (`kill -- -<pgid>`), then SIGKILL after 5s.
8. Wait up to 10s for the port to release via repeated `lookupProcessIdentity(port)` polling (re-using the netstat cache, refreshed after each kill).
9. If port still bound after 10s, abort migration with the exact port + PID + retry guidance.

If there are no daemons to kill at all (corner case: every daemon already dead at migration start), `touch pre-os-mutating` happens immediately before step 10 of the forward sequence below.

### Forward migration steps

1. Acquire `migration.lock` (refuse-if-held → `INSTALL_BUSY`).
2. Acquire `--once.lock` (refuse-if-held → blocks v0.4.x watchdog --once concurrent attempts).
3. Enumerate ALL `mcp-local-hub-*` tasks via `EnumerateAllMcphubTasks()`.
4. **Render canonical template snapshot via v0.4.x-pinned renderer** to `canonical-template-snapshot.xml`.
5. Export each task's raw XML to `legacy-tasks/<task>.xml`.
6. Classify XML deviations against snapshot. Abort if any lands in the "abort" bucket and `--discard-scheduler-customizations` was not passed.
7. Derive `supervisor-intent.json`. **If `derived-supervisor-intent.json` already exists in the journal (resume case), re-use it instead of re-deriving** (preserves operator edits during long pauses between crash and resume).
8. `touch prepared`.
9. Pre-unregister daemon stop loop (kills + retries + cache refresh + pre-os-mutating-on-first-kill per the section above).
10. Stop and unregister each legacy task via `schtasks /Delete`.
11. `touch os-mutating-complete`.
12. Install supervisor autostart shim (per Q8). Includes `--strict-mode` CLI arg if pre-migration strict-mode was 1.
13. Explicitly start supervisor per the cold-restart upgrade flow.
14. Wait for supervisor reconcile-ready via IPC `status` within 30s (reconcile-ready = IPC listener accepting + intent files read + first reconcile pass scheduled; NOT all-daemons-healthy). On timeout: auto-rollback with reason `forward-migration-supervisor-not-ready`.
15. `touch committed`.
16. Release `--once.lock` (LIFO).
17. Release `migration.lock` (LIFO).

### Rollback steps (`mcphub install --rollback-to-legacy`)

1. Acquire `migration.lock`.
2. **Issue IPC `quiesce-timers`** to supervisor — refuses new timer fires and waits for in-flight transient PIDs to complete naturally, up to 30s. Returns `{drained: N, still_running: [pids]}`.
3. **Issue IPC `exit{graceful: true, timeout_ms: 5000}`** — supervisor's exit handler terminates any still-running transient PIDs (now bounded; max 5s grace) plus daemon children. Fall back to force-kill on timeout (look up PID from `supervisor.lock`).
4. Acquire `--once.lock`.
5. Find latest `migration-journal-*/` directory with `committed` (or `pre-os-mutating` for partial rollback).
6. Read current `supervisor-state.json`. For each entry in `quarantined`, write `daemon-intent.json` entry `reason=chronic-failure, desired=stopped` via existing `WriteDaemonIntent` (canonicalizes the key).
7. **Uninstall supervisor autostart shim unconditionally** (idempotent — missing shim is silent success). Avoids any same-name collision with restored legacy XML at step 8.
8. For each `legacy-tasks/<task>.xml`: re-register via `schtasks /Create /XML /F`.
9. Run each restored daemon task via `schtasks /Run /TN <task>`.
10. **Wait up to 60s** per task for the expected port to bind. Tasks not bound after 60s appended to `rollback-warnings.json`.
11. Delete `supervisor-intent.json` + `supervisor-state.json` + `supervisor-events.log`.
12. Release `--once.lock` (LIFO).
13. Release `migration.lock` (LIFO).

**`rollback-warnings.json` schema (version 1):**

```json
{
  "version": 1,
  "warnings": [
    {
      "task": "\\mcp-local-hub-memory-default",
      "port": 9128,
      "reason": "port-not-bound-after-60s",
      "observed_at": "RFC3339Nano"
    }
  ]
}
```

**Exit semantic:** Rollback exits **0** (success-with-warnings) even when `rollback-warnings.json` has entries. Non-zero exit reserved for "rollback itself failed" (XML re-register error, journal corrupted, lock acquire failure). Operator inspects warnings file and retries per-task `schtasks /Run` as needed.

### Resume / partial-state recovery

Markers progress: `prepared` → `pre-os-mutating` → `os-mutating-complete` → `committed`.

- **`prepared` only:** no OS state touched → safe to abort and delete journal.
- **`pre-os-mutating` but no `os-mutating-complete`:** at least one daemon killed. Forward-resume re-uses existing `derived-supervisor-intent.json` if present and well-formed (preserves operator edits); enumerates ALL `mcp-local-hub-*` tasks via `EnumerateAllMcphubTasks` and probes each task's port via `lookupProcessIdentity`. Logs `event: migration-resume-rederiving-intent` only if re-derive fires. Rollback path: re-register from XML snapshots + run restored tasks + verify ports.
- **`os-mutating-complete` but no `committed`:** legacy tasks unregistered, supervisor maybe not running. Operator picks forward retry or rollback.

## Fresh install flow (detail)

### When this applies

- No `<state-dir>` exists, OR
- `<state-dir>` exists but contains no `mcp-local-hub-*` tasks, no `supervisor-intent.json`, and no migration journal directories.

### Fresh install sequence

1. Acquire `migration.lock` (refuse-if-held → `INSTALL_BUSY`).
2. Acquire `--once.lock` only if a v0.4.x watchdog task exists on disk (defensive).
3. Write `supervisor-intent.json`.
4. (Optional) `--autostart` flag → install autostart shim per Q8.
5. Explicitly start supervisor (per cold-restart upgrade flow step 6). On failure: cleanup shim if installed at step 4, leave `supervisor-intent.json` on disk for retry, release locks LIFO, exit non-zero with retry command.
6. Wait reconcile-ready via IPC `status` within 30s.
7. Release `--once.lock` (LIFO) if acquired.
8. Release `migration.lock` (LIFO).

### `--no-start` contract

`mcphub install --no-start` writes intent + optionally installs shim but does NOT start supervisor. Intended for CI / fleet-provisioning. Prints exact start command. Default is implicit `--start`.

## Cold-restart upgrade flow (detail)

### Windows binary replacement (rename-aside)

1. Write new binary to `<install-dir>/mcphub.exe.new`.
2. `MoveFileExW(target, target + ".old-<ts>", REPLACE_EXISTING)` — rename the running binary out of the way (Windows allows rename of executing image because the loader uses `FILE_SHARE_DELETE`).
3. `MoveFileExW(target + ".new", target, 0)` — atomic rename of new binary into place.
4. Schedule cleanup of `target.old-<ts>` for the next upgrade or supervisor restart.

POSIX: atomic `rename(2)`.

### Upgrade sequence

1. Replace binary atomically.
2. Connect to supervisor IPC. Client reads `supervisor.lock` for expected `{pid, start_time}` FIRST.
3. Issue IPC `quiesce-timers` (drains transients up to 30s).
4. Issue IPC `exit{graceful: true, timeout_ms: 5000}`.
5. Supervisor terminates remaining transients (force-kill after 5s grace) and daemon children, then exits with code 0.
6. **`mcphub install` explicitly starts the new supervisor.** Per-OS:
   - Windows: `schtasks /Run /TN \mcp-local-hub-supervisor` if shim installed; else launch `mcphub.exe supervise [--strict-mode]` as detached child via `CreateProcess` with `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`. **Note**: `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP` makes the supervisor unable to receive `CTRL_C_EVENT` from any other process (per Microsoft docs); graceful shutdown is **exclusively via IPC `exit`**. Task Manager End Task → un-graceful Job Object close; `KILL_ON_JOB_CLOSE` reaps children.
   - Linux managed: `systemctl --user restart mcphub-supervisor.service`.
   - Linux unmanaged: `mcphub supervise [--strict-mode] &`.
   - macOS managed: `launchctl kickstart -k gui/<uid>/com.applicate2628.mcphub-supervisor`.
   - macOS unmanaged: `mcphub supervise [--strict-mode] &`.
7. New supervisor starts → reads intent + daemon-intent → reconcile → respawns daemons.
8. Operator sees ~10s blip via MCP client retry semantics.

### Fallback if step 4 IPC fails

- Force-kill prior supervisor PID (look up `supervisor.lock`; `taskkill /F /T /PID` if PID alive with matching start_time).
- Run cold-start stale-child reaper (Linux/macOS default modes). Reaper waits 2-3 seconds after each kill for TCP TIME_WAIT before the new supervisor's first reconcile spawn.
- Proceed to step 6.

## Restart policy state machine (detail)

Supervisor runs a **single-threaded FIFO event loop**: events from IPC, child_exit, timers, and intent-file watchers serialize through one channel. No concurrent-event tie-breakers needed.

### States

- `idle`, `spawning`, `running`, `exiting`, `backoff-waiting`, `quarantined`.

### Events

- `child_exit{pid, exit_code, signal}`, `timer_due{kind}`, `intent_update{task_name, new_intent}`, `manual_restart{task_name}`, `supervisor_restart`.

### Transition table

`failures` = `child_exit` count in trailing 30-min sliding window per `(task_name)`. `gen_match` = `child_exit.pid` matches `supervisor-state.daemons[task_name].current_pid`. `queued_action` field in supervisor-state is set during `exiting` transitions to record what should happen after the child actually exits.

| From | Event | Guard | To | Side effect | Persist when |
| --- | --- | --- | --- | --- | --- |
| idle | (start) | intent.desired=running AND NOT IsActiveStop(now) | spawning | bump pid_generation, create-process | BEFORE create-process |
| idle | intent_update | new.desired=stopped | idle | none | n/a |
| idle | intent_update | new.desired=running (TTL refreshed) | spawning | bump pid_generation, create-process | BEFORE create-process |
| idle | manual_restart | intent.desired=running AND NOT IsActiveStop(now) | spawning | bump pid_generation, create-process | BEFORE create-process |
| idle | manual_restart | intent.desired=stopped OR IsActiveStop(now) | idle | reject IPC with `RESTART_REFUSED_INTENT_STOPPED` | n/a |
| spawning | (health check OK) | first probe success | running | none | AFTER probe OK |
| spawning | child_exit | gen_match | backoff-waiting | arm timer at backoff(failures) | BEFORE timer arm |
| spawning | child_exit | NOT gen_match | spawning | drop event (stale PID) | n/a (log only) |
| running | child_exit | gen_match | backoff-waiting | arm timer | BEFORE timer arm |
| running | child_exit | NOT gen_match | running | drop event | n/a (log only) |
| running | intent_update | new.desired=stopped | exiting | issue terminate, set queued_action=none | BEFORE terminate |
| running | manual_restart | always | exiting | issue terminate, set queued_action=respawn | BEFORE terminate |
| exiting | child_exit | queued_action=respawn | spawning | bump pid_generation, create-process | BEFORE create-process |
| exiting | child_exit | queued_action=none | idle | none | AFTER state write |
| exiting | manual_restart | always | exiting | coalesce — set queued_action=respawn | BEFORE persist |
| exiting | intent_update | new.desired=stopped | exiting | clear queued_action | BEFORE persist |
| exiting | intent_update | new.desired=running | exiting | set queued_action=respawn | BEFORE persist |
| exiting | timer_due | always | exiting | log + ignore (terminator in flight) | n/a |
| backoff-waiting | timer_due | failures < 10 | spawning | bump pid_generation, create-process | BEFORE create-process |
| backoff-waiting | timer_due | failures >= 10 | quarantined | clear timer | BEFORE clear |
| backoff-waiting | intent_update | new.desired=stopped | idle | cancel timer | BEFORE cancel |
| backoff-waiting | intent_update | new.desired=running (TTL refreshed) | spawning | cancel timer, bump pid_generation, create-process | BEFORE create-process |
| backoff-waiting | manual_restart | always | spawning | cancel timer, bump pid_generation, create-process | BEFORE create-process |
| quarantined | intent_update | new.desired=stopped | idle | none | n/a |
| quarantined | intent_update | new.desired=running (TTL refreshed) | spawning | reset failures, bump pid_generation, create-process | BEFORE create-process |
| quarantined | manual_restart | always | spawning | reset failures, bump pid_generation, create-process | BEFORE create-process |
| (any) | supervisor_restart | persisted state=quarantined | quarantined | none | done via load |
| (any) | supervisor_restart | persisted backoff_until > now AND failures < 10 | backoff-waiting | re-arm timer at absolute backoff_until | done via load |
| (any) | supervisor_restart | persisted backoff_until <= now AND intent.desired=running AND NOT IsActiveStop(now) | spawning | bump pid_generation, create-process | BEFORE create-process |
| (any) | supervisor_restart | persisted intent.desired=stopped | idle | none | done via load |

Backoff schedule: 0s, 0s, 0s (immediate first 3) then 5s, 15s, 60s, 5min, 30min capped.

## Maintenance timer scheduler (detail)

Supervisor schedules `supervisor-intent.maintenance_timers` via an in-process fixed-cadence evaluator.

### Two cadence kinds (v0.5.0)

- `workspace-weekly-refresh`: Sunday 03:00 local time. Fires `mcphub.exe workspace-weekly-refresh`.
- `server-weekly-refresh`: Sunday 03:00 local time. Fires `mcphub.exe restart --server <server>`.

No cron parser. New kinds in future versions get new in-tree evaluators (not a generic cron parser).

### DST + sleep catch-up

Naive "fire at Sun 03:00 local" misses spring-forward (skipped 02:00-03:00) and double-fires on fall-back. Laptop sleep across Sat-Mon misses entirely.

Catch-up algorithm:

1. Persist `last_fired_at[kind]` in `supervisor-state.maintenance_fired_at`.
2. Every supervisor tick (60s reconcile poll), for each timer:
   - Compute `next_due` = next Sun 03:00 local on or after `last_fired_at[kind]`.
   - If `now >= next_due` AND `(now - next_due) <= 6 hours` (Sun 03:00..09:00 window), fire and set `last_fired_at[kind] = now`.
   - If `now >= next_due` AND `now > next_due + 6 hours`, fire ONCE for the missed window and set `last_fired_at[kind] = now` (this catches laptop sleep across the weekend).
3. Track explicit `last_fired_at` per kind, not a counter, so DST-induced duplicate window doesn't fire twice.

Estimated implementation: ~60-80 LoC (not the 30-LoC claim earlier drafts made).

### Single-run guard

Per-timer in-process mutex prevents overlap: if a timer fires while the previous fire's transient child is still running, the new fire is skipped with one warning line.

### Transient child tracking

Every timer fire spawns a child detached from the supervisor's Job Object. PID + kind + started_at recorded in `supervisor-state.transient_pids` BEFORE the syscall (so resume sees it). On supervisor graceful exit, the `quiesce-timers` IPC command drains transients first (up to 30s), then `exit{graceful}` forcibly terminates any remaining (5s grace).

On supervisor crash, transient children outside Job Object survive. Cold-start reaper on next supervisor start checks each `transient_pids` entry: if PID is still alive AND owned by the operator (3-gate ownership), kill it; in any case remove from `transient_pids`.

### Unknown kind forward-compat

Reading `supervisor-intent.maintenance_timers` with an unknown `kind` value: log `severity: warn, event: unknown-maintenance-kind` with the offending entry; skip the entry; **do NOT quarantine the file**. Forward compat over strictness for this nested array.

## Control IPC trust boundary (detail)

### Transport

- Windows: `github.com/Microsoft/go-winio` named-pipe listener with SECURITY_DESCRIPTOR carrying the shared SID allowlist + `GENERIC_READ | GENERIC_WRITE` ACE mask.
- POSIX: unix socket at mode 0600 + owner-uid check.

### Wire format

Newline-delimited JSON.

Request:

```json
{"id": 42, "cmd": "status"}
{"id": 43, "cmd": "exit", "args": {"graceful": true, "timeout_ms": 5000}}
{"id": 44, "cmd": "restart", "args": {"server": "memory", "daemon": "default"}}
{"id": 45, "cmd": "reload"}
{"id": 46, "cmd": "quiesce-timers", "args": {"timeout_ms": 30000}}
```

Response:

```json
{"id": 42, "ok": true, "result": { "daemons": [] }}
{"id": 43, "ok": true, "result": "exit-acked"}
{"id": 44, "error": {"code": "RESTART_REFUSED_INTENT_STOPPED", "message": "..."}}
{"id": 46, "ok": true, "result": {"drained": 1, "still_running": []}}
```

### Handshake

Client reads `supervisor.lock` for expected `{pid, start_time}` FIRST, then opens connection. Supervisor sends `hello` frame on connect; client validates pid + start_time against pre-read; mismatch closes connection.

### Audit

Every command write-through to `supervisor-events.log` (JSONL) as `source: "ipc"`:

```json
{"schema_version":"1","ts":"...","severity":"info","source":"ipc",
 "event":"ipc-command","body":{"cmd":"exit","args":{},"caller":{"pid":99},"result":"ok"}}
```
