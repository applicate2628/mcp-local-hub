# v0.5.0 mcp-local-hub supervisor architecture

**Status:** Accepted spec, v7 (revised after deep-sec review rounds
1–6 — total 12× P0 + 64× P1 + 28× P2 surfaced across drafts). v7
addresses Round 6 findings: rollback IPC-timeout force-kill uses
`/T` tree-kill (matches production at `install.go:2163-2174`);
`EnumerateAllMcphubTasks` is a package-level function, not an
interface method; Windows API names corrected to the
`golang.org/x/sys/windows` surface (`windows.StartupInfoEx`,
`windows.NewProcThreadAttributeList`, `EXTENDED_STARTUPINFO_PRESENT`);
`procThreadAttributeJobList = 0x0002000D` defined locally because
it is not exported by `x/sys/windows`; `wmic` deprecation on Win11
24H2+ addressed via PowerShell `Get-CimInstance Win32_Process`
fallback; `quiesce-timers` deadlock against `migration.lock`
resolved by declaring IPC-only commands exempt from the lock
acquire; strict-mode revert-write failure gets sentinel breadcrumb
+ `STRICT_MODE_REVERT_FAILED` exit 10; template-renderer forward
compat for unknown-default drift as warn+preserve; migration
journal retention 5 newest; `netstat-cache.json` refresh after every
kill attempt success or failure; `startWithJobFn` swappable-var seam;
`internal/migration/journal.go` journal driver location pinned;
POSIX `lookupProcessIdentity` explicitly out-of-scope for v0.5.0
(Linux beta starts fresh, no v0.4.x migration); rename-aside
`.old-{ts}` cleanup via glob + 7-day-mtime sweep on supervisor
start and upgrade; `quiesce-timers` drains on separate goroutine;
`winio.ListenPipe` call site pinned; `rollback-in-progress.json`
marker; forward-retry `restart_history` retained by default with
explicit `--reset-failure-windows` flag.

**Date:** 2026-05-16

**Goal:** Replace the N-scheduled-tasks-per-daemon architecture of
v0.4.x with one `mcphub supervise` long-lived parent process that
owns every MCP daemon as a child process under an OS-appropriate
lifecycle primitive.

**Motivation:**

- **Process tail compression** — one `mcphub.exe` plus N children
  instead of N scheduler-managed orphans on crash.
- **Atomic upgrade story** — old supervisor exits, new supervisor
  reconciles, ~10s blip via MCP client retry semantics.
- **Removes the v0.4.x corrupt-state self-quarantine machinery** —
  no 5-min watchdog poll; child-exit observation is immediate.
- **Cross-platform foundation** — by removing Windows-specific Task
  Scheduler dependency, mcphub becomes a CLI tool that runs from
  any shell. The supervisor binary IS the lifecycle primitive.

| Q8 | Autostart-at-logon | Three per-OS backends under `mcphub autostart {enable, disable, status}`. Strict-mode mutation has ONE canonical command: `mcphub strict-mode {enable, disable}`. Acquires `migration.lock` (refuse-if-held → `STRICT_MODE_BUSY` exit 9), then `--once.lock`. Write order: (1) supervisor-intent.json atomically; (2) shim args atomically. On step 2 failure: revert step 1. **On revert-write failure**: write breadcrumb `<state-dir>/strict-mode-mutation-incomplete.json` carrying `{intended, actual_intent_state, actual_shim_state, step1_error, step2_error, revert_error, ts}`; emit body to stderr at exit; exit `STRICT_MODE_REVERT_FAILED` (10). Subsequent strict-mode invocations refuse-if-held on the breadcrumb until `mcphub strict-mode --recover` runs or operator deletes manually. **`mcphub strict-mode --recover` behavior**: acquires `migration.lock` (refuse-if-held → `STRICT_MODE_BUSY` exit 9, same lock contract as `enable`/`disable`), reads the breadcrumb, prompts operator with two and only two branches: (A) drive both intent + shim to the original `intended` value, (B) drive both to `actual_intent_state` (what's on disk now). No third "manual override" branch — those two are exhaustive over reconciliation targets. Once both writes succeed under the held lock, breadcrumb is deleted. If either write fails during recovery, the breadcrumb is re-asserted with updated `step1_error` / `step2_error` / `revert_error` fields and exit `STRICT_MODE_REVERT_FAILED` (10) again. Refuse-if-held with explicit exit codes beats silent blocking. Revert-failure sentinel closes the worst-case gap where both writes plus revert fail. IPC-only exemption prevents rollback's `quiesce-timers` from self-deadlocking against an in-flight `mcphub restart --server X` transient. |

### managed-entries.json (existing — preserved)

`{"version": int, "entries": [{client, server, installed_at}]}` per `internal/api/managed_entries.go:21-29`. Read-only from supervisor.

### daemon-intent.json (existing — preserved exactly)

`{"tasks": map[string]DaemonIntent}` only per `daemon_intent.go:231-233`. `DisallowUnknownFields()` at line 577 rejects extras. Keys: canonical leading-backslash form per `canonicalIntentTaskKey` at `daemon_intent.go:275-283`. Per-entry: `{desired, reason, updated_at}`. v0.5.0 supervisor reads via existing `ReadDaemonIntent`. Byte-symmetric for rollback.

### supervisor-intent.json (NEW)

```json
{
  "version": 1,
  "updated_at": "RFC3339Nano",
  "daemons": [
    {
      "task_name": "\\mcp-local-hub-memory-default",
      "server": "memory",
      "daemon": "default",
      "command": "node",
      "args": ["./mcp-memory-server.js"],
      "env": { "MEMORY_PATH": "..." },
      "workspace": "C:\\Users\\...\\repo",
      "port": 9128,
      "manifest_hash": "sha256:..."
    }
  ],
  "maintenance_timers": [
    {
      "name": "\\mcp-local-hub-workspace-weekly-refresh",
      "kind": "workspace-weekly-refresh",
      "command": "mcphub.exe",
      "args": ["workspace-weekly-refresh"]
    }
  ],
  "strict_mode": false
}
```

- `task_name` storage shape: canonical leading-backslash. Reconcile-prune diff (Q12) strips the prefix at compare time.
- No `principal` or `settings.priority` fields. Non-current-user RunAs classified as Unsupported in migration; default priority inherits `NORMAL_PRIORITY_CLASS`.
- Fixed-cadence maintenance timers. Two `kind` values: `workspace-weekly-refresh`, `server-weekly-refresh`. Both fire Sunday 03:00 local with DST + sleep catch-up. Unknown `kind` logged `warn`, skipped, file NOT quarantined.
- `strict_mode`: canonical truth. Mutated only via `mcphub strict-mode {enable, disable}` (Q8).
- Atomic write via shared state-file helper.

### supervisor-state.json (NEW)

```json
{
  "version": 1,
  "daemons": {
    "\\mcp-local-hub-memory-default": {
      "state": "running",
      "current_pid": 12345,
      "pid_generation": 7,
      "started_at": "RFC3339Nano",
      "restart_history": [
        {"at": "RFC3339Nano", "exit_code": 1, "signal": null}
      ],
      "backoff_until": "RFC3339Nano",
      "quarantine_since": "RFC3339Nano",
      "queued_action": null
    }
  },
  "transient_pids": [
    {"pid": 23456, "kind": "workspace-weekly-refresh", "started_at": "RFC3339Nano"}
  ],
  "maintenance_fired_at": {
    "workspace-weekly-refresh": "RFC3339Nano"
  }
}
```

- `daemons[*].queued_action`: `{kind: "respawn"|"none", reason}` recording pending action while in `exiting` state.
- `transient_pids[*]`: maintenance-timer fire-and-forget children outside Job Object.
- `maintenance_fired_at[kind]`: last successful fire timestamp for DST/sleep catch-up. **Serialized as RFC3339Nano UTC** (`Z`-suffix) — matches every other timestamp in the state file. Comparison logic uses `time.Time` arithmetic exclusively (no manual hour math).
- **`restart_history` pruning + retention**: on every state persist, supervisor prunes entries whose `at < now - 30m` (entries outside the 30-min failure-count window are policy-irrelevant for state-machine decisions; audit history belongs in `supervisor-events.log`, which has 10MB rotation). Within the 30-min window, entries are retained. Across `mcphub install --upgrade` and forward-retry, the pruned `restart_history` is retained by default (operators don't expect upgrade to forgive bad daemons).
- **`--reset-failure-windows` flag** clears, per daemon: `restart_history`, `backoff_until`, `quarantine_since`, AND resets `state` to `idle`. Reconcile then re-evaluates: `idle` + `intent.desired=running` + NOT `IsActiveStop(now)` → `spawning`. The v7 wording "clears restart_history per daemon" was insufficient because quarantined daemons would stay quarantined after the supposed clean-slate reset (per `supervisor_restart | persisted state=quarantined → quarantined` transition row).

## Migration journal (detail)

### Journal layout

```text
<state-dir>/migration-journal-<UTC-timestamp>/
  prepared
  pre-os-mutating                    # AFTER first successful kill
  os-mutating-complete
  committed
  rollback-in-progress               # ONLY present during rollback execution
  legacy-tasks/<task>.xml ...
  legacy-tasks-classification.json
  canonical-template-snapshot.xml    # rendered by v0.4.x-pinned renderer
  pre-migration-strict-mode
  derived-supervisor-intent.json
  killed-daemons.json
  netstat-cache.json
```

### Journal retention

After `committed` is reached AND step 14 supervisor reconcile-ready was confirmed, the migration driver under the held `migration.lock` deletes all but the 5 newest `migration-journal-*/` directories. **Two-phase crash-atomic pruning**: (1) for each victim, rename to `.pruning-<original-basename>/` (atomic on local FS even on Windows because rename is a single MFT entry update); (2) `os.RemoveAll` each renamed victim. On crash mid-prune, any `.pruning-*` prefix is unambiguously failed-prune debris and is finished by the next migration driver invocation BEFORE resume classification scans for journals. The single-phase recursive delete in v7 had a window where a half-deleted 6th-newest journal could be misclassified by resume as `os-mutating-complete no committed` — pinning the prefix sidesteps this. Per-dir delete failures are non-fatal (logged warn). Operator visibility: `mcphub install status` lists retained-journal count + oldest-retained timestamp.

### Lock ordering

1. `migration.lock` (flock, exclusive).
2. `--once.lock` (flock, exclusive).

Universal contract: every v0.5.0 lock acquirer takes `migration.lock` BEFORE `--once.lock`. LIFO release on all paths. Refuse-if-held: `mcphub install` exits `INSTALL_BUSY` (8); `mcphub strict-mode` exits `STRICT_MODE_BUSY` (9). **IPC-only commands** (`mcphub restart`, `mcphub status`) do NOT acquire `migration.lock` — they mutate supervisor in-memory + IPC state only.

### XML deviation-only classification

Canonical-template-snapshot rendered by **v0.4.x-pinned renderer** at `internal/migration/v04x_template_defaults.go` (NOT v0.5.0 install code). Pinned renderer covers known default values across the full v0.3.x..v0.4.x lineage. Concrete examples verified against `internal/scheduler/scheduler_windows.go:131-143` history: `MultipleInstancesPolicy=StopExisting` since v0.3.0 (per the v0.3.0-blockers bug #2 fix dated 2026-05-07); `AllowHardTerminate=true`, `Enabled=true`, `Priority=7` all unchanged since v0.3.0. The pinned-renderer table is canonical for any v0.3.x..v0.4.x XML the migration encounters; field values not in the table fall into the unknown-default-drift bucket (warn+preserve, or abort under `--migration-strict-template`).

For each `mcp-local-hub-*` task enumerated via `scheduler.EnumerateAllMcphubTasks()` (package-level function, NOT a `Scheduler` interface method), classify each XML field against pinned defaults:

- **Default match → silently preserved.**
- **Known deviation preserved through supervisor-intent + autostart shim**: `Settings.RunOnlyIfNetworkAvailable=true` → supervisor delays spawn until network probe passes.
- **Known deviation preserved through autostart shim only**: non-LogonTrigger triggers on the supervisor's own shim.
- **Known deviation that aborts (unless `--discard-scheduler-customizations`)**: `Principal.UserId` not current user; `Principal.LogonType` other than `InteractiveToken`; custom `<Actions>`; `IdleSettings.StopOnIdleEnd=true`, `WakeToRun=true`, `RunOnlyIfIdle=true`.
- **Known deviation silently dropped with warning line**: `<Priority>` ≠ 7 (no `SetPriorityClass` infra; default `NORMAL_PRIORITY_CLASS` covers `7` anyway).
- **Unknown XML element → warn + preserve through autostart shim XML.** Forward-compat for v0.4.x updates that ship new schema fields not anticipated by the pinned renderer.
- **Unknown default-value drift** (field present in both, value the pinned renderer doesn't claim as a known historical default): **warn + preserve** as deviation through autostart shim. `--migration-strict-template` CLI flag enables abort-on-unknown-drift posture for operators who explicitly want it.

### Pre-unregister daemon stop (Windows-only)

POSIX has no v0.4.x to migrate from (Q9); the pre-unregister daemon stop is Windows-only.

For each legacy `mcp-local-hub-*` daemon task:

1. Parse `<Exec>` argv to get `--server` + `--daemon`.
2. Resolve expected port via `portForTask(normalized, manifestPortMap(""), workspaceTasksByName())`.
3. Resolve PID + basename + CommandLine + createdUnix via NEW `lookupProcessIdentity(port)`. Implementation: `netstat -ano` snapshot from `netstat-cache.json` (refreshed once per kill-loop iteration AND after every kill attempt success or failure to bound staleness to one iteration or 1 second, whichever is shorter), then **PowerShell** as the primary identity resolver, invoked as `powershell.exe -NoProfile -NonInteractive -Command "Get-CimInstance -ClassName Win32_Process -Filter 'ProcessId=<pid>' | Select-Object Name, CommandLine, @{Name='CreationDateUnix';Expression={[int64](Get-Date $_.CreationDate -UFormat %s)}} | ConvertTo-Json -Compress"` with `exec.Cmd.SysProcAttr.HideWindow = true`. JSON output sidesteps locale-formatted date string parsing; `CreationDateUnix` projection eliminates locale-formatted dates; `encoding/json` parses natively. `wmic` is deprecated in Win11 24H2+ per Microsoft docs ("In the next release of Windows, the WMIC FoD will be disabled by default"); CIM/WMI itself remains supported. The implementation **detects `wmic` availability at first invocation** (`exec.LookPath("wmic.exe")`) and falls back to PowerShell `Get-CimInstance` if unavailable; on Win11 24H2+ hosts where `wmic.exe` is absent, PowerShell is the only path. The existing `internal/api/processes.go:283-309` `lookupProcess` callers (status_enrich, install) are migrated to the same PowerShell path as a sibling refactor noted in the implementation plan. 3 retries spaced 1s apart on transient `ok=false` (covers AV-scanner stalls); if still `ok=false` AND no matching `mcphub.exe daemon --server X --daemon Y` is in the system-wide process list, treat as unbound. Otherwise abort with `MIGRATION_PORT_LOOKUP_INCONSISTENT`.
4. 3-gate ownership check using basename + CommandLine + createdUnix:
   - Image basename = `mcphub.exe`.
   - CommandLine contains `daemon --server <server> --daemon <daemon>`.
   - createdUnix precedes `migration.lock` acquisition.
5. If gate passes, append to `killed-daemons.json`.
6. `touch pre-os-mutating` on the FIRST successful pass through this step.
7. `taskkill /PID <pid> /F /T` (Windows — `/T` critical per `install.go:2163-2174`).
8. Wait up to 10s for port release via repeated `lookupProcessIdentity(port)` polling.
9. If port still bound, abort with the exact port + PID + retry guidance.

### Forward migration steps

1. Acquire `migration.lock` (refuse-if-held → `INSTALL_BUSY`).
2. Acquire `--once.lock`.
3. Enumerate via `scheduler.EnumerateAllMcphubTasks()`.
4. Render canonical-template-snapshot via v0.4.x-pinned renderer.
5. Export each task's raw XML.
6. Classify deviations. Abort on hard deviation unless `--discard-scheduler-customizations`.
7. Derive `supervisor-intent.json`. **If `derived-supervisor-intent.json` already exists in the journal (resume case), re-use it.**
8. `touch prepared`.
9. Pre-unregister daemon stop (kills + retries + cache refresh + `pre-os-mutating`-on-first-kill).
10. Stop and unregister each legacy task via `schtasks /Delete`.
11. `touch os-mutating-complete`.
12. Install supervisor autostart shim with `--strict-mode` CLI arg if pre-migration strict-mode was 1.
13. Explicitly start supervisor per cold-restart upgrade flow.
14. Wait reconcile-ready via IPC `status` within 30s (reconcile-ready = IPC listener accepting + intent files read + first reconcile pass scheduled; NOT all-daemons-healthy). On timeout: auto-rollback.
15. `touch committed`.
16. Prune `migration-journal-*/` directories older than the 5 newest under the held `migration.lock`.
17. Release `--once.lock` (LIFO).
18. Release `migration.lock` (LIFO).

### Rollback steps (`mcphub install --rollback-to-legacy`)

1. Acquire `migration.lock`. **`touch rollback-in-progress`** under the lock (used by supervisor cold-start to refuse-to-reconcile during a mid-rollback OS reboot). **Atomicity**: if the marker `touch` fails (disk full, AV scanner I/O block, parent-dir DACL flip), release `migration.lock` immediately and exit non-zero — rollback has performed no observable mutation. Mirrors the forward path's `prepared`-marker-before-mutation ordering.
2. Issue IPC `quiesce-timers{timeout_ms: 30000}` to supervisor — drains in-flight transient PIDs on a separate goroutine; returns `{accepted: true}` immediately, then final `{drained, still_running}` frame.
3. Issue IPC `exit{graceful: true, timeout_ms: 5000}`. On timeout: force-kill via **`taskkill /F /T /PID <supervisor>`** (the `/T` ensures any non-Job-Object transients in `transient_pids` die alongside the supervisor); POSIX `kill -KILL -<pgid>` (process-group kill, not single-PID). After force-kill, verify each expected daemon port is unbound via `lookupProcessIdentity`; if any port is still bound after a bounded retry (10s), abort with `ROLLBACK_ORPHAN_DAEMONS_REMAIN` plus manual cleanup guidance.
4. Acquire `--once.lock`.
5. Find latest journal with `committed` marker (or `pre-os-mutating` for partial rollback).
6. Translate `supervisor-state` quarantined entries → `daemon-intent.json` `chronic-failure` via existing `WriteDaemonIntent`.
7. Uninstall supervisor autostart shim unconditionally (idempotent — missing shim is silent success).
8. For each `legacy-tasks/<task>.xml`: re-register via `schtasks /Create /XML /F`. **Settle 2-3 seconds** between step 3 (port-unbound confirmed via `lookupProcessIdentity`) and step 9 (task run) to let any TCP TIME_WAIT entries from step 3's force-kill drain — `lookupProcessIdentity` reports a port as "unbound" the moment the listening PID disappears, but the kernel may still hold the 4-tuple in TIME_WAIT briefly, causing `bind()` failures in legacy daemons that don't set `SO_REUSEADDR`. Mirrors the Linux/macOS cold-start reaper's 2-3s settling.
9. Run each restored daemon task via `schtasks /Run /TN <task>`.
10. Wait up to 60s per task for the expected port to bind. Append unbound tasks to `rollback-warnings.json` (schema below).
11. Delete `supervisor-intent.json` + `supervisor-state.json` + `supervisor-events.log`.
12. Delete `rollback-in-progress` marker.
13. Release `--once.lock` (LIFO).
14. Release `migration.lock` (LIFO).

**`rollback-warnings.json` schema (version 1):**

```json
{
  "version": 1,
  "warnings": [
    {
      "task": "\\mcp-local-hub-memory-default",
      "port": 9128,
      "reason": "port-not-bound-after-60s",
      "observed_at": "RFC3339Nano"
    }
  ]
}
```

**Exit semantic**: Rollback exits **0** (success-with-warnings) even when warnings present. Non-zero exit reserved for "rollback itself failed".

### Resume / partial-state recovery

Markers: `prepared` → `pre-os-mutating` → `os-mutating-complete` → `committed`. Rollback has its own marker: `rollback-in-progress`.

- **`prepared` only**: safe to abort; delete journal.
- **`pre-os-mutating` no `os-mutating-complete`**: forward-resume re-uses existing `derived-supervisor-intent.json` (preserves operator edits); enumerates ALL `mcp-local-hub-*` via `EnumerateAllMcphubTasks` + probes ports via `lookupProcessIdentity`. Logs `event: migration-resume-rederiving-intent` only on re-derive. **Cross-version resume**: a resume always uses `canonical-template-snapshot.xml` from the journal verbatim, NEVER re-renders from the currently-installed `v04x_template_defaults.go`. Prevents drift between an initial migration's snapshot and a resume's re-classification when v0.5.1+ ships an updated pinned-renderer table.
- **`os-mutating-complete` no `committed`**: operator picks forward retry or rollback.
- **`rollback-in-progress` marker present at supervisor cold start**: supervisor refuses to reconcile and exits with `SUPERVISOR_REFUSING_ROLLBACK_IN_PROGRESS` plus operator guidance ("complete `mcphub install --rollback-to-legacy` or `mcphub install --upgrade` first"). Prevents the cold-restart supervisor + stuck-rollback legacy XML race after an OS reboot mid-rollback.

### When this applies

- No `<state-dir>` exists, OR
- `<state-dir>` exists but contains no `mcp-local-hub-*` tasks, no `supervisor-intent.json`, no migration journals.

### Sequence

2. Acquire `--once.lock` only if a v0.4.x watchdog task exists on disk.

## Cold-restart upgrade flow (detail)

### Windows binary replacement (rename-aside)

1. Write new binary to `<install-dir>/mcphub.exe.new`.
2. `MoveFileExW(target, target + ".old-<ts>", REPLACE_EXISTING)`.
3. `MoveFileExW(target + ".new", target, 0)`.
4. **`.old-<ts>` cleanup**: on every `mcphub install --upgrade` AND every `mcphub supervise` startup, glob `<install-dir>/mcphub.exe.old-*` and `os.Remove` each whose name parses as `.old-<RFC3339>` form AND whose mtime is older than 7 days. `os.Remove` failures (file still mapped, AV scan, ACL flip) logged warn + retried on next pass. Bounded accumulation; no admin rights required because supervisor runs as same user that wrote the file.

POSIX: atomic `rename(2)`.

### Upgrade sequence

1. Replace binary atomically.
2. Connect to supervisor IPC; client reads `supervisor.lock` for expected `{pid, start_time}` FIRST.
3. Issue IPC `quiesce-timers` (drains transients on separate goroutine, up to 30s).
4. Issue IPC `exit{graceful: true, timeout_ms: 5000}`.
5. Supervisor terminates remaining transients (5s grace then `taskkill /F /T /PID` per transient) plus daemon children, then exits 0.
6. `mcphub install` explicitly starts new supervisor:
   - Windows: `schtasks /Run /TN \mcp-local-hub-supervisor` if shim installed; else `mcphub.exe supervise [--strict-mode]` as detached child via `windows.CreateProcess` with `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`. Note: this flag combination makes the new supervisor unable to receive `CTRL_C_EVENT` from any other process per Microsoft docs; graceful shutdown is **exclusively via IPC `exit`**. Task Manager End Task → un-graceful Job Object close; `KILL_ON_JOB_CLOSE` reaps children.
   - Linux managed: `systemctl --user restart mcphub-supervisor.service`.
   - Linux unmanaged: `mcphub supervise [--strict-mode] &`.
   - macOS managed: `launchctl kickstart -k gui/<uid>/com.applicate2628.mcphub-supervisor`.
   - macOS unmanaged: `mcphub supervise [--strict-mode] &`.
7. New supervisor → reads intent + daemon-intent → reconcile → respawns daemons.

### Fallback if step 4 IPC fails

Force-kill prior supervisor PID via `taskkill /F /T /PID` (Windows; `/T` ensures transients die alongside supervisor; verify ports unbound post-kill). POSIX: `kill -KILL -<pgid>`. Run cold-start stale-child reaper on Linux/macOS default modes; reaper waits 2-3 seconds between kills for TCP TIME_WAIT.

## Restart policy state machine (detail)

Supervisor runs a single-threaded FIFO event loop. No concurrent-event tie-breakers. **FIFO channel is buffered with capacity ≥ 16** so the separate-goroutine `quiesce-timers` handler can post `quiesce-complete` back into the FIFO without blocking on an unbuffered-channel rendezvous — prevents deadlock where the in-flight `exit{graceful}` handler waits for `quiesce-complete` while the post is waiting for the loop to dequeue.

States: `idle`, `spawning`, `running`, `exiting`, `backoff-waiting`, `quarantined`.

Events: `child_exit`, `timer_due`, `intent_update`, `manual_restart`, `supervisor_restart`, `quiesce-complete` (NEW — posted by the separate-goroutine quiesce-timers handler when drain finishes).

`failures` = `child_exit` count in trailing 30-min sliding window. `gen_match` = PID matches current generation.

| From | Event | Guard | To | Side effect | Persist when |
| --- | --- | --- | --- | --- | --- |
| idle | (start) | intent.desired=running AND NOT IsActiveStop(now) | spawning | bump pid_generation, create-process | BEFORE |
| idle | intent_update | new.desired=stopped | idle | none | n/a |
| idle | intent_update | new.desired=running (TTL refreshed) | spawning | bump pid_generation, create-process | BEFORE |
| idle | manual_restart | intent.desired=running AND NOT IsActiveStop(now) | spawning | bump pid_generation, create-process | BEFORE |
| idle | manual_restart | intent.desired=stopped OR IsActiveStop(now) | idle | reject IPC `RESTART_REFUSED_INTENT_STOPPED` | n/a |
| spawning | (health check OK) | first probe success | running | none | AFTER |
| spawning | child_exit | gen_match | backoff-waiting | arm timer at backoff(failures) | BEFORE |
| spawning | child_exit | NOT gen_match | spawning | drop event | n/a |
| running | child_exit | gen_match | backoff-waiting | arm timer | BEFORE |
| running | child_exit | NOT gen_match | running | drop event | n/a |
| running | intent_update | new.desired=stopped | exiting | issue terminate, set queued_action=none | BEFORE |
| running | manual_restart | always | exiting | issue terminate, set queued_action=respawn | BEFORE |
| exiting | child_exit | queued_action=respawn | spawning | bump pid_generation, create-process | BEFORE |
| exiting | child_exit | queued_action=none | idle | none | AFTER |
| exiting | manual_restart | always | exiting | coalesce — set queued_action=respawn | BEFORE |
| exiting | intent_update | new.desired=stopped | exiting | clear queued_action | BEFORE |
| exiting | intent_update | new.desired=running | exiting | set queued_action=respawn | BEFORE |
| exiting | timer_due | always | exiting | log + ignore | n/a |
| backoff-waiting | timer_due | failures < 10 | spawning | bump pid_generation, create-process | BEFORE |
| backoff-waiting | timer_due | failures >= 10 | quarantined | clear timer | BEFORE |
| backoff-waiting | intent_update | new.desired=stopped | idle | cancel timer | BEFORE |
| backoff-waiting | intent_update | new.desired=running (TTL refreshed) | spawning | cancel timer, bump pid_generation, create-process | BEFORE |
| backoff-waiting | manual_restart | always | spawning | cancel timer, bump pid_generation, create-process | BEFORE |
| quarantined | intent_update | new.desired=stopped | idle | none | n/a |
| quarantined | intent_update | new.desired=running (TTL refreshed) | spawning | reset failures, bump pid_generation, create-process | BEFORE |
| quarantined | manual_restart | always | spawning | reset failures, bump pid_generation, create-process | BEFORE |
| (any) | supervisor_restart | persisted state=quarantined | quarantined | none | done via load |
| (any) | supervisor_restart | persisted backoff_until > now AND failures < 10 | backoff-waiting | re-arm at absolute backoff_until | done via load |
| (any) | supervisor_restart | persisted backoff_until <= now AND intent.desired=running AND NOT IsActiveStop(now) | spawning | bump pid_generation, create-process | BEFORE |
| (any) | supervisor_restart | persisted intent.desired=stopped | idle | none | done via load |
| (any) | quiesce-complete | always | (state unchanged per daemon) | clear `quiesce_in_progress` flag; signal exit-handler completion via `quiesceCompleteCh` channel | n/a (transient supervisor-wide flag, not per-daemon state) |

Backoff: 0s, 0s, 0s, 5s, 15s, 60s, 5min, 30min capped.

**Handler residence**: `exit{graceful}` IPC handler is a SIDE-GOROUTINE (not FIFO-resident) — it accepts the IPC call, posts a `request-graceful-exit` event into FIFO so each running daemon transitions through `running → exiting → idle` via existing rows, then waits on `quiesceCompleteCh` for the separate-goroutine `quiesce-timers` drain to signal completion. When all daemons have reached `idle` AND `quiesceCompleteCh` has fired, supervisor terminates remaining transient PIDs (5s grace + `taskkill /F /T`) and exits with code 0. This side-goroutine residence prevents the in-loop-deadlock pathology where `exit{graceful}` waits for `quiesce-complete` while the FIFO dequeue waits for the handler to return. The capacity-≥-16 FIFO buffer is for `quiesce-complete` posting (the post is non-blocking); the side-goroutine pattern is the load-bearing fix.

## Maintenance timer scheduler (detail)

Fixed-cadence in-process evaluator. Two kinds: `workspace-weekly-refresh` and `server-weekly-refresh`, both fire Sunday 03:00 local.

### DST + sleep catch-up

Persist `last_fired_at[kind]` in `supervisor-state.maintenance_fired_at`. Every 60s reconcile tick, for each timer:

- Compute `next_due` = next Sun 03:00 local on or after `last_fired_at[kind]`.
- If `now >= next_due` AND `(now - next_due) <= 6 hours`, fire and update `last_fired_at[kind] = now`.
- If `now >= next_due` AND `now > next_due + 6 hours`, fire ONCE for the missed window (catches laptop sleep across the weekend).

Implementation estimate ~60-80 LoC.

### Single-run guard + transient tracking

Per-timer in-process mutex prevents overlap. Transient child PID + kind + started_at recorded in `supervisor-state.transient_pids` BEFORE the syscall.

### Graceful exit + quiesce drain

`quiesce-timers` IPC handler runs on a SEPARATE goroutine (does not block FIFO):

1. Sets `quiesce_in_progress = true` (atomic flag the FIFO event loop checks before firing new timer fires).
2. Polls `transient_pids` until empty or `timeout_ms` expires.
3. Posts `quiesce-complete{drained, still_running}` event into FIFO.
4. IPC writes final response frame `{drained, still_running}`.

`exit{graceful}` after `quiesce-complete` force-terminates any remaining transients with `taskkill /F /T /PID` (5s grace per transient) before terminating daemon children.

### Unknown kind forward-compat

Reading `supervisor-intent.maintenance_timers` with unknown `kind`: log `severity: warn, event: unknown-maintenance-kind`, skip entry, do NOT quarantine file.

## Control IPC trust boundary (detail)

### Transport

- Windows: `winio.ListenPipe(pipePath, &winio.PipeConfig{SecurityDescriptor: <SDDL string from dacl_shared_windows.go>, MessageMode: false, InputBufferSize: 4096, OutputBufferSize: 4096})` returns `net.Listener`. `PipeConfig.SecurityDescriptor` is an SDDL text string per Q11 (NOT raw self-relative SD bytes — verified at `github.com/microsoft/go-winio/blob/main/pipe.go` where the field type is `string` and `winio.ListenPipe` calls `winio.SddlToSecurityDescriptor` on it). Per-connection goroutine model integrates with stdlib `net`.
- POSIX: unix socket at mode 0600.

### Wire format

Newline-delimited JSON.

```json
{"id": 42, "cmd": "status"}
{"id": 43, "cmd": "exit", "args": {"graceful": true, "timeout_ms": 5000}}
{"id": 44, "cmd": "restart", "args": {"server": "memory", "daemon": "default"}}
{"id": 45, "cmd": "reload"}
{"id": 46, "cmd": "quiesce-timers", "args": {"timeout_ms": 30000}}
```

```json
{"id": 42, "ok": true, "result": { "daemons": [] }}
{"id": 46, "ok": true, "result": {"accepted": true}}
{"id": 46, "ok": true, "result": {"drained": 1, "still_running": []}, "final": true}
```

`quiesce-timers` produces TWO response frames: immediate `{accepted: true}`, then later `{drained, still_running, "final": true}` after drain finishes on the separate goroutine.

### Handshake

Client reads `supervisor.lock` for expected `{pid, start_time}` FIRST. Supervisor sends `hello` frame on connect. Client validates; mismatch closes connection.

### Audit

```json
{"schema_version":"1","ts":"...","severity":"info","source":"ipc",
 "event":"ipc-command","body":{"cmd":"exit","args":{},"caller":{"pid":99},"result":"ok"}}
```

## Terms and Abbreviations

- `canonical task name`: leading-backslash form (`\mcp-local-hub-...`) per `daemon_intent.go:275-283`. Storage shape for `daemon-intent.json` keys and `supervisor-intent.json` `task_name`.
- `canonical-template-snapshot`: per-migration artifact rendered by **v0.4.x-pinned** template renderer at `internal/migration/v04x_template_defaults.go`. Used by deviation-only classification.
- `ChronicCycles`: `internal/api/watchdog_state.go:266`. Not seeded into v0.5.0 supervisor-state — `mcphub watchdog enable` after migration resets the failure window (intentional clean slate).
- `cold-start reaper`: supervisor's Linux/macOS default-mode startup procedure.
- `daemon-intent.json`: v0.4.x state file `{tasks: ...}` only. Preserved verbatim.
- `deviation-only classification`: migration classifier; default match silently preserved; unknown-default-drift warn+preserve; hard customization deviations abort unless `--discard-scheduler-customizations`.
- `EnumerateAllMcphubTasks`: new package-level function (NOT a `Scheduler` interface method) in `internal/scheduler`. Lists every `mcp-local-hub-*` task regardless of Run As.
- `FIFO event loop`: supervisor's single-threaded event channel.
- `go-winio`: `github.com/Microsoft/go-winio` direct dep. `winio.ListenPipe` returns `net.Listener` integrating with stdlib `net`.
- `Get-CimInstance Win32_Process`: PowerShell cmdlet — Win11 24H2+ replacement for deprecated `wmic process` invocations. Used by `lookupProcessIdentity` with `wmic` fallback detection via `exec.LookPath("wmic.exe")`.
- `INSTALL_BUSY`: exit code 8 emitted by `mcphub install` when `migration.lock` is held.
- `IntentReason TTL`: per `IsActiveStop(now)`.
- `IPC`: Windows named pipe / POSIX unix socket.
- `IPC-only commands`: `mcphub restart`, `mcphub status` — DO NOT acquire `migration.lock`; only mutate supervisor IPC + in-memory state.
- `Job Object`: Windows kernel primitive.
- `JSON line protocol`: newline-delimited JSON.
- `KILL_ON_JOB_CLOSE`: Job Object flag.
- `killed-daemons.json`: migration journal artifact.
- `kqueue`: BSD/macOS observation only.
- `LaunchAgent`: macOS plist-defined job. Restart-after-exit, NOT containment.
- `lookupProcess(port)`: existing v0.4.x PID resolver at `processes.go:283-309`.
- `lookupProcessIdentity(port)`: NEW v0.5.0 Windows-only helper extending `lookupProcess` with basename + CommandLine + createdUnix via PowerShell `Get-CimInstance Win32_Process` (with `wmic` LookPath fallback for pre-24H2 hosts). Reads `netstat-cache.json` snapshot. 3 retries 1s apart on transient `ok=false`. POSIX out-of-scope for v0.5.0 per Q9.
- `maintenance_timers`: supervisor-intent.json section. Two fixed cadences (workspace + per-server). DST + sleep catch-up via `last_fired_at` + 6h window. Unknown `kind` warn+skip (not quarantine).
- `managed-entries.json`: v0.4.x state file.
- `managed mode` (Linux/macOS optional): init-system-owned.
- `MCP`: Model Context Protocol.
- `mcphub.exe supervise`: NEW v0.5.0 subcommand. Lives in `internal/cli/supervise.go`.
- `mcphub strict-mode {enable, disable}`: NEW canonical mutation. Universal lock order. Two-resource atomic write. On revert-write failure: `<state-dir>/strict-mode-mutation-incomplete.json` breadcrumb + `STRICT_MODE_REVERT_FAILED` (exit 10) + stderr body.
- `mcphub strict-mode --recover`: NEW recovery command for `STRICT_MODE_REVERT_FAILED` state. Reads breadcrumb, prompts operator, reconciles intent + shim manually.
- `migration.lock`: NEW exclusive flock at `<state-dir>/migration.lock`.
- `migration journal`: per-install directory. Retention: 5 newest after `committed`.
- `MIGRATION_PORT_LOOKUP_INCONSISTENT`: migration abort code when `lookupProcessIdentity` keeps returning `ok=false` but a matching `mcphub.exe daemon` is in the process list.
- `netstat-cache.json`: migration journal artifact. Refreshed after EVERY kill attempt (success or failure); TTL one iteration or 1s, whichever shorter.
- `--once.lock`: existing v0.4.x watchdog flock per `internal/cli/watchdog.go:498-529`.
- `PID generation`: monotonic counter.
- `Plan.SupervisorIntent`: v0.5.0 install plan field. Reconcile-prune diff strips canonical prefix.
- `pre-os-mutating`: migration journal marker AFTER first successful kill.
- `procThreadAttributeJobList`: `uintptr = 0x0002000D`. Locally defined in `internal/process/start_with_job_windows.go` because NOT exported by `golang.org/x/sys/windows`.
- `process.StartWithJob`: NEW. Wraps `windows.CreateProcess` with `windows.StartupInfoEx` + `windows.NewProcThreadAttributeList` for `PROC_THREAD_ATTRIBUTE_JOB_LIST` at create-time. Test seam `var startWithJobFn = process.StartWithJob` lives in `internal/cli/supervise.go`.
- `quiesce-complete`: NEW FIFO event posted by separate-goroutine `quiesce-timers` handler after drain finishes.
- `quiesce-timers`: NEW IPC command. Drains transients on a SEPARATE goroutine (does not block FIFO). Two-frame response: `{accepted: true}` immediate, `{drained, still_running, final: true}` after drain.
- `quarantine`: terminal state. On rollback, translated to `chronic-failure`.
- `reconcile loop`: supervisor's core algorithm.
- `reconcile-prune identity`: BARE task name (no leading backslash) per `install.go:1092` + `:1639-1642` + `:1773`.
- `rename-aside`: Windows binary replacement pattern. `.old-<ts>` cleanup on supervisor startup + every upgrade via glob + mtime > 7 days + `os.Remove` (failures logged warn).
- `--reset-failure-windows`: NEW `mcphub install --upgrade` flag clearing `restart_history` per daemon. Default is retain.
- `rollback-in-progress`: NEW journal marker written under `migration.lock` at rollback step 1, deleted at step 12. Supervisor cold start with this marker present refuses to reconcile, exits `SUPERVISOR_REFUSING_ROLLBACK_IN_PROGRESS`.
- `ROLLBACK_ORPHAN_DAEMONS_REMAIN`: rollback abort code when post-force-kill port verification fails.
- `rollback-warnings.json`: rollback journal artifact. Schema v1: `{"version":1,"warnings":[{task, port, reason, observed_at}]}`. Rollback exits 0 with warnings.
- `state-file helper`: shared utility under `internal/api`.
- `STRICT_MODE_BUSY`: exit 9 emitted by `mcphub strict-mode` when `migration.lock` held.
- `STRICT_MODE_REVERT_FAILED`: exit 10 emitted when strict-mode mutation step 1 succeeded, step 2 failed, AND the revert write also failed. Breadcrumb at `<state-dir>/strict-mode-mutation-incomplete.json`. Recovery: `mcphub strict-mode --recover`.
- `strict mode`: operator opt-in. `supervisor-intent.strict_mode` canonical. `--strict-mode` CLI is a SEED applied only when intent.updated_at predates supervisor mtime.
- `supervisor-events.log`: JSONL audit. Envelope byte-symmetric with `gui_event_log.go:19-25`.
- `supervisor-intent.json`: NEW state file.
- `supervisor.lock`: NEW singleton at `<state-dir>/supervisor.lock` via `internal/api/supervisor_lock.go`. `{pid, start_time}`. IPC clients pre-read.
- `supervisor-state.json`: NEW. Hybrid C state + transient_pids + maintenance_fired_at. `restart_history` retained by default across forward upgrades; `--reset-failure-windows` flag to clear.
- `SUPERVISOR_REFUSING_ROLLBACK_IN_PROGRESS`: supervisor exit code when `rollback-in-progress` marker is present at cold start.
- `systemd-user`: per-user systemd instance.
- `Task Scheduler`: Windows service. v0.5.0 uses one entry (autostart shim).
- `transient_pids`: array tracking maintenance-timer fire-and-forget children.
- `tree-kill`: `taskkill /F /T /PID <pid>` — `/T` critical because hub.exe spawns npx/uvx grandchildren. **Also used by rollback's IPC-timeout supervisor force-kill** to ensure transient PIDs die alongside the supervisor.
- `watchdog-state.json`: existing v0.4.x state file. Preserved unchanged.
- `winio.ListenPipe`: `github.com/Microsoft/go-winio` named-pipe server constructor. Returns `net.Listener`.
