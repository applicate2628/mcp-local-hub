## Basic performance acceptance

The coordinator uses injected bounded contexts for confirmation, quiesce, recovery bind, cleanup, grace, and hub shutdown; the hub owner force-closes on its five-second cap. Target-port progress emission uses the existing non-blocking broadcaster (`internal/gui/events.go:350-397`). No throughput benchmark is required for this control-plane path. The confirmation finding is a correctness/reliability failure: returning too early is not acceptable latency behavior because it bypasses the intended readiness deadline.

## Residual risk

- No real GUI child process was spawned by QA, per the explicit constraint. Retained operating-system process-handle behavior is therefore source- and seam-verified, not end-to-end process-verified.
- Grace remains intentionally able to continue after release; only fixed-delay/ordinary cleanup is permitted there. The identified reservation validation must move before release without adding any new post-release gate.
- Same-port successful handoff shares the single-shot confirmation race even though the pre-release rollback restoration criterion itself passes.
