## OPEN — DEFERRED with a recorded decision
- **2026-06-23-openpath-second-explorer-generator** (P3) — DECISION: **won't-fix
  (by design).** The tray/Settings/Logs "Open folder" affordances spawn one
  explorer.exe per DELIBERATE operator click. On a host with the Windows
  "Launch folder windows in a separate process" option, that window is
  un-reapable (architect verdict: a handed-off window is indistinguishable from
  the user's own) — but ONE window per intentional click is the CORRECT behaviour
  (the operator asked to open a folder). This differs from the FIXED
  explorer-folder-window-orphan-flood, which was `--force` AUTO-recovery that could
  fire repeatedly and flood. No code change.
- **2026-07-04-intent-collapse-cleared-stop-resurrection** (P3) — DEFER, linked to
  ROADMAP §B **E2** (delete daemon-intent.json). The `!hadPrior → merged[key]=di`
  re-add is reachable ONLY in the transient mixed old+new-binary window; the naive
  "drop don't re-add" fix breaks initial migration (needs a watermark/tombstone
  design). E2 DELETES daemon-intent.json entirely, removing this surface — do NOT
  design a tombstone for a slated-for-deletion surface. Resolves when E2 lands.
