# Backlog — daemon-port ephemeral-collision self-heal (D) follow-ups

Deferred from the D feature (`2026-07-13-daemon-port-ephemeral-self-heal`, shipped round-4b). All are hardening / robustness, NOT correctness blockers — the shipped feature closes every commission-found P1.

## 1. Monotonic intent revision/generation (commission's ideal ordering signal)
All three round-4 reviewers (fable + Sol + Terra) recommended a monotonic persisted revision on `SupervisorIntentFile` (bumped on every actual write under the flock) as the trap-free ordering signal for `reallocSnapshotOrder`, replacing the `UpdatedAt`-timestamp compare. The shipped round-4b fix (Stale/Equal → targeted `patchCachedReallocatedPort`) resolves the actual defect (port+argv always land on newPort) WITHOUT the revision, but the revision would let the common path take the intended WHOLE-apply (picking up other descriptor changes immediately instead of via the ≤60s watcher) and eliminate the equal-timestamp ambiguity class entirely. Integration care: must bump only on an ACTUAL content change (not defeat `MutateSupervisorIntentIfChanged`'s if-changed optimization), interact cleanly with intent-hash equality checks, and be backward-compatible (absent=0). A NEW field (separate from `UpdatedAt`) also side-steps the strict-mode-seed interaction that stamping `UpdatedAt` would trigger.

## 2. FIX-6 worker-lease / epoch (permanently-wedged worker)
The shipped FIX-6 (peek + record-cap-only-on-completed) stops a wedged worker from burning the cap toward a FALSE quarantine. But a PERMANENTLY-wedged reallocation worker (blocked forever on the registry/intent flock held by a wedged co-process) now yields an endless ~30s-cadence old-port backstop retry loop with NO escalation and (when the in-flight dedup absorbs the retry) NO event — a silent flap. The real cure is a worker lease/epoch with timeout replacement (spawn a fresh worker when the lease expires), which fable + Terra flagged across rounds. Bounded (a single daemon, recoverable by supervisor restart), so deferred.

## 3. Pre-existing load-induced test flake — TestVerifyProxyReady* / TestSupervise_IPC_QuiesceTimersTwoFrames
PROVEN pre-existing (disambiguation: `TestVerifyProxyReady*` failed under artificial load WITHOUT the D feature's tests present; the D feature is not on their code path). Not a D regression. Harden them for load (larger/adaptive timeouts, or `t.Parallel` isolation / a serial lane) so the tagged CI gate is deterministic under load. Independent of D.

## 4. Respawn-timer single-owner: move the epoch guard onto the loop (P3, fable-adjudicated)
Round-7's `respawnArmGen`/`respawnArmEpoch` single-timer-owner does the fire-time epoch guard on the TIMER goroutine, while the arm's `respawnArmEpoch.Add(1)` + `respawnArmGen.Store` are two non-atomic ops on the loop. Terra (round-7) flagged the Add→Store window race (a stale timer Loads the still-old epoch, passes the guard, posts a duplicate EvTimerDue). fable ARBITER-verdict: the race is REAL but a ~tens-of-ns sub-case of the wider (ms-scale, already-accepted) fire-before-arm boundary inherent to any fire-time-guard; impact is exactly ONE extra EvTimerDue → the P3 redundant-timer class already cleared in round-5, bounded by 4 dampers (no spawn outside StBackoffWaiting [tested], no wrong port [TaskName-only + F1 re-gate], no worker amplification [portGateInFlight/reallocInFlight dedup + reallocFailCount once-per-completed], no quarantine acceleration [counts real EvChildExit crashes]); never zero-fire (no lost daemon). Trigger ~1e-8/episode. NOT a merge blocker.
**Fix (when the file is next touched):** carry `armGen` in the EvTimerDue LoopEvent; the loop's EvTimerDue handler does the `respawnArmGen.Load`+compare (arm's Store and the check's Load both loop-serialized → race-free), keeping the timer-goroutine checks as best-effort early drops. This also closes the wider fire-before-arm boundary. **CAUTION (why this is a deliberate follow-up, not a rushed round-8):** `replayDeferredBackoffTimerIfPending` (supervisor_controller.go:1759-1780) re-posts a synthetic gen-less EvTimerDue for the anti-stranding reap-window replay — the loop-side guard MUST stamp it with the current gen (or exempt it), or the replay would be silently dropped and re-introduce the stranding the finding-E machinery prevents.
