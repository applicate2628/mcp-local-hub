## 1. Результат и контракт

В [NativeOwner](../../src/windows.rs) добавлен `process_view(&self) -> io::Result<ProcessView<'_>>`.
Он заимствует исходные process/Job и сохранённый при создании результат чтения времени рождения.
Наблюдение не расходует допуск, не возобновляет процесс, не публикует root exit и не закрывает ресурсы.
Результат каждого системного чтения остаётся отдельным наблюдением.

**Таблица 1. Допустимые состояния.**

| Состояние владельца | Новый view |
|---|---|
| Suspended до первого допуска | Разрешён, возможны повторные чтения |
| После успешного либо отклонённого допуска | Разрешён; расходованный допуск не восстанавливается |
| После root exit, пока исходные ресурсы удерживаются | Разрешён; конкретное чтение может вернуть ошибку Windows |
| После `finish(Pending)` без запроса остановки | Разрешён |
| После попытки `terminate`, включая сохранённую ошибку | Отказ до чтения |
| После терминального `finish`, включая ошибку закрытия | Отказ до чтения |
| Нет исходного process либо Job | Отказ; самостоятельное чтение допуск не расходует |

Прежний `admit_and_resume` использует тот же способ создания view **после** записи `admission_attempted = true`.
Таким образом, ошибка внутри настоящей попытки допуска сохраняет прежнюю одноразовую семантику.
Rust-заимствование исключает изменяющую операцию владельца, пока view ещё используется; raw handle наружу не выдаётся.

Новые проверки различают повторное чтение до запуска, чтение работающего процесса,

## 3. Ревью и принятые решения

Применены Ponytail Code Simplification, Architecture Review, API and Interface Design
и Incremental Implementation. Выбрано минимальное заимствование существующего view;
не добавлены новый владелец, реестр, зависимость или дополнительная closure-обёртка.

Ponytail изменил порядок ближайшей работы: самостоятельное чтение native/FFI сначала;
обобщение продуктового Go lifecycle/custody — вместе с настоящим принимающим адаптером.
Формальное выделение интерфейса сейчас не устраняет реальные зависимости от cmd, Job,
исходного wait и полномочий закрытия.

Автор проверил собственный diff; root независимо прочитал все четыре изменённых файла,
сверил порядок admission/state checks и лично повторил полный debug suite.
Подтверждённых незакрытых дефектов native diff не найдено.

<a id="evidence"></a>
## 4. Доказательства и ограничения

[logs.zip](logs.zip) содержит команды, журналы и JSON-квитанции;
[manifest.json](manifest.json) связывает исходные и подготовленные для публикации байты.
[SHA256SUMS](SHA256SUMS) проверяет файлы пакета. В оригиналах журналов ничего не менялось.
Публикационные копии нормализованы в UTF-8/LF; текстовые SID и имя пользовательского
профиля Windows скрыты. Private binary SID markers, исполняемые файлы и build caches
в архив не включены.

Для повторения использовать `native-runner.ps1` из архива с новым значением `-Name`;
существующая запись запуска не перезаписывается. Runner фиксирует фактические source hashes,
версии Rust/Cargo, команду и exit code; он использует уже имеющийся offline cache.

Этот результат не создаёт продуктовый CreatorIdentity, SID-formatting receipt,
контекстную отмену либо протокол retirement. Общие Go pre-push проверки и обязательная
приёмка PR остаются отдельными условиями; узкий native PASS их не заменяет.

**Термины:** Job — объект Windows, удерживающий группу процессов; SID — идентификатор
безопасности Windows; root exit — исход завершения исходного процесса;
custody — удержание ресурсов и полномочий их завершения; retirement — запрет новых
операций и завершение уже вошедших перед закрытием; compile-fail — проверка ожидаемого
отказа компилятора при нарушении контракта заимствования.
